# 自定义座位最佳实践

本文说明如何从零实现一个可联网的自定义座位。内容不依赖 Lua、C# 或特定脚本框架，文中的回调和 API 名称只用于说明职责，不要求原样照搬。

最终应能实现以下体验：

1. 玩家进入座位范围后看到“坐下”按钮，离开范围后按钮被正确清理。
2. 点击“坐下”后，平台确认座位状态，玩家贴合座位锚点并随座位或载具移动；其他客户端也能看到同一表现。
3. 坐下期间入口切换为“站起”，即使移动座位离开原 Trigger，玩家仍可站起。
4. 站起后恢复缩放、碰撞和安全位置；可按需要增加切换座位、飞行互斥和晚进房状态恢复。

## 座椅对象硬约束

- 一个座椅 NetworkObject 对应一个逻辑座位和一个 `CurrentPlayer`，同一时刻只能被一个 Actor 占用。
- 每个座椅配置一个 `SeatAnchor`；`ExitAnchor` 可选，用于定义离座位姿。
- 多个玩家同时乘坐同一载具时，必须创建多个独立的座椅 NetworkObject；每个对象都要有自己的座椅脚本、Trigger 和 `SitDown` 目标。占用判断由该座椅对象的 `CurrentPlayer` 负责，业务占用变量按需增加。
- `switchSeat=true` 只允许同一个 Actor 从座椅对象 A 切换到座椅对象 B，不允许第二个 Actor进入已占用的座椅对象。

> **前置阅读**：[基础交互](../../Manual/Ⅰ.%20核心系统%28Core%29/交互/基础交互.md)、[触发交互最佳实践](./触发交互-最佳实践.md)。
>

## 阅读路线

建议按以下顺序实现和验证，不要先实现自定义动画、载具输入或复杂 UI：

```text
对象、锚点和 Trigger 配置
  → 初始化并记录每个 Actor 的原始状态
  → 创建、点击和清理交互按钮
  → 发起 SitDown 请求 → OnSeatEntered 挂载并持续对齐
  → 发起 StandUp 请求 → OnSeatExited 停止对齐并恢复状态
  → 切换座位、飞行、占用同步和晚进房等扩展
```

自定义座位的能力与本文章节对应如下：

| 进入/离开范围、焦点生命周期与坐下/站起按钮 | [第二步：处理交互按钮](#第二步处理交互按钮) |

## 先理解座位流程

`SitDown(座位对象, 是否允许切换)` 和 `StandUp(座位对象)` 只负责由本地 Actor 发起座位请求。平台确认后，会在座位对象的脚本上触发 `OnSeatEntered(Actor)` 或 `OnSeatExited(Actor)`。挂载、位姿、缩放、碰撞、动画和 UI 状态都由座位脚本在确认回调中完成。

自定义座位分为三个部分：

| 部分 | 运行范围 | 职责 |
| --- | --- | --- |
| 交互按钮 | 本地客户端 | 玩家进入范围时创建坐下入口；坐下后提供站起入口；失焦、离开范围或对象禁用时清理按钮。 |
| 坐下表现 | 请求由本地 Actor 发起；确认回调在所有客户端执行 | 缓存原始状态，将 Actor 挂到 `SeatAnchor`，关闭碰撞并持续进行 Hips 对齐。 |
| 离座表现 | 请求由本地 Actor 发起；确认回调在所有客户端执行 | 停止持续对齐，解除挂载、恢复缩放和碰撞，并写回安全离座位置。 |

`OnSeatEntered` / `OnSeatExited` 是全端表现回调。远端玩家坐下或站起时，本端同样必须挂载、对齐和恢复远端 Avatar；若仅处理本地 Actor，其他客户端会看到角色停在原地、悬空或残留在座位上。

## 第一步：配置座位并记录原始状态

### 1. 配置对象层级

一个可坐座位至少应具有以下组成：

| 组成 | 是否必需 | 作用 |
| --- | --- | --- |
| 网络对象与座位脚本 | 是 | 接收 `OnSeatEntered` / `OnSeatExited`，并参与房间同步。 |
| 交互区域 Trigger | 是 | 检测本地玩家进入和离开，用于显示交互入口。 |
| `SeatAnchor` | 是 | 定义该座椅唯一的坐下位置与朝向；可作为移动座位或载具的子节点。 |
| `ExitAnchor` | 建议 | 定义 Actor 站起后的安全位置与朝向。 |

交互区域必须是 Trigger，不应与座位本体或载具上的实体碰撞体混用。座位锚点只描述坐下位置，不能替代 Trigger、焦点、按钮创建和点击入口。

座位锚点应尽量保持世界缩放为 `1, 1, 1`。非均匀缩放的父节点会带来剪切和动画变形风险；运行时的缩放反算只能减轻表现问题，不能替代资产层修正。

### 2. 缓存状态

座位不能只保存一组全局“当前玩家”数据。即使一个座位业务上只允许一人使用，本端仍可能需要处理远端 Avatar、切座回调和晚进房重建。应按 Actor 维护状态：

| 状态 | 用途 |
| --- | --- |
| `localActorId` | 本地玩家进入 Trigger 时缓存的 ID；按钮点击时重新解析 Actor。 |
| `hasLocalPassenger` | 本地玩家是否已被当前座位确认接纳；仅用于本地按钮状态。 |
| `seatedActors` | `Actor ID -> SeatAnchor`；供持续 Hips 对齐使用。 |
| `savedScale` | Actor 挂载前的原始 `localScale`；离座时恢复。 |
| `savedPosition` / `savedRotation` | Actor 坐下前的世界位姿；没有 `ExitAnchor` 时作为离座回退。 |
| `savedCollisionState` | Actor 落座前的碰撞状态；离座时恢复，不得固定写成某一值。 |
| `occupantActorId` | 可选同步业务状态，用于远端展示、晚进房恢复或业务统计；不替代 `CurrentPlayer`。 |

不要将长生命周期的 Actor 对象引用作为按钮入口状态。Actor 可能离房、销毁或重建；交互入口只缓存 `actorID`，点击时调用 `GetActorById(actorID)` 重新获取，返回空值时直接结束。

## 第二步：处理交互按钮

交互按钮的完整流程如下：

```text
本地 Actor 进入 Trigger
  → 缓存 actorID
  → EnableInteraction()
  → OnFocus()
  → AddInteractorButton()
  → 玩家点击“坐下”或“站起”
  → 发起 SitDown 或 StandUp 请求

本地 Actor 离开 Trigger、对象禁用或失焦
  → 非在座状态：DisableInteraction()
  → OnLostFocus()
  → RemoveInteractorButton()
```

范围回调、焦点回调和按钮点击只负责显示入口与发送请求。不要在这些入口中修改父节点、位置、缩放、碰撞或占用状态，必须等待座位确认回调。

### 1. 玩家进入和离开范围

当 Actor 进入交互区域时：

1. 过滤空 Actor 和远端 Actor，只有本地 Actor 可以影响本地交互 UI。
2. 缓存本地 `actorID`，不要缓存长期 Actor 对象引用。
3. 在座位可用时调用 `EnableInteraction()`，由焦点回调创建按钮。

当本地 Actor 离开交互区域时：

1. 若本地玩家尚未坐在当前座位，调用 `DisableInteraction()` 并清空 `localActorId`。
2. 若本地玩家已确认坐在当前座位，不得关闭交互通道，也不得清空 `localActorId`。

第二条是座位的特殊要求。移动座位会带着玩家离开原 Trigger；若按普通物体在 Exit 时关闭交互，玩家将无法再看到“站起”入口。

### 2. 创建和清理按钮

调用 `EnableInteraction()` 后，平台会在合适的焦点时机调用 `OnFocus`。在 `OnFocus` 中调用 `AddInteractorButton()` 创建并保存按钮引用，按钮文字只按已确认状态显示：

| 已确认状态 | 按钮文字 | 点击行为 |
| --- | --- | --- |
| 本地玩家未坐当前座位 | 坐下 | 请求 `SitDown` |
| 本地玩家已坐当前座位 | 站起 | 请求 `StandUp` |
| 平台座椅已被远端玩家占用 | 可保持普通坐下入口，或按业务需要置灰 | 发送后由平台拒绝 `SitDown` |

`DisableInteraction()` 或对象失焦后，平台会调用 `OnLostFocus`。在该回调中移除按钮并清空引用。对象禁用、销毁或手动注册了额外 UI / 输入监听时，也必须执行同样的清理和注销。

不要在初始化、`OnSeatEntered` 或 `OnSeatExited` 中直接创建范围按钮。按钮文字只能反映已确认状态，不能作为“是否在座”的状态来源。

## 第三步：发起坐下或站起请求

按钮点击属于本地输入。点击后先通过 `GetActorById(localActorId)` 重新获取 Actor；Actor 不存在时不做任何操作。

### 1. 发起坐下

本地 Actor 未坐当前座位时，按以下顺序处理：

1. 校验 Actor 存在且本地可操作。
2. 校验 Actor 不在飞行等与座位互斥的状态。
3. 解析当前座位锚点；锚点不存在时不发送请求。
4. 单座位以平台 `CurrentPlayer` 为占用依据；若本地没有可读的座椅状态，直接发起请求并让平台处理竞争。
5. 调用 `SitDown(座位脚本所在对象, switchSeat)`。

点击时不要提前执行挂载、Hips 对齐、禁飞、关闭碰撞或更新“已占用”状态。请求可能被拒绝、延迟或在切换座位时改变顺序，只有 `OnSeatEntered` 表示坐下真正成立。

### 2. 发起站起

本地 Actor 已确认坐在当前座位时，点击只调用 `StandUp(座位脚本所在对象)`。同样不要提前解除父子关系、恢复缩放、打开碰撞或将按钮切回“坐下”。

### 3. 切换座位

允许从一个座位直接切到另一个座位时，使用 `SitDown(新座位对象, true)` 发起请求。平台会先通知旧座位 `OnSeatExited`，再通知新座位 `OnSeatEntered`。

旧座位和新座位都必须保留完整闭环。不要手动先调用站起，也不要因切座跳过旧座位的缩放、碰撞、持续对齐和业务状态清理。

## 第四步：确认坐下并持续对齐

`OnSeatEntered(actor)` 收到非空 Actor 后，应对本地和远端 Actor 执行以下流程：

1. 读取该座位配置的唯一 `SeatAnchor`。
2. 在挂载前缓存 Actor 当前世界位置、世界旋转、`localScale` 和碰撞状态。
3. 将 Actor 挂到该锚点，将局部位置归零、局部旋转归零。
4. 使用“原始 Actor 缩放 ÷ 锚点 `lossyScale`”逐轴反算 Actor 局部缩放；对零值轴进行保护。
5. 查找 Actor 的 Animator 和 Hips 骨骼，以 Hips 相对根节点的世界偏移校正 Actor 根节点位置。
6. 在 `seatedActors` 中记录 `Actor -> SeatAnchor`，使后续帧能持续对齐。
7. 关闭或调整会导致角色与座位抖动、弹射的碰撞，并保存进入前状态。
8. 仅当 `actor.isLocal` 时，更新 `hasLocalPassenger`、按钮文字和本地交互通道。

### 1. 持续 Hips 对齐

坐姿过渡、自定义坐姿和 Animator 更新会持续改变 Hips 相对 Actor 根节点的位置。只在 `OnSeatEntered` 中对齐一次，会导致角色逐渐下沉、悬空或偏离移动座位。

因此应在动画更新后的阶段，对 `seatedActors` 中每个 Actor 重复执行：

```text
使用座位配置的 `SeatAnchor`
  → 确保 Actor 仍挂在锚点下
  → 重新反算缩放
  → 读取 Hips 世界位置
  → 调整 Actor 根节点，使 Hips 回到锚点位置
```

Animator 或 Hips 骨骼缺失时，只跳过 Hips 精对齐；仍必须保留父子挂载、局部归零、缩放和状态记录，不能中断已确认的座位流程。

### 2. 碰撞状态

落座后应关闭会造成座位抖动或弹射的碰撞，离座时恢复原始状态。必须按 Actor 保存原值，而不是离座时固定设置为“开启”。

`disableActorCollider` 只影响 Actor 与 Actor 的碰撞，不影响 Actor 与环境的碰撞。它可用于降低玩家互相挤压，但不能替代座位与角色实体碰撞的完整处理。若项目还需要控制角色实体 Collider，必须仅在平台允许的范围内关闭，并在离座时精确恢复缓存状态。

## 第五步：确认离座并恢复状态

`OnSeatExited(actor)` 是离座真正确认后的唯一清理入口。对每个非空 Actor 按以下固定顺序执行：

1. 先从 `seatedActors` 中删除 Actor，停止下一帧的持续 Hips 对齐。
2. 解除 Actor 与座位锚点的父子关系。
3. 恢复挂载前缓存的 `localScale`。
4. 恢复挂载前缓存的碰撞状态。
5. 使用 `actor.position` 和 `actor.rotation` 写入安全离座世界位姿。
6. 清除该 Actor 的锚点、缩放、位置、旋转和碰撞缓存。
7. 仅当 `actor.isLocal` 时，更新本地按钮并恢复本地交互逻辑。

离座位姿的回退顺序如下：

1. 使用显式 `ExitAnchor` 的位置和旋转。
2. 没有 `ExitAnchor` 时，使用落座前缓存的世界位置和旋转。
3. 缓存也不可用时，按座位朝向计算一个无碰撞的安全偏移位置。

不要只改 Actor GameObject 的 Transform。解除挂载后，ActorController 可能在同一帧或下一帧覆盖 Transform；必须通过 Actor 的位置、旋转 API 写入最终世界位姿。

## 第六步：实现多座椅载具

多座椅载具必须采用“一个载具根对象 + 多个独立座椅 NetworkObject”的拓扑：

```text
VehicleRoot NetworkObject
├── SeatAnchor_Driver   ← 只负责挂载驾驶座对象
├── SeatAnchor_Gunner   ← 只负责挂载炮手座对象
├── DriverSeat NetworkObject + DriverSeatScript
└── GunnerSeat NetworkObject + GunnerSeatScript
```

上图表示对象归属，不限定创建方式。`DriverSeat` 和 `GunnerSeat` 必须是两个独立 NetworkObject；可以直接配置为载具 Prefab 中对应 Anchor 的静态子对象，也可以运行时生成后再挂到 Anchor。Anchor 只负责挂载和位姿，不提供座椅逻辑。

每个座椅对象必须拥有自己的 Trigger、座椅脚本和 `SitDown` 目标：

```lua
-- DriverSeatScript
actor:SitDown(self.gameObject, true)

-- GunnerSeatScript
actor:SitDown(self.gameObject, true)
```

这里的两个 `self.gameObject` 是两个不同的 NetworkObject。禁止让根载具脚本用两个按钮把同一个 `self.gameObject` 传给两次 `SitDown`，也禁止把 `SeatAnchor` 直接作为 `SitDown` 参数。

## 第七步：补充座位能力

### 1. 自定义坐姿动画

自定义动画只能作为基础回调的扩展：

1. 在 `OnSeatEntered` 完成挂载和基础状态处理后播放。
2. 在 `OnSeatExited` 停止持续对齐、完成解除挂载后停止或恢复动画。
3. 不要新增同名座位回调来播放动画，否则会覆盖或绕开基础闭环。

### 2. 飞行与座位互斥

坐下前应拒绝飞行中的 Actor。若业务需要落座后隐藏或禁用飞行入口，应在坐下确认后对本地操作者执行；离座后恢复原有飞行能力。

若需要“开始飞行时自动站起”，订阅飞行开始事件后必须确认该 Actor 是本地玩家且已坐在当前座位，再请求 `StandUp`。脚本失焦、禁用或销毁时必须解除监听。

### 3. 摇杆移动自动站起

仅在需求明确时订阅主移动摇杆。摇杆回调中应确认本地 Actor 已坐在当前座位，再请求 `StandUp`。禁止在摇杆回调中直接解除挂载；脚本禁用或销毁时必须注销订阅。

### 4. 移动座位与载具

座位位于载具上时，座位闭环只负责 Actor 跟随和离座恢复。载具物理、输入、控制权和移动同步属于独立模块。

离座时，载具模块应额外清零本地输入缓存，防止玩家离开后载具继续沿用旧输入；不要把该逻辑当作静态座位的默认行为。

## 第八步：补充网络状态

`OnSeatEntered` / `OnSeatExited` 是瞬时事件。晚进房客户端通常不会收到它们发生前的回调，因此不能只依赖本地 `seatedActors` 缓存处理长期状态。

平台座椅的 `CurrentPlayer` 已经负责单座位互斥。只有需要把占用信息用于远端 UI、晚进房重建或业务统计时，才增加受主权控制的同步变量：

| 需求 | 最小同步信息 |
| --- | --- |
| 防止重复占座 | 不需要额外同步变量；由平台座椅 `CurrentPlayer` 拒绝第二次 `SitDown` |
| 显示远端占用状态 | 可选的 `occupantActorId` |
| 多座椅车辆远端定位 | 座椅 NetworkObject ID + 该座椅的 `occupantActorId` + 座椅 `SeatAnchor` |
| 晚进房恢复坐姿 | 对应座椅对象的占用者、`SeatAnchor` 和恢复所需的座位状态 |

同步状态必须在 `OnSeatEntered` / `OnSeatExited` 确认后更新，不能在按钮点击时提前写入。只有拥有对应同步对象写权限的一端可以写入。不要为了更新按钮文案而复制一份平台占用状态。

### 1. 晚进房状态重建

晚进房客户端读取到占用状态后：

1. 根据同步的 Actor ID 查找 Actor。
2. 根据座椅对象解析唯一的 `SeatAnchor`。
3. 若 Actor 尚未加载，等待 Actor 加载完成。
4. 按“确认坐下”的表现流程重建挂载、缩放、碰撞和持续 Hips 对齐。

如果选择同步座位状态，不要只同步“座位已被占用”。缺少占用者和座椅对象时，客户端无法将正确的 Avatar 放到正确的位置；如果没有远端展示或晚进房需求，则不需要增加这组同步状态。

### 2. 按钮与占用状态

本地玩家进入范围时，按钮只需要反映本地已确认的座位状态。平台 `CurrentPlayer` 负责最终互斥，业务占用同步不是按钮和坐下请求的必需前置条件：

| 当前状态 | 本地入口 |
| --- | --- |
| 本地玩家未坐当前座位 | 显示“坐下” |
| 本地玩家已坐当前座位 | 显示“站起” |
| 平台拒绝了远端占用下的 `SitDown` | 保持普通“坐下”文案；“已占用”属于可选业务表现 |
| 正在等待平台确认 | 保持当前已确认状态，可按需禁用重复点击 |

不要在请求发送时直接修改按钮文案。按钮仅在焦点创建、座位确认回调或同步状态更新后刷新。

## 常见错误

以下问题在静态座位或单客户端测试时不一定明显，但在多人、移动座位、动画过渡或父级缩放中很容易暴露：

### 1. 在按钮点击时直接挂载 Actor

按钮点击只能发送 `SitDown` 或 `StandUp` 请求。提前挂载 Actor、改位置、改碰撞或切换按钮状态，会让表现早于平台确认，并与 `OnSeatEntered` / `OnSeatExited` 冲突。

### 2. 用 actor.isLocal 过滤整个座位回调

`OnSeatEntered` / `OnSeatExited` 是全端表现回调。远端玩家落座和离座时，本端也要挂载、对齐、恢复缩放和解除挂载；只有本地按钮、输入和业务状态才用 `actor.isLocal` 单独处理。

### 3. 只在 OnSeatEntered 对齐一次

坐下过渡和坐姿动画会继续改变 Hips 相对 Actor 根节点的位置。只对齐一次会让角色逐渐陷座、悬空或偏离移动座位；必须在动画更新后按 `SeatAnchor` 持续校正。

### 4. 离座前没有删除持续对齐记录

如果离座时仍把 Actor 留在持续对齐列表里，刚解除挂载的 Actor 可能在下一帧又被拉回座位。离座处理必须先停止持续对齐，再解除挂载和恢复状态。

### 5. 离座位置只写到 Transform

解除挂载后，ActorController 可能接管根节点并覆盖 Transform。离座最终世界位置和旋转必须通过 Actor 的位置、旋转 API 写入。

### 6. 忽略座位锚点的缩放

带缩放或非均匀缩放的父链会影响 Actor 挂载后的外观。必须在挂载前缓存 Actor 原始 `localScale`，挂载后按锚点 `lossyScale` 反算，离座后恢复缓存值。

### 7. 扩展示例覆盖基础回调

自定义动画、禁飞、占用同步等能力只能插入基础回调的扩展点。一个脚本中只保留一份 `OnSeatEntered` / `OnSeatExited`，不要复制扩展示例后覆盖基础挂载、缩放、碰撞和清理流程。

### 8. 坐下后关闭交互通道

移动座位会让在座玩家离开原 Trigger。已确认在座时，如果调用 `DisableInteraction()` 或清空本地 Actor ID，玩家可能失去“站起”入口。

### 9. 把锚点配置当作完整交互

座位锚点只提供坐下位置和朝向，不能替代 Trigger、焦点、按钮创建 / 清理和点击入口。缺少完整交互链路时，不会自动出现坐下按钮。

### 10. 用业务占用变量替代平台座椅状态

一个座椅对象的 `CurrentPlayer` 已经是平台占用判断。额外的 `occupantActorId` 只能用于远端展示、晚进房恢复或业务统计，不能作为第二套座椅互斥机制，也不能要求每个座椅都必须配置。

### 11. 用 `RequestOwnership` 代替载具物理控制权

`HasOwnership()` 只表示同步变量写权限。SharedMode 载具驾驶应在座椅确认落座后申请载具根对象的 `RequestControllership()`，物理更新同时检查 `HasOwnership()` 和 `HasControllership()`。

### 12. 离座后按旧 Trigger 状态恢复按钮

`OnSeatExited` 已确认 Actor 离座后，应清零载具输入、释放控制权并清理按钮。不要因为旧的 `isInsideTrigger` 仍为 true 就重新创建坐下按钮；重新进入 Trigger 后再由 `OnFocus` 创建。

## 第九步：按场景验证

至少使用两个客户端进行以下验证。单客户端通过，不能证明远端挂载、切座和晚进房恢复正确。

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 交互按钮 | 进入范围、离开范围、再次进入范围 | 进入后由 `OnFocus` 创建按钮；离开或失焦后由 `OnLostFocus` 移除；再次进入后没有重复按钮。 |
| 基础坐下 | 本地玩家点击坐下，再点击站起 | 点击只发送请求；确认后才挂载或解除挂载；按钮在确认后更新。 |
| 移动座位 | 坐下后让座位离开原 Trigger | 在座玩家仍保留站起入口；站起后恢复正常范围交互。 |
| 远端观察 | 客户端 A 坐下，客户端 B 观察 | B 中 A 的 Avatar 挂到同一锚点并跟随移动，不会停在原地。 |
| 动画对齐 | 使用不同身高 Avatar 或自定义坐姿 | 坐姿过渡结束后 Hips 仍保持在锚点，不下沉、不悬空。 |
| 父级缩放 | 座位或父节点带缩放 | 坐下期间缩放合理；站起后恢复进入前的 Actor `localScale`。 |
| 碰撞 | 角色与座位、其它玩家接触后坐下和站起 | 不持续抖动或弹射；离座后碰撞恢复到进入前状态。 |
| 单座位容量 | A 坐下后 B 点击同一座椅对象 | B 的 `SitDown` 请求被平台拒绝；同一座椅始终只有一个乘员。 |
| 多座椅车辆 | A 坐驾驶座、B 坐炮手座 | 两个按钮指向两个不同座椅 NetworkObject，两个 Actor 分别落座。 |
| 切换座位 | 从座位 A 直接切到座位 B | A 完整离座清理后，B 完整挂载；不残留缩放、对齐或碰撞状态。 |
| 已被占用 | A 坐下，B 接近同一座位 | B 的 `SitDown` 请求由平台拒绝；是否显示额外“占用”文案属于可选业务表现。 |
| 晚进房 | A 已坐下，B 再进入房间 | B 根据同步占用者、座椅对象和 `SeatAnchor` 恢复 A 的正确坐姿和位置。 |

## 第十步：交付前检查清单

- [ ] `SitDown` / `StandUp` 只由本地 Actor 在按钮或明确的本地输入入口发起。
- [ ] Trigger 只缓存本地 `actorID`；点击时通过 `GetActorById` 重新获取 Actor。
- [ ] `OnFocus` 创建按钮，`OnLostFocus` 移除按钮并清空引用。
- [ ] 按钮点击不直接挂载、解绑、改缩放、改碰撞或修改占用状态。
- [ ] 已坐下的玩家离开座位 Trigger 后不会丢失站起入口；`OnSeatExited` 确认离座后再清理按钮和交互状态。
- [ ] `OnSeatEntered` / `OnSeatExited` 未以 `actor.isLocal` 整体过滤。
- [ ] 每个 Actor 都缓存了进入前的缩放、位姿和碰撞状态。
- [ ] 挂载前缓存 `localScale`，挂载后按 `SeatAnchor.lossyScale` 反算，离座解除父子关系后恢复。
- [ ] 已记录 `Actor -> SeatAnchor`，并在动画更新后持续 Hips 对齐。
- [ ] Animator 或 Hips 缺失时保留父子挂载和粗对齐，不中断流程。
- [ ] 离座时先删除持续对齐记录，再解除父子关系、恢复缩放和碰撞，最后通过 Actor API 写入离座位姿。
- [ ] `disableActorCollider` 未被误认为能够处理 Actor 与环境的全部碰撞。
- [ ] 多座椅车辆由多个独立 NetworkObject 组成，每个对象拥有自己的 `SitDown` 目标；占用判断以该对象的 `CurrentPlayer` 为准。
- [ ] 未把 VehicleRoot 或 SeatAnchor 传给座椅 `SitDown`。
- [ ] 切换座位时旧座位和新座位都执行完整闭环。
- [ ] 只有需要远端展示或晚进房恢复时，才同步占用者、座椅对象和座椅状态；防重复占座不依赖业务同步变量。
- [ ] 同步状态只在座位确认回调后、由具备写权限的一端更新。
- [ ] 已使用至少两个客户端完成远端观察、移动座位、切换座位和晚进房验证。
