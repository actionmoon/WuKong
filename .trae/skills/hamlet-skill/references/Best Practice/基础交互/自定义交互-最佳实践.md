# 自定义交互最佳实践

本文说明如何从零实现一个可联网的自定义交互对象，例如门、机关、NPC、商店入口、任务节点或奖励领取点。内容不依赖 Lua、C# 或特定脚本框架；文中的回调和 API 名称仅用于说明职责，不要求原样照搬。

最终应能实现以下体验：

1. 本地玩家进入可交互范围后，在获得焦点时看到正确的交互按钮；离开、失焦或对象禁用后按钮被正确清理。
2. 玩家点击按钮后，仅点击端在本地按钮回调中发起一次持久状态请求；主权方写入同步状态，所有客户端根据状态变化刷新表现。
3. 门的开关、机关进度、奖励领取和任务完成等持久状态由业务状态驱动，而不是由按钮文案或一次 `Interact` 事件推断。
4. 多个按钮能在本地正确分发；需要跨端区分具体动作时，额外传递动作 ID 并由主权方裁决。
5. 晚进房或断线重连的客户端能根据同步状态恢复对象表现和可用按钮。

> **前置阅读**：[基础交互](../../Manual/%E2%85%A0.%20核心系统%28Core%29/交互/基础交互.md)、[触发交互最佳实践](./触发交互-最佳实践.md)、[同步变量](../../Manual/%E2%85%A3.%20多人游戏与网络%28Multiplayer%29/数据与通信/同步变量.md) 和 [主权与控制权](../../Manual/Ⅳ.%20多人游戏与网络%28Multiplayer%29/网络基础/主权与控制权.md)。
>
> 本文是语言无关的设计说明，正文直接说明按钮生命周期、消息路由和事件/状态边界；

## 阅读路线

建议按以下顺序实现和验证。不要先实现动画、UI 特效或复杂业务分支：

```text
对象、基础交互组件与可选 Trigger 配置
  → 定义业务状态、权限归属和本地焦点上下文
  → OnFocus 创建按钮，OnLostFocus 清理按钮
  → 本地按钮点击 → 发起一次状态请求
  → 主权方裁决并写入持久状态 → 所有端按状态刷新表现
  → 按需：Interact(目标对象) → OnInteract(actor) 播放全端瞬时反馈
  → 多按钮、冷却、占用、晚进房等扩展
```

自定义交互中的功能可映射为下表。它适合帮助理解交互区域、按钮配置和消息分发的职责，但不应直接作为多人业务状态的完整实现。

| 自定义交互职责 | 自定义实现中的教学章节 |
| --- | --- |
| 交互范围、默认图标和按钮配置 | [第一步：配置对象并定义状态](#第一步配置对象并定义状态) |
| 进入/离开范围、开启/关闭交互 | [第二步：建立本地焦点入口](#第二步建立本地焦点入口) |
| `OnFocus` 创建按钮、`OnLostFocus` 清理按钮 | [第三步：处理按钮生命周期](#第三步处理按钮生命周期) |
| 按钮点击、状态请求与可选 `Interact` 调用 | [第四步：发起状态请求并处理联网事件](#第四步发起状态请求并处理联网事件) |
| 按钮配置中的本地动作 | [第六步：处理多按钮与本地交互](#第六步处理多按钮与本地交互) |

## 先理解交互模型

通用交互不等于拾取或座位。SDK 负责将本地 Actor 发起的 `Interact(目标对象)` 路由到目标对象的 `OnInteract(actor)`；它表达的是“发生过一次交互事件”，不维护门是否打开、奖励是否已领取等业务状态。

一个完整的自定义交互至少包含四层：

| 层次 | 运行范围 | 职责 |
| --- | --- | --- |
| 范围与焦点 | 本地客户端 | 识别本地玩家是否可见当前入口，开启/关闭交互通道。 |
| 交互按钮 | 本地客户端 | 在焦点阶段创建按钮、展示已确认状态、接收点击。 |
| 交互事件 | 所有客户端 | 可选。本地 Actor 调用 `Interact` 后，各端在 `OnInteract(actor)` 执行不需要晚进房重放的瞬时表现。 |
| 业务状态 | 主权方写入，所有客户端读取 | 保存开关、进度、库存、领取记录、冷却和占用等持久数据，并驱动对象与按钮表现。 |

默认联网链路如下：

```text
本地玩家进入范围
  → EnableInteraction()
  → OnFocus()
  → AddInteractorButton()
  → 点击按钮
  → 仅点击端发起一次状态请求
  → 主权方裁决并写入业务同步状态
  → 所有客户端收到状态变化并刷新表现
```

需要全端即时音效、粒子或短动画时，按钮点击端可以额外调用 `Interact(目标对象)`，所有在线端在 `OnInteract(actor)` 播放该效果；这条可选链路不得参与状态请求、主权申请或同步变量写入。

`Interact` 不会创建按钮，也不会再次触发按钮点击回调。它也不会自动同步业务状态。因此，不能把按钮文字、局部布尔变量或“本端刚收到过 `OnInteract`”作为跨端真实状态。

## 第一步：配置对象并定义状态

### 1. 配置对象

一个支持范围按钮和联网业务的自定义交互对象通常包括以下组成：

| 组成 | 是否必需 | 作用 |
| --- | --- | --- |
| 网络对象与业务脚本 | 需要联网状态时必需 | 承载同步变量、主权状态请求和可选的 `OnInteract(actor)` 瞬时事件。 |
| 基础交互组件 | 使用 `OnInteract` 时必需 | 使对象满足基础交互的组件配置和规则。 |
| 交互区域 Trigger | 按需 | 为“靠近后显示按钮”提供本地进入/离开入口。也可使用距离、按键或其它项目入口。 |
| 可视化节点与动画 | 按需 | 由业务状态驱动开门、机关运动、高亮、音效或 NPC 表现。 |
| 业务配置 | 按需 | 定义按钮文本、冷却时间、可用条件、奖励或动作类型；配置不是运行时状态。 |

交互区域必须是 Trigger，不能和实体碰撞体或其它独立玩法区域混为一用。只需要区域提示、传送或伤害效果时，可以只使用 Trigger 回调；不要为了区域逻辑额外开启交互或创建按钮。

API 文档说明 `OnInteract(actor)` 需要目标对象配置基础交互物件，且交互规则应与组件配置一致。若对象不具备这项前置配置，调用 `Interact` 不能替代组件本身。

### 2. 定义最小状态

不要从 UI 反推业务。按业务复杂度至少明确以下状态：

| 状态 | 归属 | 用途 |
| --- | --- | --- |
| `localActorId` | 本地临时状态 | 本地玩家进入范围时记录 ID；点击时重新解析 Actor，避免持有失效对象引用。 |
| `isInLocalRange` | 本地临时状态 | 表示当前对象是否应为本地玩家开启范围入口。 |
| `buttonReferences` | 本地临时状态 | 记录焦点阶段创建的按钮，失焦时清理并置空。 |
| `businessState` | 同步业务状态 | 例如门的开关、机关阶段、剩余次数、冷却截止时间或任务状态。 |
| `interactionPolicy` | 业务配置或同步状态 | 描述谁可以操作、是否被占用、是否允许重复操作及并发裁决规则。 |

`localActorId`、范围标记和按钮引用只能服务本地 UI 生命周期，不能用于表示全房间的占用、进度或完成状态。长期 Actor 对象引用也不应作为按钮入口状态：Actor 可能离房、销毁或重建，按钮点击时应重新获取本地 Actor；获取失败则直接结束本次点击。

### 3. 先定义状态机和幂等规则

在编写回调前，先列出状态转换及重复交互的结果。例如门的最小状态机为：

```text
关闭 --有效交互--> 打开
打开 --有效交互--> 关闭
```

领取奖励则不同：

```text
可领取 --主权方确认领取--> 已领取
已领取 --任意后续交互--> 拒绝或提示，不重复发奖
```

必须明确以下问题：

1. 哪些状态是持久状态，哪些只是播放一次的表现事件。
2. 两名玩家同时交互时，由谁裁决，后到请求的结果是什么。
3. 同一玩家重复点击、网络重放或主权迁移后，业务是否仍可安全重复执行。
4. 状态变化后，哪些对象表现、按钮文案和本地 UI 需要刷新。

涉及奖励、库存、任务进度或消耗的逻辑必须由权威一方在写入状态前再次校验资格和当前状态。不要仅凭客户端按钮是否可见或本地预检放行。

## 第二步：建立本地焦点入口

当交互入口由 Trigger 提供时，完整的本地流程如下：

```text
本地 Actor 进入 Trigger
  → 记录本地焦点上下文
  → EnableInteraction()
  → 平台在合适时机触发 OnFocus()

本地 Actor 离开 Trigger
  → DisableInteraction()
  → 平台触发 OnLostFocus()
  → 清理按钮和本地焦点上下文
```

进入与离开回调只建立或撤销当前对象的本地 UI 上下文，不执行开门、领取、扣除库存、播放全端业务表现或写入同步状态。

### 1. 过滤本地 Actor

Trigger 回调首先过滤空 Actor 和远端 Actor。只有本地 Actor 可以改变当前客户端的 C 区按钮、提示、高亮或 `localActorId`。

远端玩家进入同一对象的 Trigger，不得使当前客户端创建按钮、关闭按钮或覆盖本地 Actor 上下文。范围逻辑必须与跨端业务表现分开：前者是本地 UI，公共对象表现由业务同步状态驱动；可选的瞬时反馈才由 `OnInteract` 处理。

### 2. 开启与关闭交互通道

本地玩家进入范围、通过业务可用性检查后，调用 `EnableInteraction()`；离开、对象不可用或不再允许操作时调用 `DisableInteraction()`。

不要自行声明或封装与 `EnableInteraction`、`DisableInteraction` 同名的方法。它们是平台 API；同名封装会覆盖或绕开平台焦点状态机，导致 `OnFocus` / `OnLostFocus` 与按钮生命周期异常。

没有 Trigger 的交互也可以由距离检测、按键、瞄准或任务 UI 作为本地入口。此时仍要保证只有当前端处理输入，并在发起状态请求前完成本地可执行性检查；若创建 C 区按钮，按钮仍必须遵守下一节的焦点生命周期。

## 第三步：处理按钮生命周期

### 1. 只在焦点阶段创建和清理按钮

`EnableInteraction()` 只开启交互通道。对象成为焦点后，平台才会调用 `OnFocus`；应在该回调中创建按钮、保存按钮引用并设置当前已确认状态对应的文案、图标和可用性。

当对象失焦、交互被关闭或玩家离开范围后，平台会调用 `OnLostFocus`；应在该回调中移除创建过的按钮，注销按钮监听，并清空全部本地按钮引用。

```text
OnFocus:
  根据已确认的 businessState 创建按钮
  保存每个返回的按钮引用
  绑定当前语言对应的点击入口

OnLostFocus:
  注销每个按钮的本地监听
  移除指定按钮，或移除全部按钮
  清空按钮引用和仅服务焦点的本地状态
```

Lua 中，按钮点击入口是 `OnInteractorButtonClick(index)`；C# 中，应给 `AddInteractorButton()` 返回的 `Button` 注册 `onClick` 监听。C# 不会自动派发同名 `OnInteractorButtonClick`。

禁止在初始化、网络状态回调、`OnInteract`、动画回调或普通业务函数中创建范围按钮。这样会造成玩家未在范围内也能看到按钮、重复创建按钮，或离开后残留无效入口。

### 2. 按钮只展示状态

按钮文案、图标和是否显示应由 `businessState` 派生。例如：

| 已确认业务状态 | 按钮表现 | 点击后的行为 |
| --- | --- | --- |
| 门关闭 | 开门 | 发起开门交互请求。 |
| 门打开 | 关门 | 发起关门交互请求。 |
| 冷却中 | 冷却中、置灰或不显示 | 不发送业务请求。 |
| 已领取 | 已领取、置灰或不显示 | 不重复领取。 |
| 被他人占用 | 被占用、置灰或不显示 | 不发送抢占请求，除非业务明确支持。 |

不要通过读取“开门”“已领取”等文字判断真实状态，也不要在按钮点击后立即改文字模拟成功。按钮和对象表现都应在业务状态真正变化后刷新；被拒绝、延迟或并发竞争时，UI 不会与真实状态脱节。

### 3. 对象禁用时的清理

若对象会被禁用、销毁或动态卸载，必须确保本地按钮和额外输入监听也能收口。对象禁用前关闭交互通道；若框架生命周期不会保证触发失焦回调，则显式执行与 `OnLostFocus` 等价的按钮清理。

清理逻辑必须可重复调用，避免失焦和对象禁用连续到来时重复移除同一按钮或保留已经失效的引用。

## 第四步：发起状态请求并处理联网事件

### 1. 本地按钮只负责入口和请求

点击按钮是本地输入。按钮入口应按以下顺序处理：

1. 确认当前仍存在本地焦点上下文。
2. 通过 `localActorId` 或本地 Actor 服务重新获取 Actor；不存在则结束。
3. 根据已确认的业务状态做轻量预检，例如冷却、占用或操作条件。
4. 调用本地状态请求函数。该函数在本端有主权时写入同步变量；本端无主权时，仅向主权方发送一次请求，或申请主权成功后再写入。

若还需要全端瞬时反馈，点击端可额外对本地 Actor 调用 `Interact(目标对象)`。`Interact` 只对本地 Actor 有效，不要在远端 Actor、缓存的失效 Actor 或不属于当前端的 Actor 上发起该调用。

按钮点击可以调用本地状态请求函数，但不能据此直接确认业务成功或修改公共表现。同步变量只能在该函数确认本端主权后写入，或由主权端接收请求后写入；请求是否有效、是否被并发竞争取代，以及最终状态是什么，都必须由写入前的业务裁决决定。

### 2. 在 OnInteract 中处理可选的全端瞬时事件

本地 Actor 发起 `Interact` 后，目标对象的 `OnInteract(actor)` 是全端对象级回调。该回调只适合处理所有在线客户端都应看到、且不需要晚进房重放的瞬时表现，例如按键按下动画、点击音效、粒子效果或通用交互提示。

不要在 `OnInteract` 入口使用 `actor.isLocal` 过滤整个函数。否则远端玩家交互时，本端不会播放应有的对象表现。只有确实仅作用于操作者本机的 UI、镜头或输入反馈，才在对应的局部子分支中判断 `actor.isLocal`。禁止在此回调中申请主权、向主权方转发状态请求、写同步变量或修改持久业务状态。

推荐的职责划分如下：

| 位置 | 应做的事 | 不应做的事 |
| --- | --- | --- |
| 按钮点击 | 本地预检、选择动作、发起一次状态请求；按需调用 `Interact` | 直接确认业务成功、提前修改公共表现。 |
| `OnInteract(actor)` | 可选的全端瞬时表现 | 申请主权、转发状态请求、写同步变量、推断按钮来源。 |
| 主权方业务处理 | 再次校验、并发裁决、写入同步状态 | 相信某个客户端先改好的本地 UI。 |
| 状态变化监听 | 刷新对象表现、当前焦点按钮和本地 UI | 重新发起一次交互或再次写入同一状态。 |

### 3. 区分事件同步与状态同步

`Interact` 同步的是“发生了一次交互”这个事件，不等于状态已经改变。下表说明常见数据应放在哪里：

| 数据或效果 | 推荐通道 | 原因 |
| --- | --- | --- |
| 按钮按下音效、一次性粒子、短动画 | `OnInteract` 或业务事件 | 可作为瞬时表现，不是晚进房恢复依据。 |
| 门当前开关、机关阶段、任务进度 | 同步变量 | 必须最终一致，晚进房客户端需要当前快照。 |
| 单次奖励是否已领取、库存余量、占用者 | 主权方裁决后的同步状态 | 需要抵御重复点击和并发操作。 |
| 非主权方的状态修改请求 | 从点击端发给主权方的消息或 RPC，或申请主权 | 每次点击只发起一次请求；非主权方直接写同步变量会被静默忽略。 |

同步变量只能由当前网络对象的主权方写入。每次写入前都要实时检查主权，不能缓存“我是主权方”的结果；主权可能因断线、切后台或其它请求而改变。非主权方需要修改业务状态时，必须从本地按钮入口仅发起一次主权请求或主权消息；主权方收到后还要重新检查主权和业务条件。

只需要局部 UI 或本地表现的功能可以跳过状态请求和 `Interact`，直接在按钮点击入口执行本地业务。但必须在需求中明确该行为不会影响其它客户端，也不需要持久状态、奖励裁决或晚进房恢复。

## 第五步：用状态驱动表现和按钮

当主权方成功写入 `businessState` 后，所有客户端应使用同一套刷新函数或等价逻辑应用状态：

```text
业务状态变化
  → 更新对象的模型、动画、碰撞、特效和可交互性
  → 若对象当前处于本地焦点，刷新已有按钮的文字、图标和可点击状态
  → 刷新本地 HUD、提示或任务 UI
```

刷新应具有幂等性：对同一个状态重复调用，结果仍然一致。例如“门已打开”应始终将门摆到打开位置、按钮设置为“关门”，而不是每次收到刷新都反转一次门角度。

不要让状态监听反向发起状态请求或调用 `Interact`，也不要在 `OnInteract` 中用“取反”代替权威状态裁决。多个客户端同时点击时，多个取反操作可能产生不可预测的最终结果；应由主权方在实际写入前读取当前状态、校验规则并写入明确的新状态。

### 1. 冷却、一次性领取和占用

以下业务都应先由同步状态定义，再决定按钮表现：

| 业务 | 最小状态 | 主权方处理 |
| --- | --- | --- |
| 冷却机关 | 下次可用时间或剩余冷却 | 拒绝未到期请求，成功后写入新时间。 |
| 一次性奖励 | 已领取标记，必要时加领取者 ID | 已领取时拒绝，未领取时原子地写入领取结果并发放奖励。 |
| 独占操作台 | 占用者 ID、操作阶段 | 校验占用者和阶段，拒绝冲突请求。 |
| 多阶段机关 | 明确阶段值 | 只允许合法阶段迁移，拒绝跳阶段或重复推进。 |

若操作造成物理、动画或对象可用性的改变，物理开关和 Transform 应同样从已确认状态派生。不要在请求发出时先修改，随后再依赖超时回滚。

### 2. 状态就绪时机

网络对象的同步状态应在网络就绪后读取和监听。不要在网络对象尚未生成的初始化阶段，将默认值当作最终业务状态；晚到的状态快照可能覆盖本地预设。

状态监听注册、首次状态应用和对象表现恢复应遵循项目当前网络框架的生命周期。对象重新生成、主权切换或断线重连后，刷新逻辑仍必须能根据当前同步值完整重建表现。

## 第六步：处理多按钮与本地交互

### 1. 多按钮先在本地分发

多个按钮的点击来源只存在于本地按钮入口：Lua 可收到按钮索引，C# 为每个返回的 `Button` 注册各自的点击监听。`OnInteract(actor)` 不包含按钮索引，不能依赖它判断“刚才点击的是对话、商店还是任务”。

因此，多按钮先在本地根据按钮 ID 或监听器分发：

```text
点击“对话” → 打开本地对话 UI，或发送“对话”业务请求
点击“商店” → 打开本地商店 UI，或发送“商店”业务请求
点击“启动机关” → 发送带“启动机关”动作 ID 的权威请求
```

若多个按钮只需触发同一种全端对象效果，可以在本地选择动作后调用一次 `Interact`，并让 `OnInteract` 执行这项共同表现；状态请求仍必须在按钮入口单独发起。

若不同按钮必须在远端执行不同业务，不能只调用无参数的 `Interact`。应通过项目已有 RPC、主权消息或同步状态额外传递稳定的动作 ID；主权方按动作 ID 和当前业务状态裁决，所有端再由状态变化刷新结果。

不要用一个仅存在点击端的临时布尔变量让 `OnInteract` 猜测按钮来源。远端没有这个本地上下文，弱网、并发点击或事件顺序变化时会得到错误分支。

### 2. 本地交互例外

下列场景可以直接在按钮点击入口执行，不需要调用 `Interact`：

| 场景 | 处理方式 |
| --- | --- |
| 打开当前玩家的说明面板 | 直接打开本地 UI。 |
| 本地镜头切换、拍照或引导高亮 | 直接执行本地表现。 |
| 不影响其它玩家的设置页或筛选菜单 | 直接更新本地状态。 |

以下场景仍应进入权威状态链路：发放奖励、扣除资源、改变公共对象、推进共享任务、占用交互物、改变会影响其它玩家的门或机关。

### 3. 按钮配置与监听清理

按钮的文字、图标、背景和本地动作可由配置驱动。配置应描述“按钮是什么”，而不是保存“当前是否成功执行”的运行时状态。

每个焦点周期中创建的按钮都要有对称的清理：移除按钮前注销本地监听，移除后清空引用。再次获得焦点时按当前已确认状态重新创建，不复用已经失焦的按钮实例。

## 第七步：补充网络能力

### 1. 晚进房和断线重连

`OnInteract` 是瞬时事件。晚进房客户端通常不会收到它之前发生过的事件，因此不能只依赖该回调恢复门、机关或领取结果。

需要恢复的对象至少同步当前业务状态：

| 需求 | 最小同步信息 |
| --- | --- |
| 恢复门或机关表现 | 当前开关或阶段值。 |
| 显示冷却 | 下次可用时间或可用状态。 |
| 防止重复领取 | 已领取标记；按玩家领取时还需要领取者或领取集合。 |
| 恢复独占操作 | 占用者 ID 与操作阶段。 |
| 恢复多动作结果 | 当前业务阶段及必要的动作结果，而不是仅同步最后一次按钮索引。 |

客户端收到同步快照后，应直接执行状态刷新：更新对象表现，并在本地玩家当前聚焦时显示正确按钮。不要为了补状态而伪造一次 `OnInteract`。

### 2. 并发和主权迁移

两名玩家同时点击时，本地预检只能优化体验，不能保证业务正确。最终必须由主权方在实际写入前完成以下步骤：

```text
收到请求
  → 实时确认仍拥有主权
  → 读取最新业务状态
  → 校验玩家资格、动作类型、冷却和占用条件
  → 计算明确的新状态
  → 写入同步状态
```

主权方断线或切后台后，主权可能转移。新的主权方接管周期性逻辑、冷却推进或延迟执行前，应基于同步状态重建工作，并保证重复接管不会重复发奖、重复播放关键结果或重复销毁对象。

### 3. 频率控制和反馈

频繁点击的按钮应有本地防抖或“请求中”反馈，但该反馈仅用于减少重复请求，不是业务锁。真实冷却、次数和占用仍以主权方同步状态为准。

请求被拒绝时，使用后续状态刷新或明确的本地失败反馈恢复按钮；不要长时间依赖本地“请求中”标记，避免请求丢失后入口永久不可用。

## 常见错误

以下问题在单客户端或简单按钮场景里不一定马上暴露，但接入多人、远端表现或多按钮后很容易出错：

### 1. 在错误的生命周期创建按钮

按钮必须在 `OnFocus` 创建，在 `OnLostFocus` 移除。把创建逻辑放到初始化、网络状态回调、`OnInteract` 或普通业务函数里，会导致玩家不在范围内也看到按钮，或离开后残留失效入口。

### 2. 用按钮文案或 `Interact` 推断业务状态

按钮文案只是表现，`Interact` 只是一次交互事件。门是否打开、奖励是否领取、机关是否冷却完成，都必须由业务状态或同步状态决定。

### 3. 把 Lua 和 C# 的按钮回调模型混用

Lua 的按钮点击入口是 `OnInteractorButtonClick(index)`；C# 则要给 `AddInteractorButton()` 返回的 `Button` 单独注册 `onClick`。如果在 C# 里直接照搬 Lua 的同名方法，按钮点击不会生效。

### 4. 用 `OnInteract` 处理持久状态请求

`OnInteract(actor)` 是网络同步后的对象级消息，本地玩家调用 `Interact` 后，所有在线端都会收到这个回调。若在其中申请主权、向主权方发送状态请求或写同步变量，一次本地点击会被每个在线端重复执行和转发。持久状态请求必须从 `OnInteractorButtonClick` 或 C# 的本地 `Button.onClick` 发起；`OnInteract` 只保留给全端瞬时表现。

## 第八步：按场景验证

至少使用两个客户端验证交互。单客户端只能证明本地按钮入口，不能证明远端表现、状态裁决和晚进房恢复正确。

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 焦点按钮 | 进入范围、离开范围、再次进入 | 只在 `OnFocus` 创建按钮；只在 `OnLostFocus` 清理；不会重复或残留。 |
| 远端范围 | 客户端 A、B 分别进入同一对象范围 | 每个客户端只受自己的本地 Actor 影响，不会被远端进出关闭或创建按钮。 |
| 联网事件 | A 点击按钮并启用瞬时反馈，B 观察 | A 仅调用一次 `Interact`；A、B 都收到并执行应有的瞬时对象表现。 |
| 状态同步 | A 点击一次门或机关按钮，B 观察 | 只有点击端发起一次状态请求；状态由权威一方写入，A、B 的对象表现和按钮文案最终一致。 |
| 并发交互 | A、B 同时点击一次性奖励或独占机关 | 只有符合业务规则的一次状态迁移成功；不会重复奖励或出现两个占用者。 |
| 多按钮 | 分别点击不同按钮 | 本地按正确动作分发；需要跨端区分的动作带有稳定动作 ID，不依赖 `OnInteract` 猜测。 |
| 本地例外 | 点击本地说明或镜头按钮 | 仅当前端变化，不发送无意义的网络交互。 |
| 失焦清理 | 对象禁用、销毁或强制失焦 | 按钮监听和引用被清理，不留可点击的失效入口。 |
| 晚进房 | A 已改变公共状态，B 再进入房间 | B 根据同步状态直接恢复对象表现和按钮，而非等待旧 `OnInteract`。 |
| 主权迁移 | 在冷却或持续机关期间让主权方断线/切后台 | 接管端从当前状态恢复，且不会重复执行关键业务。 |

## 第九步：交付前检查清单

- [ ] 对象已配置基础交互组件；需要范围入口时，交互区域是独立的 Trigger。
- [ ] 已区分本地焦点状态、瞬时交互事件和持久业务状态。
- [ ] Trigger 回调只处理本地 Actor 的范围上下文，未让远端 Actor 污染本地 UI。
- [ ] `EnableInteraction` / `DisableInteraction` 直接调用平台 API，未被同名 helper 覆盖。
- [ ] 按钮只在 `OnFocus` 创建，只在 `OnLostFocus` 或等价清理路径移除并清空引用。
- [ ] 按钮文案、图标和可用性由已确认业务状态驱动，不是状态来源。
- [ ] 点击按钮只在本地执行一次预检和状态请求，没有提前确认业务成功或修改公共表现。
- [ ] 持久状态请求从本地按钮回调发起；只有主权方能写同步变量，且一次点击不会经由 `OnInteract` 被多端重复转发。
- [ ] 需要全端瞬时反馈时，才由本地 Actor 调用 `Interact(目标对象)`，统一瞬时表现放在 `OnInteract(actor)`。
- [ ] `OnInteract` 未因 `actor.isLocal` 被整体过滤；仅本地 UI 子分支按需判断。
- [ ] `OnInteract` 不申请主权、不转发状态请求、不写同步变量、不处理持久状态。
- [ ] 已明确 `Interact` 只同步事件，不自动同步门、奖励、任务或占用等业务状态。
- [ ] 持久状态由主权方写入同步变量；非主权方通过消息或 RPC 请求，写入前实时检查主权。
- [ ] 状态刷新是幂等的，能由当前状态完整重建对象表现和焦点按钮。
- [ ] 多按钮在本地点击入口分发；跨端不同动作不依赖 `OnInteract` 推断按钮来源。
- [ ] 已明确哪些入口是纯本地交互，哪些必须经过联网状态裁决。
- [ ] 已用至少两个客户端验证远端表现、并发交互和晚进房状态恢复。
