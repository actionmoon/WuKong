# 自定义拾取最佳实践

本文说明如何从零实现一个可联网的自定义拾取物。内容不依赖 Lua、C# 或特定脚本框架，文中的名称只用来说明职责，不要求原样照搬。

最终应能实现以下体验：

1. 玩家进入范围后看到“拾取”按钮，离开范围后按钮被正确清理。
2. 点击“拾取”按钮后，平台确认拾取，物体贴合玩家手掌；其他客户端也能看到同一表现。
3. 持有时显示丢弃和可选的功能按钮；放下后恢复物理、层级和拾取按钮。
4. 可按需要增加丢弃后销毁和晚进房状态恢复。

> **前置阅读**：[基础交互](../../Manual/%E2%85%A0.%20%E6%A0%B8%E5%BF%83%E7%B3%BB%E7%BB%9F%28Core%29/%E4%BA%A4%E4%BA%92/%E5%9F%BA%E7%A1%80%E4%BA%A4%E4%BA%92.md)、[触发交互最佳实践](./触发交互-最佳实践.md)。
>
> 本文按实现顺序整理了多人拾取所需的约束和检查项。官方参考组件用于理解功能分层，但其中部分旧实现不满足当前的多人、物理和位姿规则，本文会在对应章节明确说明应如何改造。

## 阅读路线

建议按以下顺序实现和验证，而不是先实现 UI 或扩展功能：

```text
对象与交互区域配置
  → 初始化并记录原始状态
  → 创建、点击和清理交互按钮
  → 发起拾取请求 → OnPickup 挂手、对齐、关闭物理
  → 发起丢弃请求 → OnDrop 还原父节点与物理
  → 持有时的按钮、销毁、晚进房等扩展
```

## 先理解拾取流程

平台的 `Pickup(物体, 手, 拾取矩阵)` 和 `Drop(物体)` 只负责发送“拿起”或“放下”的请求。平台确认后，拾取物自身才会收到 `OnPickup(Actor, Hand, PickUpPoint)` 或 `OnDrop(Actor, Hand)` 回调。挂手、摆放位置、物理开关和 UI 都要在拾取脚本中处理。

自定义拾取分为三个部分：

| 部分 | 运行范围 | 职责 |
| --- | --- | --- |
| 交互按钮 | 本地客户端 | 在玩家进入范围时创建按钮，点击按钮后发送拾取或丢弃请求，离开范围后清理按钮。 |
| 拾取流程 | 请求由本地 Actor 发起；确认回调在所有客户端执行 | 本地检查后发起 `Pickup`；确认后关闭物理、挂到手骨并对齐位置。 |
| 丢弃流程 | 请求由本地 Actor 发起；确认回调在所有客户端执行 | 本地持有者发起 `Drop`；确认后还原父节点和物理。 |

`OnPickup` / `OnDrop` 是全端表现回调。远端玩家拾取时，本端同样要把物体挂到远端角色的手上；若仅处理本地 Actor，其他客户端的物体会停在原地或表现异常。

## 第一步：配置对象并记录原始状态

### 1. 配置对象层级

一个可拾取物至少应具有以下组成：

| 组成 | 是否必需 | 作用 |
| --- | --- | --- |
| 网络对象与拾取脚本 | 是 | 接收 `OnPickup` / `OnDrop`，并保证对象能参与房间同步。 |
| 实体碰撞体 | 建议 | 放下时参与场景碰撞；持有期间必须关闭。 |
| 刚体 | 按物体需求 | 放下后需要重力、碰撞或投掷效果时使用。 |
| 交互区域 Trigger | 是 | 触发本地玩家进入、离开和焦点按钮。 |
| `GripPoint` 子节点 | 可选 | 定义手掌应握住的位置与朝向。 |

实体碰撞体和交互区域要分开：实体碰撞体用于物理碰撞，交互区域必须是 Trigger。官方组件在没有交互区域时会创建球形 Trigger，并按对象缩放换算半径。自定义实现也可以使用盒形或其它形状，但不要误删或复用其它功能的 Trigger。

`GripPoint` 可放在任意子层级。它表达的是“手掌应落在物体的哪个位置”，而不是简单的局部偏移；后续必须按世界矩阵差计算。

### 2. 缓存状态

每个拾取物应维护以下最小状态：

| 状态 | 用途 |
| --- | --- |
| `currentHolder` | 当前拿着物体的 Actor 引用或 ID；判断本物体是否被拿起时，以它为准。 |
| `heldHand` | 当前使用的手，用于找到手骨和对齐掌心。 |
| `previousParent` | 拾取前的父节点，用于放下后恢复对象层级。 |
| `rigidbodyInitialKinematic` | 初始化时缓存的刚体 `isKinematic` 值。 |
| `bodyColliders` | 初始化时缓存的所有非 Trigger 实体碰撞体，以及其初始启用状态。 |
| `gripPoint` | 可选的手柄/握点 Transform。缺失时允许降级为物体原点贴掌心。 |

初始化时完成以下工作：

1. 收集物体和子节点上的全部 Collider，只将 `isTrigger == false` 的实体碰撞体放入 `bodyColliders`；交互区域 Trigger 必须保留启用。
2. 缓存刚体初始 `isKinematic`。放下时必须恢复该值，不能固定设为 `false`。
3. 缓存每个实体碰撞体最初是否启用。放下时恢复各自原来的状态。
4. 获取 `gripPoint` 时允许为空，不能因缺少握点中断拾取。

## 第二步：处理交互按钮

交互按钮的完整流程如下：

```text
本地 Actor 进入 Trigger
  → EnableInteraction()
  → OnFocus()
  → AddInteractorButton()
  → 玩家点击按钮
  → 发起 Pickup 或 Drop 请求

本地 Actor 离开 Trigger、对象禁用或失焦
  → DisableInteraction()
  → OnLostFocus()
  → RemoveInteractorButton()
```

范围回调和按钮回调只负责显示入口、响应点击和发送请求。不要在这里挂手、还原父节点、切换物理或修改当前持有者，这些都必须等待 `OnPickup` / `OnDrop` 确认。

### 1. 玩家进入和离开范围

当 Actor 进入交互区域时：

1. 先过滤空 Actor 和远端 Actor，避免远端玩家影响本地按钮。
2. 检查 Actor 是否允许交互。
3. 物体无人持有时，调用 `EnableInteraction()`；物体被其他玩家持有时，不显示拾取按钮。

当本地 Actor 离开交互区域时，调用 `DisableInteraction()`。离开范围只表示不再显示当前物体的范围按钮，不表示玩家放下物体。

不要创建与 `EnableInteraction` / `DisableInteraction` 同名的辅助函数。这样可能绕开平台的焦点处理，导致按钮无法按预期创建或清理。

### 2. 创建和清理按钮

`EnableInteraction()` 后，平台会在合适的焦点时机调用 `OnFocus`。在 `OnFocus` 中调用 `AddInteractorButton()` 创建按钮，并保存返回的按钮引用。

`DisableInteraction()`、玩家离开范围或对象失焦后，平台会调用 `OnLostFocus`。在 `OnLostFocus` 中调用 `RemoveInteractorButton(button)` 移除按钮，并清空保存的引用。

不要在 `Awake`、`Start`、`OnPickup` 或 `OnDrop` 中创建范围按钮。否则玩家不在范围内也可能看到按钮，或按钮离开范围后仍然残留。

### 3. 处理按钮点击

按钮点击是本地输入，只负责调用拾取或丢弃流程：

| 脚本语言 | 点击处理方式 |
| --- | --- |
| Lua | 在 `OnInteractorButtonClick(index)` 中按按钮序号处理。 |
| C# | 为 `AddInteractorButton()` 返回的 `Button` 注册 `onClick` 监听。C# 不会自动调用 `OnInteractorButtonClick`。 |

范围内的“拾取”按钮应只调用[第三步：拾取流程](#第三步拾取流程)。持有后的“丢弃”按钮应只调用[第五步：丢弃流程](#第五步丢弃流程)。按钮点击后不要提前改文案、挂手或还原物理。

按钮文字只用于提示，不能用“拾取”或“丢弃”字样判断物体状态。是否被拿起始终以 `currentHolder` 为准。

## 第三步：拾取流程

拾取分为两段：本地玩家点击按钮后发起请求，以及平台确认后的 `OnPickup` 回调。

```text
本地点击“拾取”
  → 检查当前能否拾取
  → 关闭物理
  → 请求 Pickup
  → 平台确认
  → OnPickup 中挂到手上并对齐
```

请求前必须先关闭物理。若请求被拒绝或取消，并且之后不会触发 `OnPickup`，要恢复物理。不要只靠很短的超时恢复，因为确认可能晚到，导致物体再次参与碰撞。

### 1. 发起拾取请求

`Pickup` 只能由本地 Actor 发起。按以下顺序处理：

1. 获取本地 Actor；不存在则结束。
2. 检查本地 Actor 不处于忙碌状态。
3. 检查双手都没有其它拾取物。
4. 检查当前物体没有持有者。
5. 调用可以重复执行的 `DisablePhysical()`。
6. 计算 GripPoint 相对物体根节点的矩阵，并调用 `Pickup(本物体, 指定手, gripMatrix)`。

检查手中是否已有物品时，使用覆盖双手的 `GetPickupInHand(HandType.All)`。即使当前平台实际只支持右手拾取，也不要只查右手。

当前 API 文档标注的拾取能力仅支持右手，向左手发起 `Pickup` 不会完成拾取。实现时仍应保留并传递回调中的手参数，让状态、挂骨和矩阵计算不只写死右手；平台将来支持其它手时，就不用重写拾取流程。

拾取流程已经处理对象权限。在 `Pickup` 前额外申请权限，会增加不必要的失败情况，不应作为普通拾取流程的一部分。

最小请求流程如下。发送 `Pickup` 请求后，不要立即修改持有状态：

```text
点击“拾取”按钮：
  获取本地 Actor；不存在则结束
  若本地 Actor 忙碌、任一手已有物品，或物体已被其他玩家持有：
    结束

  DisablePhysical()                 // 覆盖平台确认前的这段时间
  请求 Pickup(本物体, 当前支持的手, gripMatrix)
```

### 2. 请求前关闭物理

拾取过程中，物理状态应按下表处理：

| 时机 | 刚体 | 实体碰撞体 | Trigger 交互区域 |
| --- | --- | --- | --- |
| 请求 `Pickup` 前 | 强制 `isKinematic = true` | 禁用 | 保持启用 |
| `OnPickup` 确认 | 再次执行同一操作 | 再次禁用 | 保持启用 |

`DisablePhysical()` 会在“发起请求前”和“确认拾取后”至少调用两次。它必须允许重复调用，并且不能覆盖初始化时记录的状态。

只设置 `isKinematic = true` 不够。玩家站在物体上拾取时，如果实体碰撞体仍启用，玩家的角色碰撞体会继续把物体当作地面；物体移动到手上后会不断把玩家推出，造成顶飞或抖动。因此必须关闭非 Trigger 的实体碰撞体。

## 第四步：确认拾取

平台确认后的回调才表示拾取真的成功。所有客户端都必须执行挂手、对齐、父节点和物理处理；只有刷新本地 UI 时才需要判断 `actor.isLocal`。

### 1. 请求时计算握点矩阵

当物体存在 `GripPoint` 时，传给 `Pickup` 的矩阵应表示“握点相对于拾取物根节点的变换”：

```text
objectWorld = TRS(object.position, object.rotation, one)
gripWorld   = TRS(gripPoint.position, gripPoint.rotation, one)
gripMatrix  = inverse(objectWorld) × gripWorld
```

两个 TRS 的缩放都使用单位缩放 `one`。不要直接使用 GripPoint 的局部位置和局部旋转：当 GripPoint 不在物体根节点的直接子级，或物体有缩放时，局部坐标会算错。

GripPoint 缺失时传入单位矩阵，物体根节点会直接贴合掌心，拾取流程仍应继续。

### 2. 确认后对齐到掌心

在 `OnPickup` 中，平台传回的 `pickUpPoint` 与请求矩阵方向相反。最终的位置和旋转按下面的矩阵计算：

```text
palmWorldMatrix  = TRS(CalculatePalmTransform(hand), one)
pickupMatrix     = inverse(pickUpPoint)；缺失时为单位矩阵
finalWorldMatrix = palmWorldMatrix × pickupMatrix
```

将 `finalWorldMatrix` 中的位置和旋转赋给拾取物。矩阵相乘的顺序不能颠倒。

手部骨骼要通过 `currentHolder.gameObject` 上的 `Animator` 动态获取，不要写死角色节点路径。先把物体设为手骨的子物体，再写入上面的最终位置和旋转。如果 Animator 或手骨缺失，跳过挂手，但仍要完成物理和状态处理。

### 3. 实现 OnPickup

对所有非空 Actor 执行以下步骤，不得用 `actor.isLocal` 在函数入口过滤：

1. 调用 `DisablePhysical()`。
2. 将 `currentHolder` 和 `heldHand` 更新为回调参数。
3. 从拿起到放下的这段时间里，在第一次挂手前记录 `previousParent`。不能把手骨当成原始父节点保存。
4. 动态查找该 Actor 对应手骨，并将物体挂到手骨。
5. 按“掌心世界矩阵 × 拾取矩阵”写入位置和旋转。
6. 仅当持有者是本地 Actor 时，更新本地 UI 为“放下”等本地表现。

`pickUpPoint`、Animator 和手骨都可能缺失。`pickUpPoint` 缺失时使用单位矩阵；Animator 或手骨缺失时跳过挂手。无论哪种情况，都要更新持有者并关闭物理。

`OnPickup` 的最小流程如下：

```text
OnPickup(actor, hand, pickUpPoint)：
  若 actor 为空：结束
  DisablePhysical()
  保存原始父节点（仅本次拿起后的第一次挂手）
  currentHolder = actor；heldHand = hand
  查找 actor 的对应手骨并挂父节点
  finalWorldMatrix = PalmWorldMatrix(actor, hand) × inverseOrIdentity(pickUpPoint)
  应用 finalWorldMatrix 的位置与旋转
  仅 actor 为本地时刷新持有时的 UI
```

## 第五步：丢弃流程

丢弃同样分为两段：本地持有者点击“丢弃”按钮后发起请求，以及平台确认后的 `OnDrop` 回调。

```text
本地点击“丢弃”
  → 确认本物体由本地玩家持有
  → 请求 Drop
  → 平台确认
  → OnDrop 中还原父节点和物理
```

### 1. 发起丢弃请求

`Drop` 只能由本地持有者发起。判断“本物体由本地玩家持有”时，使用当前物体记录的 `currentHolder`：

```text
currentHolder != null && currentHolder.isLocal
```

不要用“玩家手中是否有任意物品”判断。`IsPickup()` 只能说明玩家拿着某个物体，不能说明拿着当前物体；玩家拿着其它物体时，错误的判断会对当前物体发送 `Drop`。

点击丢弃按钮后，只调用 `Drop(本物体)`。不要在点击时提前恢复父节点、打开碰撞体或清空 `currentHolder`，必须等 `OnDrop` 确认。

### 2. 确认丢弃

`OnDrop` 在所有客户端执行。首先检查回调中的 Actor 是否就是当前持有者：

```text
actor != null && actor 与 currentHolder 是同一 Actor
```

不匹配时直接忽略。这样可以避免其它 Actor 的放下操作误改当前物体。

检查通过后，按以下顺序处理：

1. 将物体父节点恢复为 `previousParent`，然后清空该记录。
2. 调用 `EnablePhysical()`，恢复刚体最初的 `isKinematic` 值，并恢复实体碰撞体最初的启用状态。
3. 清空 `currentHolder` 和 `heldHand`。
4. 仅在放下者是本地 Actor 时，隐藏丢弃按钮并恢复本地 UI。

`OnDrop` 的最小流程如下：

```text
OnDrop(actor, hand)：
  若 actor 为空或 actor != currentHolder：结束
  恢复 previousParent
  EnablePhysical()
  清空 currentHolder、heldHand、previousParent
  仅 actor 为本地时清理持有时的 UI
```

## 第六步：处理持有时的按钮

官方组件在确认拾取后显示投掷按钮、主按钮、子按钮或摇杆，并隐藏牵手等不能同时使用的入口；确认放下后再把这些按钮收起。自定义实现也应遵守这个时机：

1. `OnPickup` 确认后，只向本地持有者显示丢弃按钮和持有时可用的功能。
2. 丢弃点击只由本地持有者发起 `Drop(本物体)`；不能用远端 `currentHolder` 调用。
3. `OnDrop` 确认后隐藏持有时的 UI，并在必要时恢复与持物冲突的角色功能。
4. 主/子按钮和摇杆只负责响应点击。物体是否被拿起，仍要看 `currentHolder` 等状态。

参考组件还会在角色操作模式变化时，重新显示范围入口或持有时的按钮。自定义实现若有类似的“可操作 / 不可操作”状态，也只应刷新 UI，不要直接改动拾取、物理或网络状态。

若持有物会限制飞行、牵手或其它角色能力，必须区分两类操作：挂手、位姿和物理属于全端表现，不能过滤远端 Actor；停止飞行等只影响操作者自身的角色动作，则只在 `actor.isLocal` 时调用。不要为了执行本地角色动作而把整个 `OnPickup` 回调变成仅本地执行。

## 第七步：补充网络功能

`currentHolder` 只记录本客户端收到过的拾取回调。玩家在物体被拿起后才进入房间时，平台通常不会补发以前的 `OnPickup`。因此该玩家不知道谁拿着物体，也不会自动看到物体在对方手上。

如果需要防止晚进房玩家重复拾取，并让其看到物体在正确的手上，需要同步以下信息：

| 需求 | 最小同步信息 |
| --- | --- |
| 防止晚进房重复拾取 | `isHeld` 或 `holderActorId` |
| 显示正确的按钮 | `holderActorId`，并与本地 Actor ID 比较 |
| 重新挂到手上 | `holderActorId`、`handType`、握点矩阵 |

只有当前负责同步对象的一端可以写入这些状态。状态应在 `OnPickup` / `OnDrop` 确认后更新，不能在按钮点击时提前更新。

### 1. 晚进房与状态重建

晚进房客户端收到状态后，先根据 `holderActorId` 找到持有者。找到后，使用同步的 `handType` 和握点矩阵，再执行一次“查手骨、挂父节点、对齐掌心”的步骤。如果 Actor 还没有加载完成，等其加载完成后再执行。不要只同步 `isHeld`，否则客户端只能知道物体被拿走了，却无法把它放到正确的手上。

交互范围的进入/离开仍只应为本地 Actor 创建或移除拾取按钮。按钮文案和点击行为由 `isHeldByLocal()` 驱动：

| 当前状态 | 本地按钮 |
| --- | --- |
| 本地玩家持有本物体 | 显示“放下”，点击请求 Drop |
| 远端玩家持有本物体 | 不显示“放下”；可隐藏、置灰或显示“被占用” |
| 无人持有且本地玩家双手空闲 | 显示“拾取”，点击请求 Pickup |

不要在请求发送时提前改 UI。UI 仅在聚焦创建、`OnPickup` 确认和 `OnDrop` 确认时刷新。

### 2. 离房与延迟销毁

参考组件还支持“持有者离房销毁”和“丢弃后延迟销毁”。两项都属于可选功能：

| 扩展 | 处理方式 |
| --- | --- |
| 持有者离房销毁 | 仅在本地玩家已确认持有且确实需要时，绑定“持有者离房后销毁”。 |
| 丢弃后延迟销毁 | 在 `OnDrop` 的持有者检查通过后开始计时；只有当前负责同步对象的一端可以推进计时和执行网络销毁；重新拾取时取消计时。 |

## 常见错误

以下问题都可能在单客户端测试时不明显，却会在多人、复杂层级或特殊物理状态下出错：

### 1. 在按钮点击时直接挂手或修改状态

按钮点击只发送 `Pickup` 或 `Drop` 请求。提前挂到手骨、恢复物理、清空持有者或切换 UI，会让本地表现早于平台确认，并与 `OnPickup` / `OnDrop` 冲突。

### 2. 直接使用 GripPoint 的局部位置和旋转

GripPoint 不一定是物体根节点的直接子节点，物体也可能有缩放。直接使用局部位姿会造成手持位置错误；应按世界矩阵计算握点相对物体的矩阵。

### 3. 用“手中有物品”判断当前物体是否被持有

手中有物品只能说明玩家拿着某个物体，不能说明拿着当前物体。当前物体的状态必须由它自己的 `currentHolder` 判断。

### 4. OnDrop 不检查当前持有者

`OnDrop` 是全端回调，不能收到任意 Actor 的放下消息就重置当前物体。必须先确认回调 Actor 与 `currentHolder` 相同。

### 5. 放下时判断 prevParent 是否为 nil

`prevParent` 为 `nil` 表示物体应解除父子关系。此时仍必须调用 `SetParent(prevParent)`；判空后跳过调用会使物体保留在当前父节点下。

### 6. 只要存在持有者就显示“丢弃”

当前持有者可能是远端玩家。显示“丢弃”按钮和发送 `Drop` 前，还要确认 `currentHolder` 是本地玩家。

### 7. 放下时固定将刚体设为非运动学

有些物体初始就是 `isKinematic = true`。放下时必须恢复初始化记录的值，而不是固定设置为 `false`。

### 8. 只在本地执行 OnPickup 或 OnDrop

不能用 `actor.isLocal` 直接跳过整个回调。远端玩家拾取时，各端仍需要挂手、对齐、恢复父节点和物理；只有本地 UI 和角色自身动作才应限制为本地执行。

### 9. 只关闭刚体，不关闭实体碰撞体

持有期间若实体碰撞体仍启用，角色可能被挂到手上的物体持续顶开，出现抖动或顶飞。关闭物理时必须同时禁用非 Trigger 的实体碰撞体。

### 10. 只在 OnPickup 中关闭物理

发送 `Pickup` 到收到确认之间仍有一段时间。必须在请求前关闭物理，并在 `OnPickup` 中再次调用同一套可重复执行的关闭逻辑。

### 11. 让远端 Actor 发起 Pickup 或 Drop

只有本地 Actor 可以发送拾取和丢弃请求。远端 Actor 只能用于 `OnPickup` / `OnDrop` 回调中的挂手和表现处理。

### 12. 在 Pickup 前额外申请主权

平台的拾取流程已处理对象主权。额外申请会增加失败路径，也可能干扰正常拾取，不应作为普通拾取步骤。

### 13. 挂到手骨后不重新对齐位姿

只设置父节点会保留原来的世界位姿，物体不会正确贴合手掌。挂手后还要按掌心矩阵和握点矩阵更新位置与旋转。

### 14. 只检查右手是否已有物品

拾取前应检查双手。只检查右手会漏掉左手已持有物体的情况，进而错误地发送第二次拾取请求。

## 第八步：按场景验证

至少使用两个客户端进行以下验证。单客户端通过，不能证明远端挂手和晚进房恢复正确。

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 交互按钮 | 进入范围、离开范围、再次进入范围 | 进入后在 `OnFocus` 创建按钮；离开或失焦后在 `OnLostFocus` 移除按钮；再次进入后不会出现重复按钮。 |
| 基础拾取 | 本地玩家进入范围、点击拾取、再放下 | 入口随范围创建和清理；确认后再挂手；放下后恢复原父节点、刚体和碰撞体。 |
| 丢弃流程 | 本地持有物体后点击“丢弃” | 点击时不改变物体；`OnDrop` 确认后才恢复父节点、碰撞体和 UI。 |
| 脚下拾取 | 站在实体碰撞体上发起拾取 | 请求发出到确认期间，角色不被顶飞、不持续抖动。 |
| 远端观察 | 客户端 A 拾取，客户端 B 观察 | B 上物体挂在 A 的手骨并贴合掌心，不会残留在原地。 |
| 双手占用 | 本地左手或右手已有其它拾取物，尝试拾取 | 不发起第二次拾取请求。 |
| 非本物体持有 | 本地持有其它物体后接近当前物体 | 当前物体不会误显示“放下”或发起对当前物体的 Drop。 |
| 已被他人持有 | A 持有，B 靠近物体 | B 看不到“拾取”按钮，且不会发送拾取请求。 |
| 延迟销毁 | 放下后等待，再次在到期前拾取 | 到期前重新拾取会取消销毁；未重新拾取时仅由写权限方执行一次网络销毁。 |
| 晚进房 | A 已持有，B 再进入房间 | B 知道对象已被占用，并在 Actor 加载后将物体重建到 A 的正确手上。 |

## 第九步：交付前检查清单

- [ ] `Pickup` / `Drop` 仅由本地 Actor 发起。
- [ ] `OnFocus` 中创建范围按钮，`OnLostFocus` 中移除按钮并清空引用。
- [ ] Lua 使用 `OnInteractorButtonClick(index)`，C# 为返回的 `Button` 注册 `onClick`。
- [ ] 请求前已预关闭刚体物理和非 Trigger 实体碰撞体。
- [ ] `OnPickup` / `OnDrop` 未以 `isLocal` 整体过滤。
- [ ] `OnPickup` 在所有客户端动态查手骨、挂手并完成矩阵对齐。
- [ ] `OnDrop` 仅接受当前持有者的回调，并还原原始父节点。
- [ ] 按钮点击只发送 `Pickup` 或 `Drop` 请求，不直接挂手、恢复物理或修改持有者。
- [ ] 物理恢复了初始化的 `isKinematic` 和碰撞体状态。
- [ ] 持有本物体的判断使用 `currentHolder.isLocal`，未使用“手中有任意物品”替代。
- [ ] 前置“手中已有物品”检查覆盖双手。
- [ ] GripPoint 使用物体和握点的世界矩阵计算，未直接使用 GripPoint 的局部坐标。
- [ ] GripPoint、Animator、手骨和回调矩阵缺失时，拾取流程仍能继续。
- [ ] 需要晚进房或防重复拾取时，已同步持有者、手和重新挂手所需信息。
- [ ] 未在 `Pickup` 前额外申请主权。
- [ ] 已使用至少两个客户端完成“远端观察”和“晚进房”验证。
