# 触发交互最佳实践

本文说明如何用区域 Enter / Exit 生命周期实现触发交互，不依赖具体实现语言。适用于区域提示、陷阱、传送、高亮，以及进入范围后开启 C 区按钮的场景。


## 一、最小生命周期

当区域需要维护本地玩家或当前区域上下文时，保留以下流程：

```text
OnActorTriggerEnter(actor)
  → 过滤空 Actor 和非本地 Actor
  → 记录当前本地 Actor
  → 执行 Enter 扩展逻辑

OnActorTriggerExit(actor)
  → 过滤空 Actor 和非本地 Actor
  → 执行 Exit 扩展逻辑
  → 清理当前区域上下文
```

硬性要求：

1. `OnActorTriggerEnter` 和 `OnActorTriggerExit` 都必须先判断 Actor 是否为空，以及 `isLocal` 是否为真。
2. 进入逻辑只能写在 Enter，离开逻辑只能写在 Exit。
3. 区域状态只服务当前区域，并在离开时收口。
4. 离开区域不能直接等同于任务完成、拾取结束或其它无关业务完成。

## 二、C 区交互入口

仅当进入区域后需要玩家操作 C 区按钮时，使用以下生命周期：

```text
Enter
  → EnableInteraction()
  → OnFocus()
  → 创建 C 区按钮

点击按钮
  → 调用具体的交互、拾取、座位或玩法入口

Exit
  → DisableInteraction()
  → OnLostFocus()
  → 移除 C 区按钮
```

注意：

- `EnableInteraction()` 只是开启交互资格，不是区域触发效果本身。
- 按钮应在 `OnFocus()` 中创建，在 `OnLostFocus()` 中移除。
- 不要在初始化、Enter 或普通业务函数中直接创建范围按钮。
- 不要声明或覆盖 `EnableInteraction()`、`DisableInteraction()` 同名函数。
- 按钮点击只负责调用具体入口，不要提前修改业务状态。

## 三、区域状态、提示和高亮

只有业务需要时才记录区域状态，例如：

| 状态         | 用途               |
| ---------- | ---------------- |
| 当前本地 Actor | 当前区域提示或交互入口的使用者。 |
| 是否在区域内     | 控制提示、高亮或持续效果。    |
| 进入时间       | 需要停留时长或简单冷却时使用。  |
| 当前目标       | 记录提示或高亮对应的对象。    |

进入区域时设置状态并开启提示或高亮；离开区域时关闭提示或高亮并清理状态。不要用这些本地变量代表房间全局业务状态。

## 四、直接触发区域玩法

陷阱、传送、伤害区或区域效果可以直接使用 Enter / Exit，不要求调用 `EnableInteraction()`：

```text
Enter：
  过滤本地 Actor
  记录当前区域上下文
  执行进入效果

Exit：
  过滤本地 Actor
  执行离开或清理效果
  清理当前区域上下文
```

持续伤害、持续物理、输入监听、动画和网络同步由对应玩法模块处理；Trigger 只负责进入和离开的生命周期入口。

## 常见错误

### 1. 漏掉本地玩家 guard

`OnActorTriggerEnter(actor)` 或 `OnActorTriggerExit(actor)` 省略 `actor == nil or not actor.isLocal` 后，远端玩家也会进入本地提示、C 区入口或区域状态逻辑。

### 2. 把开启 C 区交互当作唯一用途

`EnableInteraction()` 只用于开启 C 区按钮流程。陷阱、传送、提示、高亮和区域统计应直接在 Enter / Exit 的区域扩展点实现，不要为这些场景额外创建交互按钮。

### 3. 在 Exit 中宣布无关业务完成

`OnActorTriggerExit(actor)` 可以清理当前区域的状态或关闭普通 C 区交互，不能因为玩家离开区域就直接完成任务、清空拾取持有者或结束其它对象的持续业务。

### 4. 以自定义 helper 替代平台交互开关

不要声明与 `EnableInteraction` / `DisableInteraction` 同名的函数，也不要用同名 wrapper 覆盖平台 API；这会绕过平台焦点状态机并导致按钮生命周期异常。

## 五、模块边界

- C 区按钮：使用 `OnFocus`、`OnLostFocus` 和按钮点击入口。
- 拾取：使用 `Pickup` / `Drop` 与 `OnPickup` / `OnDrop`，不要在 Enter 中直接挂手。
- 座位：使用 `SitDown` / `StandUp` 与座位进入、离开回调，是否保留交互通道遵循座位规则。
- 普通物理对象：使用 `OnTriggerEnter` / `OnTriggerExit`，不要把普通碰撞回调当作本地 Actor 回调。
- 玩家级触发：需要 Player 参数时使用 `OnPlayerTriggerEnter` / `OnPlayerTriggerExit`。

## 六、交付检查清单

- [ ] Enter / Exit 首先过滤空 Actor 和非本地 Actor。
- [ ] 进入和离开逻辑分别写在对应生命周期入口中。
- [ ] `EnableInteraction()` 仅在确实需要 C 区按钮时调用。
- [ ] 按钮在 `OnFocus` 创建，在 `OnLostFocus` 移除。
- [ ] 未自定义同名的 `EnableInteraction` / `DisableInteraction` 函数。
- [ ] 区域状态在 Exit 时正确清理。
- [ ] Exit 未完成无关业务。
- [ ] 拾取、座位、持续物理和网络同步未被 Trigger 回调替代。
