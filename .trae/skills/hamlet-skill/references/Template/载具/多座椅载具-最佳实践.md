# 多座椅载具最佳实践

本文规定驾驶座、炮手座、乘客座等多座椅载具的网络对象模型。实现前先阅读 [自定义座位-最佳实践.md](../基础交互/自定义座位-最佳实践.md)。

## 一、硬约束

- 一个座椅 NetworkObject 对应一个逻辑站位和一个 `CurrentPlayer`。
- 一个座椅被占用后，第二个 Actor 对该座椅的 `SitDown` 请求会被平台拒绝。
- `SeatAnchor` 只描述一个座椅对象的坐下位姿，不是座椅本身，也不能增加并发容量。
- `switchSeat=true` 只允许同一个 Actor 从座椅 A 切换到座椅 B；不能让两个 Actor 共享座椅 A。
- 多座椅车辆必须使用多个独立座椅 NetworkObject，并让每个 Actor 调用对应座椅对象的 `SitDown`。

## 二、对象拓扑

```text
VehicleRoot NetworkObject
├── SeatAnchor_Driver   ← 绑定 DriverSeat 对象
├── SeatAnchor_Gunner   ← 绑定 GunnerSeat 对象
├── DriverSeat NetworkObject + DriverSeatScript
└── GunnerSeat NetworkObject + GunnerSeatScript
```

上图表示对象归属，不限定创建方式。`DriverSeat` 和 `GunnerSeat` 必须是两个独立 NetworkObject，可以直接作为静态子对象配置在载具 Prefab 的对应 Anchor 下，也可以按 VehicleSystem 模式动态生成后再绑定 Anchor。无论采用哪种方式，两个座椅都不能合并成一个 NetworkObject。

`VehicleRoot` 负责载具 Rigidbody、物理主权、武器、输入桥接和载具级同步状态。每个座椅对象独立负责：

- 独立 Trigger；
- 独立 `OnFocus` / `OnLostFocus` 按钮；
- 独立 `SitDown` / `StandUp` 目标；
- 独立 `OnSeatEntered` / `OnSeatExited`；
- 可选的业务占用标记；
- 独立的 Actor 挂载、Hips 对齐、碰撞和离座清理。

禁止以下拓扑：

```text
VehicleRoot NetworkObject + 两个逻辑座位入口
```

然后让两个按钮都调用：

```lua
actor:SitDown(vehicleRoot.gameObject, true)
```

这两个请求仍然指向同一个逻辑座椅，不能产生两个乘员。

## 三、坐下调用

座椅脚本必须把当前座椅对象作为 `SitDown` 目标：

```lua
-- DriverSeat.lua
actor:SitDown(self.gameObject, true)

-- GunnerSeat.lua
actor:SitDown(self.gameObject, true)
```

```csharp
// DriverSeat / GunnerSeat 的独立座椅组件
actor.SitDown(gameObject, true);
```

`self.gameObject` / `gameObject` 必须是具体座椅 NetworkObject，不能是载具根对象、任意 Anchor 或可视模型子节点。

按钮点击只做前置检查和发起请求。不要在点击时提前挂载 Actor、改 Transform、关闭碰撞或写入“已占用”状态；这些动作只能在座椅确认回调中执行。若没有远端占用展示或晚进房重建需求，不要额外维护占用同步变量。

## 四、座椅生命周期

每个座椅对象都要独立完成以下闭环：

```text
静态座椅：Prefab 加载时已经位于对应 SeatAnchor
动态座椅：生成座椅 NetworkObject → 绑定到对应 SeatAnchor
  → 本地 Actor 进入座椅 Trigger
  → OnFocus 创建该座椅按钮
  → SitDown(当前座椅对象)
  → OnSeatEntered(全端)
  → Actor 挂载、Hips 对齐、碰撞关闭、按需更新业务状态
  → StandUp(当前座椅对象)
  → OnSeatExited(全端)
  → 停止对齐、解除挂载、恢复状态、清空按需业务状态
  → 静态座椅随载具网络对象销毁；动态座椅由创建方执行 NetDestroy
```

`OnSeatEntered` / `OnSeatExited` 不能只处理本地 Actor。远端客户端也必须将远端 Actor 挂到正确的座椅对象并持续对齐；只有按钮、输入和本地 UI 使用 `actor.isLocal`。

## 五、座椅占用与按钮状态

平台座椅的 `CurrentPlayer` 是座椅占用的权威状态：

- 一个座椅被占用后，第二个 Actor 的 `SitDown` 请求由平台拒绝；
- 业务侧不需要为了防重复坐下再增加 `occupantActorId`；
- “驾驶位(占用)”或“炮手位(占用)”不是必需 UI 状态，按钮可以始终显示普通座位文案；
- 只有需要远端展示、晚进房恢复或业务统计时，才在座椅对象上按需增加占用同步变量；
- 业务占用变量不能替代 `CurrentPlayer`，也不能决定平台是否允许坐下。

座椅按钮必须遵守以下生命周期：

1. `OnFocus` 创建当前座椅按钮；
2. 点击只调用 `SitDown` / `StandUp`；
3. `OnSeatEntered` 后更新“站起”状态；
4. `OnSeatExited` 后清理按钮和本地交互状态；
5. 如果业务需要让已坐下玩家离开 Trigger 后仍能站起，则仅在“仍坐着”阶段保留按钮，不能把该规则延伸到已经触发 `OnSeatExited` 的状态。

## 六、实现步骤

1. 为每个并发座位创建一个独立的 NetworkObject。
2. 为每个座位配置独立的座椅脚本、Trigger、SeatAnchor 和交互按钮。
3. 固定座位直接配置在载具 Prefab 中；运行时数量不固定时，使用网络生成接口创建座位。
4. 将每个座位绑定到对应的载具 Anchor，并在所有客户端保持相同的父子关系和局部位姿。
5. 等待载具和座位完成网络初始化。
6. 调用具体座位对象的 `SitDown`：

```lua
actor:SitDown(driverSeat.gameObject, true)
```

7. 在 `OnSeatEntered` 中完成 Actor 挂载、Hips 对齐和碰撞处理。
8. 在 `OnSeatExited` 中完成持续对齐停止、解除挂载、状态恢复和按钮清理。
9. 使用座位对象的 `CurrentPlayer` 处理单座位互斥。

## 七、SharedMode 主权

- 载具根对象主权负责载具物理和载具级同步变量。
- 若配置了座椅占用同步变量，只能由该座椅对象主权方写入。
- 非主权座椅脚本确实需要更新该变量时，通过 `SendMessageToOwner` 请求该座椅主权方代写；没有远端展示或晚进房需求时不应增加这条链路。
- 驾驶位如要求“驾驶者拥有载具主权和物理控制权”，应先直接调用具体驾驶座对象的 `SitDown`，等待 `OnSeatEntered` 确认落座后，再按 `isNetworkSettled → HasOwnership → HasControllership → RequestControllership` 申请载具根对象控制权。SharedMode 下控制权请求会同时取得主权；不能用根对象 `RequestOwnership` 代替控制权请求，也不能阻塞座位框架的落座请求。
- 炮手座不应因为坐下而抢走载具物理主权；炮塔输入通过座椅脚本向载具主权方转发。
- 驾驶员离座时，驾驶座脚本必须清零驾驶输入并调用载具根对象的 `ReleaseControllership()`；否则下一名玩家的控制权请求可能因旧 `ControllerActorNr` 未释放而被拒绝。
- `HasOwnership()` 只表示同步变量写权限，`HasControllership()` 才表示当前端是否拥有对象控制权；物理驾驶必须同时满足两者。
- `RequestControllership` 应在 `OnSeatEntered` 后延迟调用，避免与座位框架同帧控制权握手竞争。
- 控制权请求失败时不能解除 `Rigidbody.isKinematic`，也不能继续写入载具速度或旋转。

## 八、切换座椅

同一个 Actor 从炮手座切换到驾驶座时：

```lua
actor:SitDown(driverSeatGameObject, true)
```

平台会先让旧座椅收到 `OnSeatExited`，再让新座椅收到 `OnSeatEntered`。旧座椅必须先清理自身的挂载、碰撞、输入和按需业务状态。

若驾驶座已经被其他 Actor 占用，目标逻辑座椅的 `CurrentPlayer` 非空，切换请求失败，原炮手座状态必须保持不变。

## 九、常见误区

| 错误做法 | 正确做法 |
| --- | --- |
| 一个 NetworkObject 承载驾驶座和炮手座 | 创建两个独立座椅 NetworkObject，每个座椅配置一个 `SeatAnchor` |
| 两个按钮都调用根载具的 `SitDown` | 每个按钮调用对应座椅对象的 `SitDown` |
| 无展示/重建需求仍增加占用同步 | 优先使用平台 `CurrentPlayer`；只有确有远端展示或晚进房需求时才按座椅同步 |
| 在按钮点击时直接挂载 Actor | 等待对应座椅的 `OnSeatEntered` |
| 用 `switchSeat=true` 绕过已占用座椅 | `switchSeat=true` 只切换同一 Actor 到另一个空闲座椅 |
| 用 `RequestOwnership` 申请物理驾驶权限 | 入座确认后使用 `RequestControllership`，SharedMode 下它会联动获得主权 |
| 离座只清零输入，不释放控制权 | 离座清零输入后调用 `ReleaseControllership()` |
| `OnSeatExited` 后仍按 Trigger 状态重建按钮 | 离座后清理按钮；重新进入 Trigger 再创建 |
| 静态座椅只在某一端临时 `SetParent` | 直接在 Prefab 中配置父子层级；各端从场景网络对象恢复相同层级 |
| 动态座椅只在某一端调用 `SetParent` | 各客户端根据座椅状态和对应 Anchor 恢复绑定 |
| 销毁动态座椅时只销毁根对象 | 动态座椅由创建方执行 `NetDestroy`；静态座椅随载具对象生命周期清理 |

## 十、验收清单

- [ ] 每个并发座位都有独立 NetworkObject。
- [ ] 每个 `SitDown` 传入具体座椅对象，不传 VehicleRoot 或 Anchor。
- [ ] 一个座椅被占用后，第二个 Actor 无法进入该座椅。
- [ ] 两个不同座椅可以由两个不同 Actor 同时占用。
- [ ] 远端客户端能看到每个 Actor 位于对应座椅。
- [ ] `switchSeat=true` 只用于同一 Actor 在两个座椅对象之间切换。
- [ ] 没有把业务占用变量当作平台座椅占用的唯一依据。
- [ ] 驾驶物理同时检查 `HasOwnership()` 和 `HasControllership()`。
- [ ] 驾驶员离座后清零输入并调用 `ReleaseControllership()`。
- [ ] `OnSeatExited` 后按钮和交互状态已清理。
- [ ] 静态座椅随载具生命周期清理；动态座椅由创建方完成 `NetDestroy`，两种方式都完成输入 / 占用清理。
