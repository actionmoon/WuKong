# 商品与星光币管理

在虚拟世界中，商品与星光币的管理均由 `DouyinMarketingService` 接口提供支持。开发者可以通过这些接口实现商品列表展示、商品信息刷新、限购逻辑判断以及星光币余额的实时监听。

本篇为 Manual，讲解商品获取、分页、限购、星光币等**概念与能力边界**。完整的可执行实践代码请见 Best Practice：

- Lua 实现：[商品与星光币管理-Lua](../../../Best%20Practice/商业化/商品与星光币管理-Lua.md)
- C# 实现：[商品与星光币管理-CSharp](../../../Best%20Practice/商业化/商品与星光币管理-CSharp.md)

## 一、获取商品信息

商品信息获取分为**全量获取**与**分页获取**，应根据商品总数选择合适方式。

| 方式 | 接口 | 适用场景 |
| --- | --- | --- |
| 全量获取 | `GetProductInfos(callback)` | 商品数量不超过 50 个 |
| 分页获取 | `GetProductPage(pageSize, callback)` | 商品数量超过 50 个，避免请求超时 |

**关键说明：**

- 回调状态码 `0` 表示成功，非 `0` 表示失败。
- `GetProductInfos` 返回**全量**商品信息（含上架、下架、已删除）。UI 展示时需按业务过滤 `DouyinProductInfo.status`（如仅展示 `Online`）。
- 分页数据模型 `DouyinProductPage` 通过 `hasMore` 判断是否还有下一页，通过 `AdvanceToNextPage` 拉取下一页（结构详见 [数据结构参考](数据结构参考.md)）。
- **购买前置**：调用 `Purchase` 前**必须**先调用一次 `GetProductInfos()` 或 `GetProductInfo()` 获取并缓存商品信息，否则会出现购买失败/无法调起支付面板等异常。

## 二、刷新单个商品信息

当后台修改了商品配置，或用户完成一次限购商品购买后，可通过 `GetProductInfo(productId, callback)` 获取指定商品的最新基础信息。

> **说明**：平台还提供刷新单个商品**限购状态**的能力，可在监听到购买成功后用于同步界面限购展示。该接口的具体签名与用法以引擎实际开放版本为准，本手册不展开示例。

## 三、商品限购（概念说明）

系统支持多种商品限购类型（`DouyinProductLimitType`）：

1. **None（不限购）**：可随意重复购买。
2. **All（全局限购）**：针对单个用户设置累计购买上限。
3. **Daily（每日限购）**：针对单个用户设置每日购买上限，自然日 0 点重置。

> *注：部分高级限购功能可能属于一期未完全对外开放特性，实际以引擎版本为准。*

**自定义限购**：若需实现“每周限购”“特定等级限购”等平台未内置的规则，需开发者通过自定义数据存储（DataStore）方案，将用户购买历史、时间戳、等级等信息持久化，并在发起购买前执行自定义校验逻辑。

## 四、星光币管理

星光币是虚拟世界的主要交易货币，支持实时查询、余额监听与跳转充值。

| 能力 | 接口/属性 | 说明 |
| --- | --- | --- |
| 查询余额 | `StarLight`（静态属性） | 当前用户的星光币数量 |
| 监听变化 | `onStarLightChanged`（静态事件） | 余额变化时触发，用于实时刷新 UI |
| 跳转充值 | `OpenRechargePage()` | 余额不足时拉起官方充值面板 |

> **注意**：订阅 `onStarLightChanged` 后，务必在脚本 `OnDestroy` 时移除监听，避免悬挂回调。

## 五、测试与外显过滤

- **测试商品**：测试购买流程需真实扣除星光币，建议创建低价测试商品（如 1 星光币）。
- **外显过滤**：测试商品需通过商品 ID 列表（白名单机制）手动过滤，防止在正式环境外露给普通玩家。
