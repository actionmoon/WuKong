# 排行榜服务 (DouyinRankService)

`DouyinRankService` 提供了设置玩家排行榜数据的能力：向平台**托管排行榜**上报分数。榜单的排序规则、展示格式与重置周期均由平台后台控制台配置，开发者只负责上报数据，不需要（也无法）读回完整榜单列表。

## 核心 API

- `SetRankData(score, alias, callback)`：设置（上报）玩家的排行榜分数。

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `score` | 数值 | 是 | 用于排序，按 `score` 从大到小排序，`score` 越大排名越靠前；若分数相同，按写入时间从早到晚排序。当 `alias` 为空时，`score` 同时用于排序与榜单外露展示；当 `alias` 不为空时，`score` 仅用于排序，不用作外露展示。 |
| `alias` | 字符串 | 否 | 可以为空。为空时按上述 `score` 的排序与展示规则处理；不为空时作为榜单的外露展示值，而排序权重仍取 `score`。例如传入 `alias="黄金"`、`score=3` 与 `alias="白银"`、`score=2`，则“黄金”权重 3 高于“白银”，榜单上“黄金”展示在“白银”前面。 |
| `callback` | 回调 | 否 | 回调返回 `success`，即接口调用成功与否。 |

## 注意事项

- 排行榜的具体数据格式、排序规则及重置周期需要在平台后端控制台进行配置。
- 切勿在 `Update` 中高频调用。通常在对局结束、通关或分数发生质变时才进行上报。
- `alias` 的展示语义：为空时 `score` 兼作外显；不为空时 `alias` 作外显、`score` 只参与排序。需要展示“段位/称号”等非数值榜面时使用 `alias`。
- **与 OrderedDataStore 的边界**：`DouyinRankService` 是平台**托管**的官方排行榜——只上报、由平台负责排序/展示/重置，开发者不持有也不读回榜单数据；而 [数据存储OrderedDataStore](../数据库/数据存储OrderedDataStore.md) 是开发者**自建**的有序榜单——分数写入自己的 store，自行分页读回、自定义淘汰与重置。需要平台统一榜单时用前者，需要完全自控的榜单/分页明细时用后者。

## 选型：托管榜 vs 自建有序榜

`DouyinRankService` 与 [数据存储OrderedDataStore](../数据库/数据存储OrderedDataStore.md) 都能做榜单，按需求选择：

| 需求 | 用 `DouyinRankService`（托管） | 用 `OrderedDataStore`（自建） |
| --- | --- | --- |
| 平台统一展示的官方榜 | ✅ | — |
| 只需上报、不读回明细 | ✅ | — |
| 段位 / 称号外显（alias） | ✅ | 需自行编码 |
| 读回榜单、分页、TOP-N | — | ✅ |
| 自定义排序 / 淘汰 / 重置周期 | — | ✅ |
| 榜面数据完全自控 | — | ✅ |

需要平台统一榜单时用托管榜；需要读回明细、分页、自定义规则时用自建有序榜。

## 常见问题（FAQ）

| 错误现象 | 原因 | 修复 |
|---|---|---|
| 低分覆盖了高分 | 每次都无条件上报 | 只在 `score > 历史最优` 时上报（只升不降） |
| 榜单请求风暴 / 卡顿 | 在 `Update` 中调用 | 只在对局结束 / 分数质变时上报 |
| 重复上报 | 未拦截并发 | 用并发标志拦截一次未回调的重复触发 |
| 段位没有正确排序 | 只传了别名，未给分数权重 | 别名作外显 + 分数传排序权重 |
| 想读回榜单读不到 | 托管榜只上报、无读接口 | 改用自建有序榜 [OrderedDataStore](../数据库/数据存储OrderedDataStore.md) |
| 失败后一直重试 | 无重试上限 | 限制最大重试次数，超限提示 |
