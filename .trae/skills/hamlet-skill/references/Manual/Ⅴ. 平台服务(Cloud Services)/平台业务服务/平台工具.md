# 平台工具

`DouyinUtility` 是一个全局工具类，提供一组与具体业务无关的**通用平台方法**：轻量提示、原生确认弹窗、文本 emoji 过滤，以及基于服务器时间的可信时间获取。

本文档说明其能力概念、核心 API、关键约束与能力边界。完整的可执行案例（Toast / Alert 封装、emoji 过滤、服务器时间与可信时间判断）见 Best Practice。

---

## 一、核心 API 概览

| API | 说明 | 返回形态 |
| --- | --- | --- |
| `Toast(msg)` | 显示一条轻量、非阻塞的提示信息 | 无返回值 |
| `Alert(title, message, confirm, confirmCallback, cancel, cancelCallback)` | 弹出原生确认弹窗，两个按钮的点击结果分别通过确认 / 取消回调返回 | 无返回值（回调式） |
| `FilteEmoji(content)` | 过滤文本中的 emoji，返回过滤后的字符串 | 同步返回字符串 |
| `GetServerTime()` | 获取服务器时间，默认 UTC 0 时区 | 同步返回时间对象 |
| `GetServerUnixTime()` | 获取服务器 Unix 时间戳 | 同步返回整数 |

> `DouyinUtility` 目前**只有以上 5 个方法**，没有其它工具接口。其中 `Alert` 是回调式，其余 4 个均为同步返回。

---

## 二、能力说明

### 1. 轻量提示（Toast）

用于给玩家一条一闪而过的反馈信息，非阻塞、无按钮。它只是**反馈**，不是操作是否成功的判定依据，也不能替代需要玩家确认的弹窗。

### 2. 原生确认弹窗（Alert）

用于需要玩家二次确认的场景。它是**回调式**的：玩家的选择只通过确认回调、取消回调两个入口表达，**没有同步的布尔返回值**，因此确认后要执行的业务逻辑必须放在确认回调里。参数顺序固定为标题、正文、确认按钮文案、确认回调、取消按钮文案、取消回调，不可交换按钮文案与回调的位置。

### 3. emoji 过滤（FilteEmoji）

玩家昵称、输入框文本等在部分机型（尤其 iOS）上 emoji 容易显示为乱码。入库或展示前用它过滤，返回过滤后的干净字符串。

### 4. 服务器时间（GetServerTime / GetServerUnixTime）

用于签到、限时活动、冷却等**可信时间**判断。签到、限时活动、冷却等判断必须以服务器时间为准，客户端本地时间可被玩家篡改。`GetServerTime` 默认返回 UTC 0 时区，展示给玩家前需转换为本地时间；比较逻辑用 Unix 时间戳更方便。

---

## 三、硬约束与能力边界

- **`Alert` 是回调式、无同步返回**：不要把它当作能直接返回布尔值的同步方法；确认后的业务逻辑必须写在确认回调内，取消分支即使没有业务也应保留占位回调，保证参数顺序正确。
- **危险操作用 `Alert` 而非 `Toast`**：重置、消耗、购买、传送、放弃进度等不可逆操作要先经 `Alert` 确认；`Toast` 只是反馈，不构成确认。
- **网络时间接口调用前需判网络就绪**：`GetServerTime` / `GetServerUnixTime` 属网络相关能力，网络未就绪时可能异常或返回无效值，调用前应先判断网络状态已就绪，尤其在初始化阶段。
- **可信时间以服务器为准**：涉及作弊风险的时间判断（签到、限时、冷却）一律使用服务器时间，不使用客户端本地时间。
- **时区需转换**：`GetServerTime` 默认 UTC 0 时区，展示给玩家前需转换为本地时间。
- **提示不要每帧触发**：`Toast` / `Alert` 应由点击或一次性状态变化触发，不要在每帧更新逻辑中连续弹出。
