# 创作者服务
`DouyinCreatorService` 提供了一系列用于与抖音创作者生态交互的核心 API，主要包括：获取当前创作者信息、关注创作者、以及打开创作者主页。
本文档说明其能力概念、核心 API、关键字段与硬约束边界。完整的业务链路封装与可执行案例（Helper、按钮接入、错误处理）见 Best Practice。

---


## 一、核心 API 概览
| API | 说明 | 是否异步 |
| --- | --- | --- |
| `GetCreatorInfo(callback)` | 获取当前场景的创作者信息（`CreatorInfo`） | 是 |
| `Follow(secUid, callback)` | 根据 `secUID` 关注对应的创作者 | 是 |
| `OpenCreatorInformation(secUid)` | 打开对应创作者的主页面板 | 否（纯动作） |

**`CreatorInfo` 关键字段说明**：

- `secUID` (string): 创作者唯一标识，用于关注与跳转的入参。
- `name` / `portrait` (string): 创作者的昵称和头像 URL。
- `numberOfFans` (int): 创作者的粉丝数。
- `isFollowing` (bool): **当前用户是否已关注该创作者**。
- `isFollowed` (bool): 创作者是否关注了当前用户（防混淆：请勿与 `isFollowing` 搞混）。
- `fans` (string): 创作者粉丝指数。


---


## 二、硬约束与能力边界

- **必须动态获取** **`secUID`**：调用 `Follow` 之前必须通过 `GetCreatorInfo` 获得 `secUID`，**严禁硬编码** **`secUID`**。在调试器模式下可能返回空，请做好容错处理。
- **区分关注方向**：使用 `creatorInfo.isFollowing` 判断“用户是否已关注”，切忌使用 `isFollowed`。
- **拦截并发与轮询**：
   - 不要把获取操作放到 `Update` / `FixedUpdate` 等帧回调中轮询。
   - 玩家频繁点击时，应用 `pending` 状态阻止并发发起多个 `Follow` 或 `GetCreatorInfo` 请求。
- **无需等待跳转主页**：`OpenCreatorInformation` 没有返回值和 Callback，切勿编写等待逻辑。
- **身份隔离**：创作者身份不是当前用户身份。不要把玩家的 `openID` 传给 `Follow` 方法。

## 四、常见问题（FAQ）

| 问题现象 | 原因 | 解决 |
| --- | --- | --- |
| 关注按钮点击后无反应 / 崩溃 | 传入的 `secUID` 为空 | 先 `GetCreatorInfo` 拿到 `secUID`，判空后再调用 `Follow` / `OpenCreatorInformation` |
| 复用资源后关注错人 | 硬编码了 `secUID` | 始终使用当前运行时的 `CreatorInfo.secUID`，不要缓存跨场景的旧值 |
| 已关注玩家仍重复触发关注 | 忽略了 `isFollowing` | 已关注时直接视为成功（或改为打开主页），不重复调用 `Follow` |
| 打开主页后一直等回调 | `OpenCreatorInformation` 无回调、无返回值 | 它是纯动作，不要编写等待逻辑 |
| 关注对象错误 | 把玩家 `openID` 当作 `secUID` 传入 | 创作者身份 ≠ 玩家身份，只传 `CreatorInfo.secUID` |
| 调试器里获取不到信息 | 调试器模式下 `GetCreatorInfo` 可能返回空 | 判空并提示“当前无法获取创作者信息”，不继续后续调用 |
