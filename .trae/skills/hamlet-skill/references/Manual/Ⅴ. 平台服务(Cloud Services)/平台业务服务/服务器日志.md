# 服务器日志

`DouyinLogService` 是一个全局静态类，提供**结构化日志上报能力**：在 DS（DedicatedServer）服务端把分级日志上报到平台后台，供开发者在**创作后台的「服务器日志看板」**排查线上问题。

本文档说明其能力概念、日志级别语义、查询入口与硬约束边界。完整的可执行案例（带上下文的结构化日志封装、频控自保护、问题定位场景）见 Best Practice。

---

## 一、核心 API 概览

`DouyinLogService` 提供 5 个分级方法，签名统一为 `(string message)`：

| API | 级别语义 | 是否上报后台 |
| --- | --- | --- |
| `Debug(message)` | 开发调试用，辅助定位问题 | **否**（仅本地，不上报） |
| `Log(message)` | 通用日志：常规运行信息、简单流程节点、基础状态 | 是 |
| `Info(message)` | 信息日志：关键流程、状态变化、重要事件 | 是 |
| `Warning(message)` | 警告日志：需关注的异常或潜在风险，通常不中断流程 | 是 |
| `Error(message)` | 错误日志：功能异常或关键流程失败，需尽快处理 | 是 |

> **`Debug` 与其余级别的关键差异**：`Debug` 只用于开发阶段本地定位，**不会上报后台看板**；需要在线上看板追查的日志请用 `Log` / `Info` / `Warning` / `Error`。

---

## 二、查询入口：创作后台服务器日志看板

上报的日志在**创作后台「服务器日志看板」**查询：

- **路径**：创作平台 → 创作中心 → 世界板块 → 具体世界详情页 → 服务器日志。
- **查询方式**：指定查询**时间段**，输入用户**抖音号**与对应**世界版本**进行检索、下载。
- **仅限 DS 开发模式世界**：看板目前仅支持 DS 开发模式世界查询。
- **常见查询失败**：所选时间段无日志（提示无权限 / 记录不存在）或进房时间缺失时，扩大搜索时间范围重试。

> 正因为日志要靠「时间段 + 抖音号 + 世界版本」检索，日志内容应带上足够的**业务上下文**（如玩家 OpenID、房间 ID、模块标签），否则难以定位到具体玩家与流程。

---

## 三、硬约束与能力边界

- **仅 DS 环境生效**：日志只能在 DS 服务端上报；在客户端（本地玩家端）调用**不会生效**。
- **单条长度上限 8KB**：超长内容会被截断，避免把大对象整体序列化后打印。
- **频控限制**：单个房间内，**每帧最多 20 条、每秒最多 200 条**。超出会导致日志截断甚至性能问题。
- **严禁在 `Update` 中疯狂打印**：高频帧回调里打印极易触发频控；应聚合或降频。
- **敏感信息红线**：不得打印 Token、密钥、支付凭据、手机号等敏感 / 隐私信息。
- **分级要规范**：按语义选级别，不要所有日志都用 `Error`，否则看板噪声大、无法分级排查。

## 四、常见问题（FAQ）

| 错误现象 | 原因 | 修复 |
|---|---|---|
| 看板查不到日志 | 在客户端打的上报级日志 | 上报级日志（`Log`/`Info`/`Warning`/`Error`）放 DS 服务端，客户端调用不生效 |
| 日志被截断 | 单条超 8KB / 触发频控 | 精简内容（只打关键字段）+ 限流聚合 |
| 无法定位到具体玩家 | 日志没带上下文 | 统一拼 `[模块] key=value`（`openID` / `roomID` / `orderId` 等） |
| 看板全是红色噪声 | 什么都用 `Error` | 按语义分级：常规 `Log`/`Info`、可疑 `Warning`、失败 `Error` |
| 刷屏卡顿 | 在 `Update` 逐帧打印 | 降频 / 每秒聚合 |
| 泄露隐私 | 打印了 Token / 密钥 / 手机号 | 遵守敏感信息红线，绝不打印 |
| 找不到异步版本 / 带标签重载 / 设置级别 / 单例入口 | 平台无这些接口 | 只用 5 个单参方法，上下文自行拼进 message、限流自行实现 |
