# 奖励服务

`DouyinOfficialRewardService` 是一个全局静态类，用于下发**「官方合养精灵形象」「装扮」**等高优平台奖励。常配合「关注创作者」等世界内行为，做「完成条件 → 领取官方奖励」的激励闭环。

本文档说明其能力概念、返回结构、错误码与硬约束边界。完整的可执行案例（发奖封装、防重复领取、关注领奖组合链路、可信校验）见 Best Practice。

---

## 一、核心 API

- `IssueReward(rewardID, callback)`：下发指定奖励。`rewardID` 为奖励的唯一标识；`callback` 回调返回下述 `IssueRewardResponse` 结构。

### 返回结构 `IssueRewardResponse`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | int | `0` 为发放成功，其他为失败 |
| `message` | string | 发放失败的原因 |
| `rewardInfo` | list | 奖励具体信息列表，每项含以下字段 |
| ┗ `id` | long | 形象 / 装扮 ID |
| ┗ `name` | string | 奖励名 |
| ┗ `imageUrl` | string | 缩略图 URL |
| ┗ `rewardType` | int | 奖励类型：`2` 形象，`3` 装扮 |

### 错误码

| 错误码 | 含义 |
| --- | --- |
| `10001` | 内部参数错误（奖励 ID 不存在 / 世界不一致 / 奖励物品不存在），联系运营排查 |
| `10002` | 鉴权失败 |
| `20801` | 当前装扮 / 非 UGC 形象已存在（玩家已拥有） |
| `20802` | 奖励配置错误 / 奖励 ID 无效 |
| `20803` | 当前形象奖励数量领取到达上限 |

---

## 二、`rewardID` 说明

- `rewardID` 是标识**当前奖励**的唯一 ID，**不是**创作后台形象的唯一 ID，也**不是**合养精灵形象兑换组件上填写的「合养精灵 ID」。
- 获取方式需**联系官方运营**（飞书答疑群）。
- 该接口可发放非世界作者本人账号的形象 / 装扮，具体情况需联系运营。

---

## 三、关注领奖（组合场景）

奖励服务常与创作者关注组合成激励闭环：

1. 通过 `DouyinCreatorService.GetCreatorInfo` 获取创作者信息，读 `isFollowing` 判断是否已关注。
2. 未关注时调用 `DouyinCreatorService.Follow(secUID, callback)` 发起关注。
3. 关注成功后调用 `IssueReward` 下发奖励，并将**发放结果落库**，防止重复领取。

关注相关接口详见 [创作者服务](创作者服务.md)。

## 四、硬约束与能力边界

- **仅线上环境有效**：`IssueReward` 仅支持线上环境调用，本地客户端 / 模拟器测试不生效；应通过 `DouyinApplication.isSimulator` 拦截调试器环境。
- **作者本人 / 合养精灵无法领取**：通过该接口或兑换组件获取精灵形象时，世界作者本人账号、与世界作者合养的精灵**均无法获取**。
- **形象上架审核中拉不到**：若合养精灵形象已提交上架商店审核，在审核通过前，组件 / 接口**无法拉取到该形象数据**。
- **已拥有 / 达上限属正常业务分支**：`20801`（已拥有）、`20803`（达上限）不是程序错误，应向玩家友好提示，不当作失败重试。
- **发放要防重复**：领取资格应在 DS 服务端校验，发放结果落库；避免同一玩家对同一奖励重复领取。
