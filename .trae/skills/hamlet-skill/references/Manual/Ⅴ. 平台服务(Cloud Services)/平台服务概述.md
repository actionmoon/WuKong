# 平台服务概述
平台服务（Platform Services）是一组由底层框架或宿主应用（如客户端、服务端、调试器）直接提供的核心能力接口。与基于游戏对象的生命周期不同，平台服务通常以**全局静态方法或单例**的形式调用，为开发者提供独立于场景的通用功能。
本文档汇总了平台服务的分类、核心职责以及详细手册的导航链接。
## 一、平台服务分类矩阵
在当前的五层架构中，平台服务主要分为以下几个大类，专注于云端与系统业务能力：

| 服务分类 | 核心服务类 | 主要职责与能力 | 详细文档导航 |
| --- | --- | --- | --- |
| **数据库** | `DouyinDataStore` <br> `DouyinOrderedDataStore` | 在云端持久化存储游戏数据，支持数值类型的排序存储（排行榜）与通用键值对存储，业务可在其上自建数据访问层。 | [数据库概述](./数据库/数据库概述.md) |
| **商业化** | `DouyinMarketingService` | 创作者内容变现解决方案，涵盖虚拟商品创建、星光币支付、以及安全的服务端发货闭环。 | [商业化概述](./商业化/商业化概述.md) |
| **创作者与社交** | `DouyinCreatorService` | 围绕抖音创作者生态，提供获取作者信息、关注操作以及跳转主页的能力。 | [创作者服务](./平台业务服务/创作者服务.md) |
| **房间与环境** | `DouyinRoomService` | 管理当前运行的房间元信息，如房间 ID、世界 ID 以及玩家的渠道来源（逛一逛/侧边栏等）。 | [房间服务](./平台业务服务/房间服务.md) |
| **平台业务体系** | `DouyinOfficialRewardService` <br> `DouyinRankService` | 负责与平台业务后台的交互，例如发放官方形象/装扮奖励、上报排行榜分数。 | [奖励服务](./平台业务服务/奖励服务.md) <br> [排行榜服务](./平台业务服务/排行榜服务.md) |
| **系统与运维** | `DouyinLogService` | 提供 DS 端的结构化日志上报收集机制，帮助在云端排查线上问题。 | [服务器日志](./平台业务服务/服务器日志.md) |
| **网络资源** | `DouyinImageService` | 提供运行时从网络加载和下载图片的便捷接口。 | [图片服务](./平台业务服务/图片服务.md) |

*(注：通用工具、应用程序生命周期、相机与输入服务等底层基石接口，已划分至 [核心系统%28Core%29](../Ⅰ.%20核心系统%28Core%29/) 模块。)*

## 二、使用原则与硬约束
在接入和使用平台服务时，请务必遵循以下通用规则：

1. **按需异步处理**：大部分涉及到与后端交互的平台服务（如获取创作者信息、发起关注、发放奖励）均是异步操作，必须通过回调（Callback）接收结果，切勿假设为同步返回值阻塞主线程。
2. **环境隔离**：
   * 某些接口仅限 **DS 服务端** 调用（如 `DouyinLogService` 及其级别输出，`DouyinOfficialRewardService` 的发奖接口）。
   * 某些状态仅限 **客户端环境** 生效。
   * 调用前应善用 `DouyinApplication.isServer` / `isSimulator` 进行环境检测与逻辑隔离。
3. **频率限制**：严禁在 `Update` / `FixedUpdate` 等帧循环中频繁调用网络相关的平台服务（如 `GetCreatorInfo`、`SetRankData` 或 `DouyinLogService.Log`）。高频调用将导致节流截断或引发严重的性能问题，相关逻辑应当由状态变更事件或显式点击触发。
