# 精灵维度数据存储方式

在虚拟世界中，当存在合养精灵等机制时，不同玩家可能共享同一个小火人实体。针对绑定在精灵（Pet）实体上的数据（如等级、属性、经验、专属外观等），推荐在原生 `DouyinDataStore` 之上自行封装一层**精灵维度数据访问层**，对读写做隔离管理。

> **说明**：平台**不提供**名为 `DouyinPetDataStore` 的开箱即用模块，本篇中出现的 `PetDataStore` 是一个**业务自定义封装示例**（并非平台 API），用于演示如何组织精灵维度的数据访问层。其内部实际调用的仍是原生 DataStore 的 `GetDataStore` 与 store 的 `GetData` / `SetData` / `IncrementData` / `UpdateData` / `RemoveData` 接口，参见 [数据存储DataStore](../数据存储DataStore.md)。

该封装层的核心思路：将 `petOpenID` 拼接为原生 DataStore 的作用域（`Scope`，如以 `pet_` 为前缀加上 openID）。这种设计能够确保数据紧跟精灵本体，而不会因为合养玩家账号的切换或离线而丢失。

## 1. 核心特性

- **自动身份绑定**：接口直接传入 `pet` 对象，封装层内部解析并校验 `pet.petOpenID` 并拼成 `Scope`。
- **本地缓存机制**：可在封装层内维护内存缓存（如按 `petOpenID` 建表），命中缓存时直接返回，避免频繁发起网络请求；数据变更时同步更新缓存。
- **JSON 序列化**：对于复杂的数据结构（如 Table / 对象），封装层内部调用平台内置的 JSON 库进行序列化与反序列化（原生 DataStore 的 value 仅支持数字/字符串/布尔及其组成的表，表需序列化为字符串存入）。

## 2. 封装层接口设计示例

下面以业务自定义模块 `PetDataStore`（**非平台 API**）为例，演示精灵维度数据访问层应暴露哪些接口，以及每个接口内部对应的原生 `DouyinDataStore` 调用。完整可运行实现见 Best Practice：[数据存储DataStore-Lua](../../../../Best%20Practice/数据库/数据存储DataStore-Lua.md)（其 §8.2「小火人级数据」即以 `pet_ + openID` 作 Scope 的样例）。

### 2.1 获取数据 (GetData)

获取指定精灵的存储数据。若封装层开启了内存缓存且存在对应缓存值，可直接回调返回；否则内部以 `pet_` 前缀加 `petOpenID` 作为 Scope 获取对应 store，再调用其 `GetData(dataKey)` 读取。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `pet` | DouyinPet | 精灵对象，封装层内部解析其 `petOpenID` 拼成 Scope |
| `storeName` | string | 存储空间的名称（gameName） |
| `dataKey` | string | 数据字段键名 |
| `callback` | 回调 | 回调返回 `success, message, data` 三项：是否成功、提示信息、数据 |

### 2.2 设置数据 (SetData)

覆盖指定精灵的数据，并在开启缓存时同步更新本地缓存。内部对应 store 的 `SetData(dataKey, data)`（Table / 对象需先序列化为 JSON 字符串）。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `pet` | DouyinPet | 精灵对象 |
| `storeName` | string | 存储空间的名称 |
| `dataKey` | string | 数据字段键名 |
| `data` | any | 要保存的数据（Table 需序列化为 JSON 字符串） |
| `callback` | 回调 | 回调返回 `success, message, data` 三项：是否成功、提示信息、数据 |

### 2.3 增量更新 (IncrementData)

针对数值型字段进行原子的增减操作。内部对应 store 的 `IncrementData(dataKey, delta)`（`delta` 为数字，被自增的 key 须以数值类型写入）。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `pet` | DouyinPet | 精灵对象 |
| `storeName` | string | 存储空间的名称 |
| `dataKey` | string | 数据字段键名 |
| `value` | number | 增量值 |
| `callback` | 回调 | 回调返回 `success, message, data` 三项：是否成功、提示信息、数据 |

### 2.4 函数式更新 (UpdateData)

传入自定义处理函数对精灵数据进行更新，适用于存在竞态条件或需要基于当前值计算新值的场景。内部对应 store 的 `UpdateData(dataKey, func)`（平台先读出当前值交给 `func` 计算，再写回）。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `pet` | DouyinPet | 精灵对象 |
| `storeName` | string | 存储空间的名称 |
| `dataKey` | string | 数据字段键名 |
| `func` | 处理函数 | 接收当前值，返回计算后的新值 |
| `callback` | 回调 | 回调返回 `success, message, data` 三项：是否成功、提示信息、数据 |

### 2.5 移除数据 (RemoveData)

删除指定数据键的值，并清理本地缓存。内部对应 store 的 `RemoveData(dataKey)`。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `pet` | DouyinPet | 精灵对象 |
| `storeName` | string | 存储空间的名称 |
| `dataKey` | string | 数据字段键名 |
| `callback` | 回调 | 回调返回 `success, message, data` 三项：是否成功、提示信息、数据 |

## 3. 使用注意事项

1. **有效性校验**：封装层应通过 `DouyinPetService.GetPet(pet.petID)` 验证目标精灵当前是否在线，若无效或离线，操作将直接返回失败。
2. **加载时机**：通常建议在 `OnActorSpawn` 事件中获取网络对象的 `douyinPet` 组件，并在此时预加载对应的精灵数据。
3. **DS 模式限制**：若采用 Dedicated Server 模式开发，与玩家数据一样，精灵数据的读写逻辑必须置于服务端执行，客户端无权直接调用（否则触发 `-11002`）。
