# 数据库概述

抖音虚拟世界提供了一套完整的数据存储系统（DataStore），用于在云端持久化存储游戏数据。平台主要提供两种**原生存储结构**：`DouyinDataStore`（通用键值对）和 `DouyinOrderedDataStore`（有序数值/排行榜）。在此之上，业务可根据自身需要自行封装一层数据访问层，把重复的异步块、JSON 编解码、容错逻辑收敛起来（详见 §3，属业务自定义封装，非平台提供）。

## 1. 核心概念

在使用 DataStore 之前，需要理解三个核心键值概念，它们组合起来唯一标识一条数据：

* **Name（游戏名称/storeName）**：用于标识不同的游戏或应用业务模块（例如："backpack"、"sim_game"）。
* **Scope（作用域/scopeName）**：用于区分数据的作用范围。为了规避单键容量限制，系统推荐以 `playerOpenID` 或 `petOpenID` 作为隔离作用域。
* **Key（键/dataKey）**：数据字段名，用于标识具体的数据字段（例如："coin"、"items"）。最大长度 128 字符。

> **数据类型**：`DouyinDataStore` 的 value 支持数字、字符串、布尔值，或仅包含这些类型的表（表需序列化为 JSON 字符串后存入）；`DouyinOrderedDataStore` 的 value **仅支持数值类型**。

## 2. 底层存储实体类对比

| 特性 | DouyinDataStore | DouyinOrderedDataStore |
| --- | --- | --- |
| **用途** | 通用键值对数据存储 | 数值类型的排序数据存储（如排行榜） |
| **支持类型** | 字符串（配合 JSON 序列化存储 Lua Table） | 仅支持数值类型 |
| **元数据与版本** | 支持 | 不支持 |
| **排序与分页** | 不支持 | 支持（GetSortedData 分页拉取） |
| **单 Store 键数量上限** | 约 1000 个（`-11005`） | 约 5000 个（`-11007`） |

## 3. 进阶：自建数据访问层（业务封装，非平台提供）

由于直接使用原生 `DouyinDataStore` 存在较多繁琐的规范要求（如 Lua 侧必须包裹在 `DATASTORE` 异步块内、需自行处理 `-10001` 新号报错、需手动序列化 JSON），实际项目中通常会自行封装一层数据访问层，把这些重复逻辑收敛起来。以下模块均为**业务自定义封装示例（并非平台 API）**，其内部实际调用的仍是原生 `DouyinDataService.GetDataStore(name, scope, all_scope)` 与 `store:GetData/SetData/IncrementData/UpdateData/RemoveData`：

1. **用户维度封装**：以 `playerOpenID` 拼接为 `Scope`（如 `"player_" .. playerOpenID`），隔离每个玩家的数据。示例见 [用户维度数据存储方式](数据存储方式/用户维度数据存储方式.md)。
2. **精灵维度封装**：以 `petOpenID` 拼接为 `Scope`（如 `"pet_" .. petOpenID`），隔离每个小火人的数据。示例见 [精灵维度数据存储方式](数据存储方式/精灵维度数据存储方式.md)。

## 4. 容量、频控与限制

* **Value 大小限制**：单个 value 最大长度约为 6000 字符（JSON 序列化后）。超过会返回错误码 `-10013`。
* **Key 数量限制**：单个 `DouyinDataStore` 最大 key 数量约为 1000 个（超过返回 `-11005`）；`DouyinOrderedDataStore` 约为 5000 个（超过返回 `-11007`）。建议采用上述“用户维度”或“精灵维度”拆分方式分散存储。
* **总容量限制**：每个世界的数据存储总容量上限通常约为 100M，触达上限返回错误码 `-11004`。
* **QPS / 频控**：云端数据库有读写频控，不建议高频实时写入。单个世界每分钟数据存储 API（所有读写接口累计）默认上限 900 次、峰值上限 1800 次，超出返回 `-11001`。建议玩家进入时读取一次并缓存到内存，离线或定期统一落库。

> 完整的错误码全表与各限制的详细说明，见 [数据存储DouyinDataStore](数据存储DataStore.md) §4 能力边界与限制、§5 错误码参考。

## 5. DS (Dedicated Server) 开发模式下的特别限制

* **强制服务器调用**：对于使用 DS 开发的新世界，数据存储必须且只能在 DS 服务器脚本上执行。
* **错误码 `-11002`**：若在客户端脚本上调用任何数据存储相关的 API，将会直接上报 `-11002` 错误码。所有数据存储业务逻辑需通过 `DouyinRemoteEvent` 或 `DouyinRemoteFunction` 通知服务器处理。
