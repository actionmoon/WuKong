# 刚体与运动模型

本文档介绍 `UnityEngine.Rigidbody` 的核心概念、运动模型选型以及参数设置逻辑。
`Rigidbody` 是平台物理系统里最核心的组件：它决定了物体是否受重力驱动、是否可被外力推动、是否有质量参与碰撞反馈。

---

## 一、 运动模型选型：被动受力 vs 主动驱动

物体的运动来源大致分两类。**选定一种模型就不要与另一种混写**，两种模型的 `drag` / `mass` 语义完全不同，混用会导致物体运动失控。

### 1. 被动接受力（一次性 AddForce）
- **使用场景**：玩家碰一下就滚走的球、推箱、冰球、滚筒、弹球。
- **运动来源**：在**单一实体碰撞入口**（默认 `OnActorCollisionEnter`）里调用 `AddForce(force, ForceMode.Impulse)` 一次性施加冲量。力的方向通常按玩家与物体的相对位置计算。
- **物理拓扑要求**：至少需要一个 `isTrigger=false` 的实体 Collider 提供物理接触面。
- **注意**：
  - 不需要套用主权门禁（`HasOwnership`）。本地物理不需要主权，否则单机或网络未同步时物体会“踢不动”。
  - 接触施力需配置短冷却（如 `0.1s`），避免同一次物理接触连续触发。

### 2. 主动驱动（持续写入 velocity / MoveRotation）
- **使用场景**：追踪玩家的敌人 NPC、遥控无人机、追踪导弹。
- **运动来源**：在 `FixedUpdate` 里根据业务状态和输入计算目标 `velocity` 并写回；旋转使用 `rb:MoveRotation(...)`。
- **物理拓扑要求**：视是否需要碰撞阻挡，通常配置实体 Collider。
- **注意**：
  - 必须在 `FixedUpdate` 中进行。
  - 不要与 `AddForce` 混写。

### 3. 运动学平台（MovePosition）
- **使用场景**：剧情驱动的机关升降台、传送带、载人移动平台。
- **运动来源**：配置 `isKinematic = true`。在 `FixedUpdate` 中使用 `rb:MovePosition(...)` 与 `rb:MoveRotation(...)`。
- **注意**：
  - 开启 `isKinematic` 后，刚体不接受任何外力（包括重力和玩家推力）。
  - 若要让玩家能够平稳地站在上面被带走，必须配合 Layer `Default(0)` 命中踩地检测。

## 二、 参数异常诊断与排查指南

在开发过程中，如果刚体表现不符合预期，请对照下表排查：

| 异常现象 | 优先排查点 | 避坑警告（不要这么做） |
| :--- | :--- | :--- |
| **动态物体掉入地下** | 1. 检查是否存在 `isTrigger=false` 的实体 Collider<br>2. 检查地面 Layer 与碰撞矩阵<br>3. 检查初始位置是否与地面严重重叠 | 不要只把 `mass` 调大或直接关闭重力。 |
| **物体完全不动** | 1. 是否误设了 `isKinematic=true`<br>2. 脚本是否未挂载或未进入 `FixedUpdate` 驱动逻辑 | 不要同时使用 `velocity` 和 `AddForce` 尝试“强行推走”。 |
| **物体一直漂浮在空中** | 1. 是否关闭了 `useGravity` 且未主动控制高度<br>2. 是否只有 Trigger 没有实体 Collider | 不要用极大的 `drag` 代替重力和实体 Collider。 |
| **物体被玩家轻易推飞** | 1. 检查 `mass` 和 `drag` 量级是否过小<br>2. 是否未配置 `Props(6)` Layer 防带飞 | 不要直接关闭实体 Collider 导致无法交互。 |
| **玩家无法靠近交互** | 1. 是否缺少 `isTrigger=true` 的 Interaction Trigger<br>2. 脚本是否与 Trigger 同节点 | 不要指望仅靠实体 Collider 就能自动提供交互按钮。 |
