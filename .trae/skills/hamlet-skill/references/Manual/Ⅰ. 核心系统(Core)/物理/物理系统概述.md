# 物理系统概述

本文档介绍平台底层的物理系统（基于 Unity PhysX）的核心概念与能力支持情况。
物理系统的设计严格遵循 **“场景驱动选型”** 与 **“动静属性分离”** 原则。

---

## 一、 核心使用场景与组件选型

在为对象添加物理组件前，必须明确其在游戏中的业务场景与运动来源。请根据下表确定所需的核心组件组合：

### 1. 静态与环境对象
- **纯视觉 / 静态装饰**
  - **组件选型**：无物理组件。
  - **避坑**：不要为不需要物理碰撞的装饰物添加 Collider。
- **静态地面 / 墙体 / 障碍物**
  - **组件选型**：`Collider`（`isTrigger = false`）。
  - **避坑**：仅提供阻挡与物理支撑，不负责产生主动交互事件。
- **静态可交互对象（如：开关、拾取物）**
  - **组件选型**：`Collider`（`isTrigger = true`）+ 交互脚本同节点。
  - **避坑**：Trigger 仅提供靠近检测与范围信号，不提供实体阻挡。

### 2. 动态与受力对象
- **被动受力对象（如：可踢的球、可推的箱子）**
  - **组件选型**：`Rigidbody`（`isKinematic = false`）+ 实体 `Collider`。
  - **行为**：通过 `AddForce` 或物理碰撞产生反馈。
  - **避坑**：不要在脚本中每帧锁定或修改其 `velocity`，应由物理引擎接管。
- **主动驱动动态对象（如：追踪导弹、寻路 NPC）**
  - **组件选型**：`Rigidbody`（`isKinematic = false`）+ 实体 `Collider`。
  - **行为**：在 `FixedUpdate` 中主动写入 `velocity` 或调用 `AddForce`。
  - **避坑**：不要同时使用 `velocity` 和 `AddForce` 驱动同一对象。
- **运动学驱动对象（如：移动平台、传送带）**
  - **组件选型**：`Rigidbody`（`isKinematic = true`）+ 实体 `Collider`。
  - **行为**：通过 `MovePosition` / `MoveRotation` 驱动。
  - **避坑**：不要对其使用 `AddForce`，物理引擎不会响应。

## 二、 物理能力支持矩阵

平台对 Unity 原生物理特性的支持情况如下：

- **✅ 完全支持**
  - **Rigidbody**：直接读写常规属性（`mass`, `drag`, `useGravity`, `isKinematic` 等）。
  - **Collider**：支持 Box、Sphere、Mesh 等常用形状及 `isTrigger` 切换。
  - **Trigger 与碰撞回调**：`OnActorTriggerEnter/Exit`（针对玩家）、`OnTriggerEnter`、`OnCollisionEnter`。
  - **射线与范围检测**：`Physics.Raycast`、`Physics.OverlapSphere` 等。
  - **物理材质**：通过 `sharedMaterial` 设置弹力（`bounciness`）与摩擦力（`friction`）。
  - **点对点碰撞忽略**：`Physics.IgnoreCollision` 忽略特定 Collider 之间的碰撞。

- **⚠️ 限制与警告**
  - **Layer 与碰撞矩阵**：资源配置阶段的 `layer` 静态字段仅支持 `0` (Default) 和 `9` (自定义)；其它层级（如 `6` Props）必须在运行期通过脚本递归 `SetLayer`。
  - **全局碰撞过滤**：`Physics.IgnoreLayerCollision` 会产生全局副作用，容易误伤，仅在明确规划下使用。

- **❌ 不支持或不建议**
  - **Character Controller**：玩家角色移动由平台接管，业务侧不要挂载该组件。
  - **直接修改 Transform**：对于带有 Rigidbody 的对象，严禁直接修改 `transform.position/rotation`，必须通过刚体 API 驱动。

## 三、 核心分层：静态属性 vs 运行期驱动

为了保证物理表现的一致性与可调性，物理参数分为**静态属性**与**运行期状态**，两者边界明确：

### 1. 静态物理属性（资源配置层）
- **内容**：刚体质量（`mass`）、阻尼（`drag`/`angularDrag`）、初始状态（`useGravity`/`isKinematic`）、重心（`centerOfMass`）、Collider/Trigger 尺寸、物理材质。
- **原则**：**优先通过资源配置文件维护，运行期不应无条件覆写**。
- **避坑**：不要在脚本的 `Start` 中写死 `rb.mass = X`，这会导致编辑器内的调参失效。

### 2. 运行期状态与力（脚本逻辑层）
- **内容**：一次性冲量（`AddForce`）、持续速度驱动（`velocity`）、生命周期内的状态切换（如：拾取时临时开启 `isKinematic`，进入载具时临时关闭 `useGravity`）。
- **原则**：运行期的状态切换必须有**成对的生命周期契约**（如 `PickUp` 对应 `Drop`），在退出状态时必须恢复初始静态配置。

## 四、 名词与概念对照

| 名词 | 业务语义 |
| :--- | :--- |
| `mass` | **质量（kg）**：影响冲量响应与碰撞反馈；不应用于解决"穿模"问题。 |
| `drag` | **线性阻尼**：决定速度自然衰减的快慢。 |
| `angularDrag` | **角速度阻尼**：决定自旋衰减的快慢（球类通常较低，载具较高）。 |
| `isKinematic` | **运动学开关**：开启时无视重力与外力，仅由脚本主动位移（如移动平台）。 |
| `isTrigger` | **触发器开关**：开启时取消实体碰撞，仅用于检测重叠（如靠近交互区）。 |
| `useGravity` | **重力开关**：决定是否受全局向下重力影响。 |
| `layer` | **物理层级**：决定碰撞矩阵过滤及踩地检测（例如：玩家能否站在该物体上）。 |
