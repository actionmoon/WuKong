# 碰撞体与触发器 (Collider & Trigger)

`UnityEngine.Collider` 决定了物体在物理空间的**碰撞形状与触发范围**。
本文档解析 Collider 与 Trigger 的语义差异、多 Collider 组合模式以及碰撞层（Layer）的基本作用。

---

## 一、 Collider vs Trigger：角色与职责

Collider 组件通过 `isTrigger` 字段区分两种截然不同的物理角色。在设计交互对象时，必须明确其所需的职责。

| 角色模式 | `isTrigger` | 物理职责 | 触发的回调入口 |
| :--- | :--- | :--- | :--- |
| **实体碰撞 (Collider)** | `false` | 参与物理反馈（支撑、阻挡、被推挤、撞击地面） | `OnCollisionEnter` / `OnCollisionStay` / `OnCollisionExit` / `OnActorCollisionEnter` / `OnActorCollisionExit` |
| **触发器 (Trigger)** | `true` | 不产生实体碰撞，仅用于发送重叠与穿越信号 | `OnTriggerEnter` / `OnTriggerStay` / `OnTriggerExit` / `OnActorTriggerEnter` / `OnActorTriggerExit` |

### 双 Collider 职责协作模式
一个复杂的交互对象（如：需要被踢击，又需要靠近拾取的篮球）通常需要同时挂载 **实体 Collider + Trigger**：
- **实体 Collider**：负责撞地、撞墙、与玩家身体产生接触反馈。
- **Interaction Trigger**：负责靠近检测、弹出交互按钮以及交互生命周期。

**注意**：这不是要求所有对象都配置两个 Collider。纯交互对象可以只有 Trigger，纯环境障碍物可以只有实体 Collider。但若一个对象兼具“物理接触 + 靠近交互”，必须按双 Collider 模式验收。

**Hamlet Actor 回调与层级约束**

- **核心机制**
  - **事件封装**：`OnActorTriggerEnter` / `OnActorTriggerExit` / `OnActorCollisionEnter` / `OnActorCollisionExit` 是对 Unity 原生事件的二次封装，专用于处理玩家与实体/触发器的交互回调。
  - **同节点强制绑定**：接收回调的脚本（`DouyinScript` / `DouyinScriptBehaviour`）**必须**与产生该回调的 `Collider` 挂载于**同一个 `GameObject`** 上。
  - **无冒泡特性**：尽管 Unity 原生允许 Rigidbody 与子 Collider 组成复合碰撞体（物理接触依然生效），但 Hamlet Actor 回调**不会**沿父子层级冒泡。
- **避坑与拓扑规范**
  - ❌ **常见失效拓扑**：“脚本在 Root，Trigger/Collider 在 Child”。父节点脚本无法接收子节点的事件。
  - ✅ **推荐拓扑 1（逻辑表现分离）**：将脚本与 Collider/Trigger 放在同节点，视觉 Mesh 作为纯表现放在子节点。
  - ✅ **推荐拓扑 2（节点独立自治）**：若必须保留子节点 Collider，则将负责该回调的逻辑脚本直接挂载到该子节点。

## 三、 核心场景与组件搭配

| 业务场景 | 所需 Collider 配置 | 常见误区 |
| :--- | :--- | :--- |
| **地面、墙体、环境障碍物** | 仅需要 `isTrigger=false` 的实体 Collider。 | 误加 Trigger 导致无谓的性能消耗。 |
| **纯靠近交互（如：空气墙触发剧情、商店 NPC）** | 仅需要 `isTrigger=true` 的 Trigger。 | 误用实体 Collider 导致玩家被卡住。 |
| **物理道具（如：篮球、推箱）** | `isTrigger=false` 的实体 Collider 用于撞击；<br>`isTrigger=true` 的 Trigger 用于靠近拾取/提示。 | 只有 Trigger 导致物体直接掉下地板；只有实体 Collider 导致无法弹出靠近交互按钮。 |
| **得分区域（如：球门）** | 仅需要 `isTrigger=true` 的 Trigger 覆盖得分区域。 | Trigger 尺寸过小导致快速穿过的物体漏判。 |

## 四、 Trigger 尺寸设计指南

Trigger 的尺寸（如 Radius 或 Size）应该**只比交互所需略大**：

- **球类拾取**：`sphere radius` 建议比球本体半径大 **20% ~ 40%**（例如球半径 0.25，Trigger 半径设为 0.35）。
- **通用拾取范围**：比物体包围盒稍大，使玩家在常规距离下能自然触发。

**尺寸过大的危害**：
1. 交互脱节：玩家距离很远就弹出按钮，或者在屏幕外触发剧情。
2. 状态反复抖动：当物体被轻微踢离原位时，玩家会反复在 Trigger 的边缘进出，导致频繁触发 `Enter/Exit`，干扰下游业务逻辑。

## 五、Layer 与碰撞矩阵

Unity 用 32 位 Layer 标签给物体分类，然后通过全局的**Layer 碰撞矩阵**决定哪些层之间发生实体碰撞。SDK 使用的关键 Layer：

| Layer ID | Layer 名 | 用途 |
| --- | --- | --- |
| `0` | Default | 默认层；玩家踩地检测**命中**；实体碰撞正常 |
| `2` | IgnoreRaycast | 对射线检测隐身；**不推荐**用作物理过滤（副作用大） |
| `6` | Props | 物理道具层；**踩地检测穿过**，但仍保留实体碰撞（可被踢 / 推） |
| `9` | 项目自定义（通常载具专用） | 载具类物体常用；具体碰撞矩阵按项目定义 |

## 六、 踩地检测与 Layer 分类

在 Hamlet 平台中，物体的 Layer 决定了它是否被玩家的**踩地检测**命中，这直接影响“玩家能否站在物体上”。
这是一次显性的二选一设计：

| 需求场景 | 目标 Layer | 踩地检测结果 | 表现效果 |
| :--- | :--- | :--- | :--- |
| **允许玩家站立并被带走（如：移动平台）** | `Default (0)` | ✅ 命中 | 玩家站得稳，物体移动时会带走玩家。 |
| **防止玩家被顶飞（如：球、可踢道具）** | `Props (6)` | ❌ 穿过 | 玩家站不住，不会被顶飞；但仍保留实体碰撞（可踢可推）。 |

*注：资源配置文件的 `layer` 静态字段仅支持 `0` 和 `9`，如果要设置为 `Props (6)`，必须在运行期通过脚本递归 `SetLayer`。*
