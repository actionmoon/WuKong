# Actor 模式概述 (Avatar 与 Pet)

在抖音虚拟世界（Douyin World）中，代表玩家在世界中控制和交互的实体被称为**玩家网络对象 (Actor)**。

根据玩家与这个显示对象之间的控制关系，提供了两种底层模型：**Avatar 模式** 和 **Pet 模式**。这两种模式在游戏对象映射、控制权流转以及相关 API 的可用性上有着根本的差异。

## 一、两种模式的核心差异

| 维度 | Avatar 模式 (独立形象) | Pet 模式 (合养精灵) |
| --- | --- | --- |
| **玩家与显示对象关系** | 玩家与显示对象 **一对一**，每个玩家拥有专属形象 | 玩家 **操控** 合养精灵，一只精灵可归属两个玩家，双方共享一只显示对象 |
| **控制权切换** | **不存在**。控制权固定属于关联玩家 | **存在**。控制权在两个合养玩家间进行“主控”与“观察者”的切换 |
| **典型应用场景** | 绝大多数独立虚拟形象世界、单人形象玩法 | 抖音合养精灵世界、双人合养玩法 |
| **通用数据入口** | 均可通过 `DouyinPlayerService` 与 `DouyinPlayer` 作为玩家层面的统一入口 | 同左 |

## 二、对象关系映射模型

理解这两种模式的关键，在于理解 `DouyinPlayer` (玩家逻辑实体) 与 `DouyinActor` (场景显示实体) 之间的绑定关系。

### 1. Avatar 模式 (一对一绑定)
在 Avatar 模式中，玩家实体与场景中的显示实体是严格的**一对一专属绑定**关系。
不存在“合养”概念，也不存在控制权在玩家之间转移的逻辑。

```text
   +-----------------+          +----------------+
   |   抖音玩家 A     |          |   抖音玩家 B    |
   |  DouyinPlayer   |          |  DouyinPlayer  |
   +--------+--------+          +--------+-------+
            |                            |
            v                            v
   +-----------------+          +----------------+
   |  DouyinActor    |          |  DouyinActor   |
   |  形象 A (专属)   |          |  形象 B (专属)  |
   +-----------------+          +----------------+
```

### 2. Pet 模式 (多对一共享与主控切换)
在 Pet 模式中，引入了一个中间层 `DouyinPet`。两个玩家共同拥有这只精灵，但同一时刻，**只能有一名玩家作为“主控端”**，另一名玩家作为“观察者端”。
主控端和观察者端会在游戏过程中发生**控制权切换**。

```text
   +-----------------+          +----------------+          +----------------+
   |  抖音玩家 A      |          |  抖音玩家 B     |          |  DouyinPet     |
   |  DouyinPlayer   |          |  DouyinPlayer  |          |  合养精灵       |
   +--------+--------+          +--------+-------+          +--------+-------+
            |                            |                           |
            | 两个玩家共有一只精灵         |                           |
            +----------------------------+---------------------------+
                                         |
                                         v
                              +----------+-----------+
                              |  DouyinActor         |
                              |  世界内的显示对象     |
                              |  操作权在两人间切换   |
                              +----------------------+
```

## 三、开发约束与 API 黑名单

由于 Avatar 模式下**根本不存在**双人合养、主控切换等概念，因此所有服务于 Pet 模式的专属 API 在 Avatar 模式下**必须严格禁用**。

如果在 Avatar 模式下调用这些 API，业务逻辑会建立在不存在的前提上（例如依赖返回了 `null` 的对象，或监听了永远不会触发的事件），这通常会导致逻辑静默失效或引发严重的运行时异常。

### Avatar 模式下的 API 黑名单（C# 与 Lua 双端一致）

#### 1. 类级别禁用
*   **`DouyinPetService`**：整个类禁止使用（调用将给出警告提示并严格禁用）。
*   **`DouyinPet`**：整个类禁止使用（调用将给出警告提示并严格禁用）。

#### 2. DouyinActor 上的禁用成员
*   **属性 `isPet`**：禁用。方法警告，强制返回 `false`。
*   **属性 `douyinPet`**：禁用。方法警告，强制返回 `null`。
*   **属性 `isBindMode`**：禁用。暂时不做拦截，但属于无效状态。
*   **属性 `isMasterMode`**：禁用。读取时返回默认值 `true`。
*   **属性 `isObserverMode`**：禁用。读取时返回默认值 `false`。
*   **事件 `onGetPetMessage`**：禁用。暂未做返回值限制，但毫无意义。

#### 3. 生命周期与事件禁用
*   **回调 `OnActorOperationChanged(actor)`**：禁用，不得声明。这是 Pet 模式下主控与观察者发生操作权切换时的回调，在 Avatar 模式下永远不会触发（底层暂时不做拦截，但观察不到任何回调）。

### 误用避坑指南
*   **获取当前玩家 Actor**：请直接使用 `DouyinActorService.GetLocalActor()` 或 `DouyinPlayerService.GetLocalPlayer():GetActor()`，**绝不要**通过 `DouyinPet` 去绕一圈获取。
*   **状态管理**：Avatar 模式下不需要处理因“失去控制权”而导致的 UI 隐藏或摇杆禁用等逻辑，请直接依赖 `OnEnable` / `OnDisable` 或全局玩家生命周期事件即可。
