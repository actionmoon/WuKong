# 遥控状态与角色锁定

## 适用场景
- 玩家进入无人机、机械炮塔、加特林、遥控车或云台等设备的控制状态。
- 左摇杆的输入需要从“控制玩家角色移动”切换为“控制被控设备移动或瞄准”。

## 核心机制

### 冲突处理流程
进入控制状态后，同一组 `moveVec` 会同时被角色和设备接收。标准解决流程如下：

1. **进入控制状态**（如点击“控制炮塔”后）：
   - 确认 Actor 是本地玩家且设备可控制。
   - 调用 `actor:Immobilize(true)` 锁定玩家角色的摇杆移动。
   - 设备脚本开始消费摇杆事件，驱动设备运动。
2. **退出控制状态**（如点击“退出控制”后）：
   - 清零设备的 `moveVec` 及其他临时输入状态，停止设备运动。
   - 隐藏控制相关 UI，调用 `actor:Immobilize(false)` 恢复玩家角色的摇杆移动。
3. **必须**在被控设备的 `OnDestroy` 中，无条件执行状态清零、解绑监听，并调用 `actor:Immobilize(false)`。若遗漏此兜底，设备意外销毁时玩家将永久卡死。

## 业务边界
`Immobilize(true)` 的作用域极其严格：
- **负责**：仅仅是禁止玩家 Actor 响应左摇杆的移动逻辑。
- **不负责**：停止全局摇杆事件分发；分配设备的控制权或网络主权；停止角色的重力和碰撞；替代模组自身的输入监听逻辑。

## 避坑指南
- **兜底恢复缺失（致命错误）**：**必须**在被控设备的 `OnDestroy` 中，无条件执行状态清零、解绑监听，并调用 `actor:Immobilize(false)`。若遗漏此兜底，设备意外销毁时玩家将永久卡死。
- **过早锁定角色**：只能在玩家**成功进入控制状态后**锁定角色。严禁在玩家刚进入 Trigger 区域或刚显示交互按钮时就提前调用 `Immobilize(true)`。
- **粗暴处理摇杆**：禁止通过禁用全局摇杆来解决冲突；设备脚本应持续保持 `Start / Perform / Cancel` 的监听闭环，仅在内部逻辑中判断是否消费该输入。
- **状态竞争解锁**：当有多个系统可能同时锁定角色时，禁止单一模组在退出时无条件调用 `Immobilize(false)` 解除锁定，应使用统一的锁定令牌进行管理。
