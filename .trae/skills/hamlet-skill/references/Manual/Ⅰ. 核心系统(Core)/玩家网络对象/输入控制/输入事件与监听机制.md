# 输入事件与监听机制

## 适用场景
- 监听跨平台输入（移动摇杆、视角拖拽、跳跃按钮等）。
- 将平台原始输入转换为业务脚本的逻辑状态。

## 核心机制

### 事件分类
`DouyinInputService` 屏蔽了 PC（键盘/鼠标）和移动端（触屏摇杆/手势）差异，提供统一静态回调：
- **移动摇杆**：`onMoveInputStart`, `onMoveInputPerform`, `onMoveInputCancel`
- **视角拖拽**：`onLookInputStart`, `onLookInputPerform`, `onLookInputCancel`
- **跳跃动作**：`onJumpInputStart`, `onJumpInputPerform`, `onJumpInputCancel` (PC空格与手机跳跃按钮行为一致)
- **其他触控**：`onTouchEvent` (触摸), `onZoomInput` (双指缩放)

### 三态生命周期
持续性输入（如摇杆、拖拽）必须遵循三态闭环，回调函数仅负责**状态采样**：
- **Start**：输入开始。
- **Perform**：输入持续，更新当前值。
- **Cancel**：输入结束。

## 业务边界
输入监听模块的功能非常明确：**负责将平台输入转换为脚本变量**。
- **不负责**：判断角色状态（如是否上车）、分配物理控制权限、计算摇杆死区、直接写入刚体速度或位置。

## 避坑指南
- **生命周期断裂**：必须成组监听。严禁只监听 `Perform` 而遗漏 `Start` 或 `Cancel`。
- **输入状态残留**：`Cancel` 事件必须将对应的采样变量（如 `moveVec`）彻底清零。
- **物理更新不同步**：禁止在输入回调中直接驱动物理或修改 `Transform`；正确做法是回调只更新变量，由 `FixedUpdate` 或 `Update` 统一消费。
- **参数取值错误**：`onMoveInputPerform` 直接接收 `Vector2` 对象，必须通过 `x` / `y` 读取输入值；严禁将其当作带有 `direction` 字段的事件对象读取。
- **内存泄漏**：必须在 `Start` 中注册监听，并在 `OnDestroy` 中移除当前脚本注册的回调（移除前需检查引用是否已初始化）。
