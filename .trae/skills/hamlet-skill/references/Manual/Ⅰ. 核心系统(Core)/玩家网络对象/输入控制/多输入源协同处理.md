# 多输入源协同处理

## 适用场景
- 同一动作存在多个触发入口（例如：摇杆移动 + 键盘 WASD + 屏幕 UI 按钮）。
- 持续性技能、开火或蓄力动作，需要支持多端并行操作。

## 核心机制

### 状态独立与统一聚合
多个输入源绝不能各自独立、直接地修改目标物理状态。必须采用“分别记录，统一结算”模式：

```lua
-- 1. 独立记录：每个输入源只更新属于自己的状态变量
local actionHeld = {
  keyboard = false,
  platformButton = false,
  runtimeUI = false,
}

-- 2. 统一聚合：通过统一函数评估整体状态
local function isActionHeld()
  return actionHeld.keyboard
    or actionHeld.platformButton
    or actionHeld.runtimeUI
end
```
**3. 统一执行**：业务逻辑（如 `Update` 或 `FixedUpdate`）仅读取 `isActionHeld()` 的结果进行结算。

### 拾取与乘坐的特殊处理
拾取（Pickup/Drop）和乘坐（SitDown/StandUp）等非连续方向输入：
- **必须**走平台提供的完整交互闭环（靠近显示按钮 -> 调用原生 API -> 触发原生回调完成物理切换）。
- Runtime UI 可以用来显示状态，但**严禁**绕开原生流程直接修改“已拾取”或“已乘坐”的业务变量。

## 避坑指南
- **状态互相覆盖**：一个输入源释放时，**只允许**将对应字段改为 `false`；严禁一并清空其他仍在按住的输入源状态。
- **缺乏总清理**：角色离座、放下物品、退出当前玩法、禁用脚本或 `OnDestroy` 时，必须对所有输入源状态进行一次**总清零**。
- **UI 替代原生**：除非需求明确规定仅限 UI 操作，否则绝不能因为新增了 UI 按钮，就擅自删减摇杆、键盘的平台原生输入逻辑。
