# 相机视角控制

`DouyinCameraService` 提供了对玩家主相机的控制权。平台默认具备一套跟随玩家的底层相机逻辑，业务侧对相机的干预必须遵守特定的时机和规则，避免与底层逻辑发生覆盖冲突导致抖动。

---

## 一、核心特征

- **平台跟随为底**：平台默认在每帧的 `LateUpdate` 阶段更新相机跟随；业务干预必须协同这一时机。
- **仅走 SDK 服务**：所有干预必须通过 `DouyinCameraService`；**严禁**直接读写 `Camera.main.transform` 的 `position` / `rotation`。
- **本地玩家专属**：相机只对本地玩家有意义，**不进行多人同步**；业务侧通过 `actor.isLocal` 过滤。
- **全局副作用**：`SetPitch` / `SetDistance` / `SetOffset` 等参数修改是**全局的**，进入某状态时设置、退出该状态时**必须显式恢复**。
- **平台跟随不回拨 FOV**：写入 `GetCamera().fieldOfView` 会持续保留，不会被平台跟随逻辑覆盖。

---

## 二、API 速查

| API | 用途 | 备注 |
| --- | --- | --- |
| `DouyinCameraService.GetCamera()` | 获取主相机 `UnityEngine.Camera` | 代理服务异常时返回 `nil` |
| `DouyinCameraService.GetYaw()` / `SetYaw(yaw)` | 读写相机水平偏航角（度） | `GetYaw` 异常时返回 `nil` |
| `DouyinCameraService.GetPitch()` / `SetPitch(pitch)` | 读写相机俯仰角（度） | `GetPitch` 异常时返回 `nil` |
| `DouyinCameraService.SetDistance(distance)` | 设置相机到主角距离 | 只有 setter；宿主自行缓存默认值 |
| `DouyinCameraService.SetOffset(offset)` | 设置目标点 `Vector3` 偏移 | 只有 setter；宿主自行缓存默认值 |
| `Camera.fieldOfView` | 视野角（度） | 写入 `GetCamera()` 返回的相机；平台不会回拨 |
| `DouyinCameraService.StartPhotograph()` / `StopPhotograph()` | 进入 / 退出拍照模式 | — |
| `DouyinCameraService.IsPhotographMode()` | 是否处于拍照模式 | — |
| `DouyinCameraService.onCameraModeChanged` | 模式切换事件 | 用 `AddListener` / `RemoveListener` 配对 |
| `DouyinInputService.onLookInputStart` / `onLookInputPerform` / `onLookInputCancel` | 玩家拖视角三事件 | 供业务侧让出自动回正控制权 |

## 三、通用硬约束（跨节共享）

以下约束在所有相机业务里都成立，各节的专属约束会在对应节尾另行说明。

1. **nil-guard**：`GetCamera` / `GetYaw` / `GetPitch` 等 getter 返回值**必判 `nil`**——代理服务异常时会返回 `nil`，不判会崩溃。
2. **严禁直改相机 Transform**：**严禁**直接获取 `Camera.main.transform` 修改 `position` / `rotation`。**唯一例外**：`GetCamera()` 返回的相机上写 `fieldOfView` 是允许的（官方 API 允许，运行时不会被回拨）。
3. **全局副作用必须恢复**：调用 `SetDistance` / `SetPitch` / `SetOffset` 改变相机状态后，在退出该状态（下车、离开触发区、脚本 `OnDestroy`）时**必须显式恢复**到宿主约定的默认值——不要假设系统或 `GetDistance` / `GetOffset` 存在，宿主自己缓存默认值。
4. **`LateUpdate` 唯一时机（yaw 回正）**：yaw 回正逻辑**必须**放在 `LateUpdate` 中执行——平台默认相机跟随在 `LateUpdate` 阶段更新；写在 `Update` / `FixedUpdate` 会被立即覆盖或与平台跟随覆盖冲突产生高频抖动。
5. **事件监听精准解绑**：`onLookInput*` / `onCameraModeChanged` 一律用 `AddListener(handler)` + `RemoveListener(handler)` 配对（Lua 侧**不用** C# 的 `+=` / `-=`）；**保存 handler 引用**用于精准解绑，**不要**用 `RemoveAllListeners()`——后者会误清其它模块的订阅。
6. **状态变量放脚本顶层**：`isLookingActive` / `lastLookTime` 等跨函数状态**必须声明在脚本顶层**，不能放到 `Start` 内部的局部作用域，否则 `LateUpdate` 拿不到状态。
7. **业务条件由扩展点表达**：业务相关的开关条件（是否驾驶 / 是否进入触发区 / 是否按住油门）**必须由宿主脚本写在 `getCameraAlignTargetYaw` 等扩展点内部**，通过返回 `nil` 表达"当前不需要对齐"；**不要**在通用相机模块的 `LateUpdate` 中硬编码任何业务条件。
8. **静态参数走资源配置**：物体的静态物理 / 视觉参数应通过资源配置文件维护静态字段；Lua/C# 里只做运行期状态与副作用切换。

## 四、Yaw 水平渐进回正

驾驶载具、剧情引导、锁定目标等场景下，通常希望相机能平滑地回正到某个方向。由于 yaw 极易与平台默认跟随以及玩家手动拖拽视角冲突，必须严格遵守以下范式。

### 4.1 回正硬约束（4 条）

1. **必须在 `LateUpdate` 执行**：见通用硬约束 #4。
2. **避让玩家输入**：当玩家正在拖拽屏幕（监听 `DouyinInputService.onLookInput*`）或刚松手（`cameraAlignGrace` 冷却时间内），必须暂停自动回正。
3. **使用 `Mathf.DeltaAngle`**：计算目标角度差必须使用最短角差函数，避免 350°→10° 时反向旋转一整圈。
4. **按步长渐进**：使用 `maxStep = cameraAlignSpeed * speedScale * Time.deltaTime` 逐步逼近，**禁止**直接 `SetYaw(targetYaw)` 每帧直写目标值——目标每帧都变，这等价于让相机以无穷角速度跟随目标抖动。

### 4.2 扩展点契约

通用回正模块暴露两个扩展点函数，由宿主脚本覆写来表达"何时对齐、对齐到哪里"：

| 扩展点 | 语义 | 返回 |
| --- | --- | --- |
| `getCameraAlignTargetYaw()` | 当前希望对齐到的 yaw（度） | 数值 = 对齐目标；`nil` = 当前不对齐 |
| `getCameraAlignSpeedScale()` | `[0, 1]` 范围的速度缩放 | `0` / 负值 = 不对齐；越大回正越积极 |

**`LateUpdate` 逐项 guard 顺序**（任一不满足直接 `return`）：

```
isLookingActive 为 false
Time.time - lastLookTime >= cameraAlignGrace
getCameraAlignTargetYaw() 返回非 nil
getCameraAlignSpeedScale() 返回 > 0
GetYaw() 返回非 nil
```

### 4.3 Look 输入监听时序

`Start` 中注册 Look 输入监听必须放在**宿主自身的输入注册之后**；`OnDestroy` 中清理 Look 监听同样放在**宿主输入解绑之后**。保持"先业务输入、后相机输入"的对称顺序。

具体代码骨架见 [相机回正-Lua.md](../../../../Best%20Practice/相机/相机回正-Lua.md)。

## 五、Pitch / Distance / Offset 相机参数

在赛车追尾、骑乘生物、进入狭窄室内等场景，通常需要改变相机的空间参数。

### 5.1 API 用途

| API | 效果 | 典型用途 |
| --- | --- | --- |
| `SetDistance(distance)` | 相机拉远 / 拉近 | 车后追尾拉远、狭窄空间拉近 |
| `SetPitch(pitch)` | 相机俯仰角 | 后上方追尾角度、抬高观察 Boss |
| `SetOffset(offset)` | 观察目标点位置偏移 | 抬高视线、瞄准偏移 |

### 5.2 数值建议（驾驶态参考）

| 参数 | 常见起步值 | 说明 |
| --- | --- | --- |
| `driveCameraDistance` | `7 ~ 10` | 过大让小车占屏太小，过小则后方追尾感不明显 |
| `driveCameraPitch` | `8 ~ 18` | 过大变俯视，过小则"后上方"不明显 |
| `driveCameraOffset` | `Vector3(0, 0.8, 0)` ~ `Vector3(0, 1.5, 0)` | 用于把视线目标点抬高 |

### 5.3 与 yaw 回正的分工

- **不要**把 pitch / distance / offset 逻辑塞进 yaw 回正的 `LateUpdate`——职责混淆会让相机在各种阶段与业务事件下产生难以调试的耦合。
- 参数设置放到业务生命周期时机：`OnSeatEntered` 里进入、`OnSeatExited` / `OnDestroy` 里恢复默认。
- 如果实测某个运行时版本会**回拨** `SetDistance` / `SetPitch` / `SetOffset`，把 `applyDriveCameraView()` 放到驾驶状态下的 `LateUpdate` 末尾，**并让 yaw 回正逻辑先完成**。

### 5.4 平台跟随行为

主流版本下，`SetDistance` / `SetPitch` / `SetOffset` 一次写入后会持续生效，不会被平台回拨。业务侧无需每帧重写。

## 六、FOV 视野增强

当载具加速或使用冲刺技能时，动态增大视野角（FOV）能极大增强速度感。

### 6.1 平滑过渡

FOV 必须使用 `Mathf.Lerp` 平滑过渡，**严禁瞬切**（会造成眩晕）。

```lua
currentFov = CS.UnityEngine.Mathf.Lerp(currentFov, targetFov, CS.UnityEngine.Time.deltaTime * fovLerpSpeed)
camera.fieldOfView = currentFov
```

### 6.2 数值建议

| 参数 | 常见起步值 | 说明 |
| --- | --- | --- |
| `baseFov` | `55 ~ 65` | 平台默认值或当前稳定值 |
| `boostFov` | 相对 `baseFov` **+6 ~ +10** | 差值再大容易眩晕 |
| `fovLerpSpeed` | `4 ~ 8` | 越大切换越快 |

### 6.3 常见误区

| 误区 | 结果 | 正确做法 |
| --- | --- | --- |
| 用 FOV 模拟"把相机拉远" | FOV 只改变视野宽窄，无法把相机移到车后追尾位置 | 用 `SetDistance` + `SetPitch` + `SetOffset` |
| `fovLerpSpeed` 过大瞬切 | 眩晕 | `4 ~ 8` 平滑过渡 |
| 把 FOV 调得过小（如 `35`）模拟加速 | 窄视野像长焦镜头（视野角变小、透视变弱），反而**削弱**速度感 | boost 时**增大** FOV，不减小 |
| boost 结束后额外清理 FOV | 无必要 | 目标 FOV 回到 `baseFov` 即可，写入会持续保留 |

## 七、拍照模式

当玩家进入拍照模式时，相机控制权会被平台接管。

### 7.1 核心 API

- `StartPhotograph()` / `StopPhotograph()`：主动进入 / 退出拍照模式。
- `IsPhotographMode()`：判断当前是否处于拍照模式。
- `onCameraModeChanged`：监听模式切换事件（回调参数为 `CS.DouyinCameraMode.Photograph` 或 `CS.DouyinCameraMode.GamePlay`）。

### 7.2 与业务相机参数的冲突处理

拍照模式下平台可能接管相机参数。业务侧建议：

- **进入拍照模式（`Photograph`）**：暂停 yaw 回正 / pitch / distance / offset 等业务干预。
- **退出到游戏模式（`GamePlay`）**：**重新施加**当前业务状态的相机参数（例如驾驶中要重新 `applyDriveCameraView()`）。
- 监听 / 解绑使用 `onCameraModeChanged:AddListener(handler)` + `RemoveListener(handler)`（见通用硬约束 #5）。

## 八、模块边界（本节不覆盖）

以下需求超出本手册章节范围：

- **第一 / 第三人称视角切换**：`DouyinCameraService` 不提供 API；业务侧需自行设计视角状态机。
- **Cinemachine / 自定义 `Camera` 组件**：本手册**只**覆盖 `DouyinCameraService`；第三方相机方案需自行确认与平台跟随的兼容性。
- **多人相机同步**：相机对本地玩家有意义，业务侧通过 `actor.isLocal` 过滤，**不做**网络同步。
- **相机 Shake / 抖动特效**：暂无平台级 API，业务侧可在 `LateUpdate` 末尾追加 yaw / pitch 微扰实现，但要与 yaw 回正逻辑做时序上的隔离。

## 九、避坑 FAQ

| 现象 | 违反约束 | 修复 |
| --- | --- | --- |
| 相机与平台跟随覆盖冲突产生高频抖动 | §3 #4（回正写在 `Update` / `FixedUpdate`） | 挪到 `LateUpdate` |
| 玩家松手后视角立刻被强制回正 | §4.1 #2（漏 `cameraAlignGrace` 冷却） | 加上 `Time.time - lastLookTime >= cameraAlignGrace` 判断 |
| 从 350° 回正到 10° 时相机反向长路径旋转 | §4.1 #3（直接做差） | 用 `Mathf.DeltaAngle` |
| 相机每帧被直写到目标值，跟着目标抖动 | §4.1 #4（每帧 `SetYaw(targetYaw)`） | 按 `maxStep` 渐进 |
| 通用相机模块被绑死到某个业务场景 | §3 #7（业务条件硬编码进 `LateUpdate`） | 收敛到 `getCameraAlignTargetYaw` 内部 |
| 相机被直写 `transform` 扭转 | §3 #2 | 只走 `DouyinCameraService.SetYaw` |
| `LateUpdate` 拿不到 `isLookingActive` | §3 #6（状态放到 `Start` 局部作用域） | 声明到脚本顶层 |
| `RemoveAllListeners` 清掉宿主其它订阅 | §3 #5（未精准解绑） | 保存 handler 引用 + `RemoveListener(handler)` |
| `GetCamera()` / `GetPitch()` 在拍照或异常时崩溃 | §3 #1（未判 nil） | `if camera == nil then return end` |
| 下车后相机仍是追尾视角 | §3 #3（退出未恢复默认） | `OnSeatExited` 里 `restoreDefaultCameraView()` |
| pitch / distance / offset 塞进 yaw 回正的 `LateUpdate` | §5.3 | 拆到独立函数，在业务生命周期时机调 |
| 用 FOV 模拟"拉远相机" | §6.3 | `SetDistance` 才是拉远 API |
| FOV 从 60 瞬切到 90 眩晕 | §6.1（未平滑过渡） | `Mathf.Lerp` + `fovLerpSpeed = 6` |
| 把 FOV 调窄模拟加速 | §6.3 | boost 时应**增大** FOV |

## 十、Lua 与 C# 差异说明

- **Lua**：全部通过 `CS.DouyinCameraService` / `CS.DouyinInputService` 访问；事件用 `:AddListener(handler)` / `:RemoveListener(handler)` 配对。
- **C#**：同名 API 走 `DouyinCameraService` 的 C# 绑定，方法签名一致；`onCameraModeChanged` 等事件同样通过 `AddListener` / `RemoveListener`（Unity `UnityEvent` 语义），**不使用** C# `+=` / `-=`。
- **代码骨架覆盖**：**同时提供 Lua / CSharp 两套代码骨架**（见下节）；通用硬约束（§三）与 yaw 回正硬约束（§4.1）跨语言适用。
