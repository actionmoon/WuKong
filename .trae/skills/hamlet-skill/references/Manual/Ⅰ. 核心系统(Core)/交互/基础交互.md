# 基础交互

“基础交互”是本地玩家在进入普通网络对象交互区域内，发起的交互请求（如拾取、座位、通用操作），并根据交互请求类型，将请求事件分发到目标对象的业务脚本，由目标对象的业务脚本处理对应的交互逻辑。

交互由三部分组成：
- **发起对象**：本地玩家角色，负责主动发起交互请求（如拾取、座位、通用操作）。
- **响应对象**：具有处理交互事件的普通网络对象，收到交互事件后处理表现和业务状态。
- **交互触发**：本地玩家在普通网络对象交互区域内，自动触发或点击交互按钮触发。

本文重点说明基础交互的分类、核心机制与能力边界。具体代码实现与硬约束请参考相应的最佳实践文档。

## 一、交互分类与边界

基础交互按照“触发方式”和“业务职责”划分为两大类：**触发交互** 和 **非触发交互**。

### 1. 触发交互 (Trigger Interaction)
- **概念**：玩家进入或离开对象的 Trigger 区域时，自动触发或取消的交互方式。
- **边界**：只处理“谁进入或离开当前区域”及其直接相关的上下文。**不负责**后续的交互按钮点击、拾取挂手、座位对齐、物理持续驱动或业务状态机。
- **典型场景**：
  - 作为非触发交互的“UI 唤醒入口”（识别本地玩家，开启/关闭交互按钮）。
  - 执行与进入/离开直接绑定的玩法逻辑（如陷阱、传送、伤害区、区域提示与高亮）。

### 2. 非触发交互 (Non-Trigger Interaction)
- **概念**：在玩家进入或离开对象的 Trigger 区域时，由玩家主动发起（如点击交互按钮），并在全端回调或同步状态中执行业务表现的交互方式。
- **边界**：触发区域只负责本地 UI 入口，真实业务必须由明确的请求（如 `Pickup` / `SitDown` / `Interact`）发起。
- **分类**：非触发交互包含三种具体的业务类型：

| 类型 | 核心机制 | 系统框架逻辑 | 业务负责 | 典型场景 |
| --- | --- | --- | --- | --- |
| **拾取 / 丢弃** | 本地玩家把可拾取物拿在手上、随手部移动，并可丢弃 | 持有关系、挂点、动画、主权、控制权和网络同步 | 物理开关、UI、挂载与对齐表现 | 武器、道具、可拿起的物件 | 
| **座位** | 玩家坐到指定对象上、保持坐姿跟随其移动，再站起 | 座位占用互斥、事件派发、主权、控制权和基础动画 | `SeatAnchor` 挂载对齐、按钮与业务扩展 | 椅子、沙发、载具、观众席 |
| **通用交互** | 除拾取和座位之外的通用对象操作 | 将交互事件路由到目标对象回调 | 业务状态、动画、UI 以及持久数据同步 | 开关门、机关、NPC、商店、任务节点 |

> **座位配置约束**：每个座位 NetworkObject 配置一个 `SeatAnchor` 和一个逻辑 `CurrentPlayer`；多座椅车辆必须拆成多个独立座椅 NetworkObject，并分别调用 `SitDown`。

> **注意**：拾取和座位由框架接管较深的状态与同步；而通用交互只同步“发生一次交互”的瞬时事件，业务状态（如门是否打开、是否已领取奖励）必须由开发者通过同步变量自行维护。

## 二、核心交互机制

### 1. 非触发交互：入口与业务分离
非触发交互（拾取、座位、通用交互）必须严格遵循**入口与业务分离**的四段式生命周期机制：

| 阶段 | 运行端 | 核心机制 | 边界与红线 |
| --- | --- | --- | --- |
| **1. UI 生命周期** | 本地 | 通过 Trigger 区域的 `OnActorTriggerEnter` / `OnActorTriggerExit` 开启或关闭交互，在`OnFocus`和`OnLostFocus`中处理焦点状态下创建和清理交互按钮。 | 绝不能在此阶段修改对象的业务状态或进行挂载。 |
| **2. 发起请求** | 本地 | 玩家点击交互按钮后，进行本地预检，调用 `Pickup` / `SitDown` / `Interact`。 | 绝不能在点击时提前改变公共对象状态。 |
| **3. 全端确认** | 全端 | 平台下发 `OnPickup` / `OnSeatEntered` / `OnInteract`，各端统一接管物理并执行表现。 | 绝不能用 `actor.isLocal` 过滤表现逻辑，否则远端表现异常。 |
| **4. 状态恢复** | 全端 | 玩家离开或丢弃时，平台下发`OnSeatExited`/`OnDrop`清理回调。 | 必须精确恢复接管前缓存的物理、缩放与父节点初始状态。 |

### 2. 状态同步和断线重连
网络回调事件（如 `OnInteract`、`OnPickup`）是**瞬时事件**。
拾取/座位 由系统内部实现状态的同步，并且在断线重连时，会再次调用网络回调事件（如 `OnInteract`、`OnPickup`），以恢复状态。

### 3. 交互通道与交互按钮生命周期管理
基础交互的入口显示由“交互通道（Interaction Channel）”与“焦点（Focus）”状态机共同驱动。必须严格遵循以下 API 的调用时机与规范：

| 核心 API | 职责与机制 | 调用时机与规范 | 核心避坑 / 红线 |
| --- | --- | --- | --- |
| `EnableInteraction()` | 开启交互通道。允许平台在玩家满足距离等条件时触发 `OnFocus`。 | **进入 Trigger 时**：过滤确认是本地玩家，且业务允许交互（如未被独占、未在冷却）后调用。 | **严禁同名覆盖**：绝不能自定义同名函数（如 `function EnableInteraction()`），这会覆盖平台 API 导致焦点状态机失效。 |
| `DisableInteraction()` | 关闭交互通道。强制对象失去焦点并触发 `OnLostFocus`。 | **离开 Trigger 时**：本地玩家离开范围、对象被禁用、或业务状态变为不可用时调用。 | **座位特例**：若玩家已坐在座位上（移动座位会带玩家离开 Trigger），**绝不能**调用此接口，否则将丢失“站起”交互按钮。 |
| `AddInteractorButton()` | 在本地 UI 创建交互按钮，并绑定点击响应事件。 | **获得焦点时**：仅在 `OnFocus` 回调中调用。交互按钮文案需由当前已确认的业务状态（如门已开/关）驱动。 | **禁止越界创建**：绝不能在初始化（`OnInit`/`Awake`）或全端表现回调（`OnInteract`）中创建交互按钮。 |
| `RemoveInteractorButton()` | 移除交互按钮，注销点击监听，并清空所有引用。 | **失去焦点时**：仅在 `OnLostFocus` 回调中调用。对象销毁或动态禁用时也需确保清理。 | **对称清理**：清理逻辑需具备幂等性，防止多次失焦导致重复移除或残留失效引用。 |
