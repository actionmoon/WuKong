# 游戏对象的属性

## 主权（Ownership）

主权用来决定**哪个玩家可以更改网络对象的属性并将其同步给其他玩家**。每个网络对象的主权在某一时刻一定归属于某位玩家，一个玩家可同时拥有多个网络对象的主权。如果你希望玩家能够更改物体的属性（例如设置同步变量），必须先检查或请求主权。

### 主权变更场景

1. **自动切换主权**：
   当主权方离开房间或切后台时，系统会自动将该对象的主权转移给房间内其他玩家，同时触发 `OnOwnershipTransferred` 事件。在设计数据同步逻辑时需特别注意切后台导致的主权转移。
2. **主动请求主权**：
   任何玩家均可调用 `RequestOwnership(callback)` 申请主权。原主权方会触发 `OnOwnershipRequest(senderID)`：
   * 返回 `true` 或不实现该方法：同意转移。
   * 返回 `false`：拒绝转移。
   * *注意：若物体挂载了多个脚本，必须所有脚本均返回 `true` 才能成功转移。*
3. **直接指定主权**：
   主权方或服务器可以通过调用 `SetOwner(player)` 直接将主权转移给指定玩家。

### 核心接口
| **接口/事件** | **说明** |
| --- | --- |
| `HasOwnership()` | 判断自己是否拥有当前物体的主权 |
| `GetOwner()` | 获取主权方的 `DouyinPlayer` 对象 |
| `IsOwner(player)` | 判断指定玩家是否为主权方 |
| `RequestOwnership(callback)` | 请求当前物体的主权，在 callback 中返回是否成功 |
| `SetOwner(player)` | 直接指定主权方 |
| `OnOwnershipRequest(senderID)` | 收到其他玩家主权请求时的回调，返回 boolean 决定是否同意 |
| `OnOwnershipTransferred()` | 主权发生转移时的广播回调事件 |

## 控制权（Controllership）

控制权与主权是不同的概念，用于精细化管理网络对象的操作权限：
* 主权决定谁负责数据同步，控制权决定谁实际操作该对象（例如物理移动）。
* **断线重连差异**：拥有控制权的玩家断线重连后，主权会重新回到该玩家身上；若仅有主权而无控制权，重连后主权不一定回归。
* **动态对象**：动态创建的网络对象，控制权不会自动归属创建者，需主动请求。

### 核心接口
| **接口** | **说明** |
| --- | --- |
| `HasControllership()` | 判断自己是否拥有控制权 |
| `RequestControllership(callback)` | 请求控制权 |
| `GetController()` | 获取控制方的玩家对象 |

## 自定义属性：同步变量（Sync Variable）

同步变量是会自动在所有玩家间同步数据的存储容器，是实现多人数据状态同步（如排行榜、开关状态等）最简便的方式。

### 使用规范

对象属性同时满足以下条件时，应使用同步变量：

1. **动态性**：属性值会在运行时发生变化，而不是在配置阶段固定不变。
2. **共享性**：至少有一个其他客户端需要读取或依赖该属性。
3. **一致性要求**：各客户端的数据不一致会导致表现错误或逻辑分歧。

典型适用场景包括：

* **属性与状态同步（Attribute & Status）**：同步对象的持续状态，如血量、等级和开关状态。
* **行为与事件同步（Action & Event）**：同步一次性触发的行为或事件，如攻击、施法和交互。
* **权威逻辑同步（Authority & Determinism）**：由权威端计算并下发确定性逻辑结果。

无需额外同步的情况：
* 网络对象的位置、旋转和缩放由引擎自动同步，无需再使用同步变量。
* **物理移动**：网络对象的物理移动（如移动平台、球等）由引擎自动同步，无需再使用同步变量。
* 明确申明不需要同步变量的属性，如：用户的界面状态、临时数据等。

### 支持的数据类型
* **基础类型**：`bool`, `byte`, `short`, `int`, `long`, `float`, `double`, `string`, `Vector2`, `Vector3`, `Quaternion`
* **集合类型**：`List<T>`, `Dictionary<K, V>`（Dictionary 的键 K 仅限 `byte, short, int, long, string`）
* *注：不支持直接同步结构体（Struct）。如需同步复杂结构，可序列化为 JSON 字符串。*

### 声明与使用
使用 `---@varSync` 注解在 Lua 中声明同步变量：
```lua
---@varSync intValue:int
---@varSync listSync:List<int>
---@varSync dictionarySync:Dictionary<int,string>
---@end
```

**修改与读取原则：**
1. 无法使用等号（`=`）直接赋值，必须使用 `SetValue()` 和 `GetValue()`。
2. **只有主权方**可以调用 `SetValue()` 修改同步变量。
3. 同步变量的有效值必须在 `OnNetSpawned` 生命周期之后才能可靠获取。

### 数据变化监听（OnValueChange）
当主权方修改变量后，所有客户端都会同步此变化，并可通过 `OnValueChange` 监听：
* 本地客户端 `SetValue()` 后，**立即触发**本地的 `OnValueChange`。
* 远端客户端在接收到网络同步数据后触发 `OnValueChange`。
* 即使没有被主动赋值，同步变量在 `OnNetSpawned` 之后也会自动触发一次 `OnValueChange` 以完成初始化同步。

**代码示例：**
```lua
function OnNetSpawned()
    -- 基础类型监听 (回调参数包含当前值和旧值)
    intValue:OnValueChange(function(curVal, preVal)
        print("intValue changed:", curVal, "from", preVal)
    end)

    -- List/Dictionary 监听 (回调无参数，需内部遍历获取)
    listSync:OnValueChange(function()
        listSync:ForEach(function(value, idx)
            print("list index:", idx, "value:", value)
        end)
    end)
end
```

### 初始化同步变量（NetSpawn 回调）
如果希望在动态创建网络对象（`NetSpawn`）时传入初始值，可以在 `NetSpawn()` 的回调函数中直接对同步变量进行赋值。
由于 `NetSpawn` 的回调时序位于目标对象的 `Awake` 之后、`OnNetSpawned` 之前，这样设置的初始值能够在所有客户端的 `OnNetSpawned` 执行时被正确获取。
