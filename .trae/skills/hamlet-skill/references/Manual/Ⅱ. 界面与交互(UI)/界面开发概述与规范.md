# 界面开发概述与规范

Douyin SDK 完整支持基于 Unity UGUI 系统的界面自定义开发。在进行 UI 设计和开发前，需遵循标准的分辨率、层级和渲染规范，以保证与官方系统界面的和谐共存。

## 场景与适用范围

> **适用范围**：当 [hamlet-preferences.md](../../../hamlet-preferences.md) 中 `DevTool=UnityEditor` 时阅读。
> DevTool 的详细说明请参考 [开发工具概述](../VI.%20开发工具/开发工具概述.md)。

- **自定义 2D/3D 界面**：需要为世界玩法搭建基础操作、导航、任务面板、弹窗等 UI 时查阅此规范。
- **界面层级冲突排查**：当自定义 UI 遮挡官方 UI，或被官方 UI 遮挡时，核对 Sort Order 规范。
- **画质表现优化**：当 UI 贴图在真机上出现模糊、边缘发虚等画质降级问题时，核对贴图压缩与渲染配置。

## UI 基础配置标准

> **适用范围**：当 [hamlet-preferences.md](../../../hamlet-preferences.md) 中 `DevTool=UnityEditor` 时阅读。
> DevTool 的详细说明请参考 [开发工具概述](../VI.%20开发工具/开发工具概述.md)。

- **UI 分辨率基准**：推荐使用 **1170 * 2532**。
- **Canvas Scaler 模式**：必须选择 **Scale With Screen Size** 以保证跨设备适配。
- **贴图生成规范 (避坑)**：
  - **问题场景**：移动端为了性能优化，默认会对超过 1024x1024 尺寸的纹理进行压缩，导致 UI 在中低画质下触发 Mip Map 降级，视觉表现模糊。
  - **解决方案**：在 Unity Project 窗口中选中所有的 UI Sprite 贴图，在 Inspector 面板中**取消勾选“Generate Mip Maps”**，确保 UI 纹理在任何画质下不被压缩降级。

## UI 层级 (Sort Order) 规范

为了保证三方世界`自定义界面`与`系统界面`不发生互相遮挡的冲突，UI 层级划分了明确的区间边界。开发者必须严格遵守以下 Sort Order 设定：

### 世界玩法 UI (底层)
- **Sort Order 区间**：`< -10` (推荐 `-100` ~ `-11`)
- **UI 类型**：UGUI
- **业务场景**：作为最底层的背景层，展示在官方主界面及角色 UI 之下。
- **典型内容**：世界 3D 场景物体上挂载的 2D UI 面板。

### 角色层与主界面 UI (官方保留)
- **Sort Order 区间**：`-10` ~ `0`
- **UI 类型**：系统原生 UI
- **业务场景**：官方保留层级，开发者不可占用此区间。
- **典型内容**：
  - `-10` ~ `-1`：角色昵称、角色聊天气泡。
  - `0`：系统主界面（包含操作区域、用户聊天区域）。

### 世界玩法 UI (上层)
- **Sort Order 区间**：`1` ~ `399`
- **UI 类型**：UGUI
- **业务场景**：展示在官方主界面之上，用于承载绝大多数三方世界的核心功能与弹窗。
- **层级细分建议**：
  - **Low (1 ~ 99)**：常驻型玩法主功能导航。
  - **Normal (100 ~ 199)**：展开式功能面板（如新手引导）。
  - **High (200 ~ 299)**：弹出式功能面板（如任务、背包、商城界面）。
  - **Top (300 ~ 399)**：高优先级通知弹窗（如更新公告、游戏内强提示）。

### 系统级应用层 UI (极高层级)
- **Sort Order 区间**：`400` 以上及无限高
- **UI 类型**：Native
- **业务场景**：系统最高优先级的界面，不可被遮挡。
- **典型内容**：
  - `400` ~ `499`：重要系统级通知弹窗（停服更新等）。
  - 无限高：平台功能 UI（相机、分享、横竖屏切换、表情动作、系统 Loading、通知弹窗等）。
  - **避坑**：此类 UI 无法通过 Sort Order 遮挡，若有特殊全屏玩法，只能通过特定的 API 接口进行动态隐藏或禁用（详见[系统界面](./系统界面.md)）。
