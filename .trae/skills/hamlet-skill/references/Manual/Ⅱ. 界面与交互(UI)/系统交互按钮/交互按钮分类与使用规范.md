# 交互按钮分类与使用规范

本项目有两类核心交互按钮：**基础交互按钮 (右侧中间区域)** 和 **操作按钮 (右下区域)**。

## 场景与使用边界

为更清晰地对比两者差异，请参考以下维度：

- **基础交互按钮 (右侧中间区域)**
  - **出现时机**：玩家靠近对象并获得对象焦点后。
  - **业务表达**：“我正在操作眼前这个具体对象”。
  - **典型操作**：拾取物品、坐上载具、打开箱门、与 NPC 对话等。
  - **UI 性质**：附着在场景对象交互流程上，随对象焦点出现和移除的临时交互按钮。
  - **使用限制**：不能用于进入玩法后的持续操作。
  - **实现参考**：调用 `self:AddInteractorButton()`。

- **操作按钮 (右下区域)**
  - **出现时机**：玩家进入当前玩法上下文后。
  - **业务表达**：“我正在执行当前玩法的主操作或副操作”。
  - **典型操作**：上升、下降、开火、瞄准、蓄力等。
  - **UI 性质**：全局共享的 `UIType.CustomMain` / `UIType.CustomSub` 槽位，不附着单个对象，服务于当前玩法。
  - **使用限制**：不能替代靠近对象后出现的交互按钮。
  - **实现参考**：接管 `UIType.CustomMain` / `UIType.CustomSub`。

## 移动端约定

本项目面向手游体验。存在键盘按键操作时，必须同时提供可点击的移动端入口；键盘操作可以不提供，但可点击按钮不能缺失。

- 需要靠近具体对象才能发起的操作，必须使用**基础交互按钮**提供点击入口。
- 进入玩法后持续可用的主、副操作，必须使用**操作按钮**提供点击入口。
- 右下区域按钮只有 `CustomMain` 和 `CustomSub` 两个全局共享槽位；进入玩法前应确认当前玩法可以占用对应槽位，并在退出时及时释放。
