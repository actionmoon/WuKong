# 基础交互按钮

“基础交互按钮”是本地玩家与非触发交互（如拾取、座位、通用交互）对象进行通信的唯一合法 UI 入口。它负责展示交互物当前已确认的业务状态，并接收玩家的本地输入请求。

## 场景与适用范围

- **通用交互入口**：实现拾取物品、坐上载具、开启机关等非触发类交互时使用。
- **业务状态展示**：需要通过按钮文案或状态来反映当前业务状态（如“开门”与“关门”切换）时。
- **多功能分发**：同一个交互物存在多个可选操作（如“对话”、“商店”、“启动机关”）时。

> **提示**：本文重点说明基础交互按钮的生命周期、事件模型与分发机制。具体代码实现与约束请参考 [非触发交互最佳实践](../../../Best Practice/基础交互/自定义交互-最佳实践.md)。

## 生命周期：创建、修改与销毁

基础交互按钮的生命周期必须严格遵循“焦点驱动”与“状态驱动”原则，它仅存在于本地客户端的 UI 层。

### 1. 创建 (Creation)
- **触发时机**：玩家进入交互区域且满足业务条件时调用 `EnableInteraction()`，随后平台在合适的时机下发 `OnFocus` 回调。
- **执行动作**：在 `OnFocus` 中调用 `AddInteractorButton` 创建按钮，并绑定当前语言和状态对应的初始文案。
- **边界红线**：禁止在对象初始化 (`OnInit`/`Awake`)、网络状态回调或 `OnInteract` / `OnPickup` 等全端表现回调中创建按钮，否则会导致玩家在范围外看到按钮。

### 2. 修改 (Modification)
- **触发时机**：当主权方裁决并更新了同步业务状态（Business State）后，本地客户端监听到状态变化时。
- **执行动作**：幂等地刷新当前焦点按钮的表现（如修改文案、图标，或置灰、隐藏）。
- **边界红线**：禁止在点击按钮时为了反馈而立即强行改写文案来模拟成功（如点击“开门”立刻改为“关门”）。网络请求可能被拒绝或延迟，UI 修改必须完全由已确认的业务状态派生。

### 3. 销毁 (Destruction)
- **触发时机**：玩家离开范围调用 `DisableInteraction()`，或对象被禁用、销毁时，平台下发 `OnLostFocus` 回调。
- **执行动作**：在 `OnLostFocus` 中必须调用 `RemoveInteractorButton` 移除所有已创建的按钮，注销本地监听，并**清空所有按钮引用**。
- **边界红线**：清理逻辑必须可重复调用，避免失焦和对象禁用连续到来时重复移除同一按钮或保留失效引用。

## 响应事件模型

按钮点击属于纯粹的本地输入，只负责向平台或主权方发送请求，不直接执行跨端表现。Lua 和 C# 在事件响应模型上存在差异：

| 语言环境 | 事件响应模型 | 核心机制与约束 |
| --- | --- | --- |
| **Lua** | 集中式索引回调 | 平台触发组件级回调 `OnInteractorButtonClick(index)`。开发者需要通过 `index` 判断点击了哪个按钮。 |
| **C#** | 对象级事件监听 | `AddInteractorButton()` 返回一个 `Button` 实例，需单独为其注册 `onClick.AddListener(...)`。**注意：C# 不会自动派发同名 `OnInteractorButtonClick` 回调。** |

**点击响应边界**：
- 点击时应重新获取当前本地 Actor（通过缓存的 ID，而非长期引用），并做轻量本地预检（如是否冷却中）。
- 预检通过后，仅调用对应的平台 API（如 `Pickup` / `SitDown` / `Interact`）。

## 多按钮分发与跨端路由

当同一个对象上存在多个交互入口（如“对话”、“商店”、“启动机关”）时，必须遵循“本地分发，跨端带参”的原则。

### 1. 本地事件分发
多个按钮的点击来源只存在于本地按钮入口，必须在本地完成路由分发：
- **Lua**：根据 `OnInteractorButtonClick` 传入的 `index` 进行分支处理。
- **C#**：根据不同的 `Button.onClick` 监听器直接进入对应的处理函数。

### 2. 跨端动作路由 (Action ID)
平台的基础网络回调 `OnInteract(actor)` **不包含按钮索引**。因此，不能依赖它来判断远端玩家点击了哪个按钮。

- **共同表现**：若多个按钮只需触发同一种全端对象效果（如不管点什么，门都会闪一下），可在本地分发后调用一次无参的 `Interact`。
- **差异化业务（动作裁决）**：若不同按钮在远端执行不同业务（如“买东西”与“接任务”），**绝不能**只调用无参数的 `Interact`。
- **标准做法**：通过项目已有的 RPC、主权消息或同步变量，额外传递一个稳定的 **动作 ID (Action ID)**。主权方按动作 ID 和当前业务状态裁决，所有端再由状态变化刷新最终结果。

## 例外场景：纯本地交互
存在少数可以直接在按钮点击时执行的例外场景，这些例外**不经过**联网状态裁决，也不会广播给远端：
- 打开仅当前玩家可见的说明面板或 UI 菜单。
- 触发本地镜头切换、拍照模式或引导高亮。
- 调整不影响其他玩家的设置页。

*(注：除上述纯本地表现外，任何涉及发放奖励、改变公共状态、占用交互物的行为，必须进入标准的“请求 -> 全端确认”链路。)*
