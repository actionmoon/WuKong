# 脚本开发概述

抖音虚拟世界 SDK 基于 Unity 引擎运行，为了支持创作者动态添加游戏世界和玩法内容，平台提供了强大且灵活的脚本开发能力。当前环境支持 **Lua 脚本**与 **C# 脚本**混合开发，满足从简单交互到复杂架构的各类需求。

## 核心脚本语言支持

### 1. Lua 脚本 (推荐)
- **版本支持**：SDK 内置支持 **Lua 5.3**，具有运行速度快、安全性高且易于使用的特点。
- **特性**：平台将大量 UnityEngine 的 API 及虚拟世界的独有能力映射到了 Lua 侧，允许通过极其轻量级的方式控制逻辑。
- **挂载方式**：无法直接挂载在 GameObject 上，需要依赖 `Douyin Script` 容器组件进行桥接。
- **相关文档**：[Lua 脚本开发](Lua脚本/Lua脚本开发.md) 

### 2. C# 脚本 (进阶/服务端架构)
- **特性支持**：平台支持直接编写 C# 脚本，高度还原了在原生 Unity 下的开发体验，包括继承 MonoBehaviour 生命周期等能力。
- **网络架构分离**：C# 脚本被严格划分为客户端与共享库（`GameScripts`）和服务端专属库（`ServerScripts`），极大地提升了 Dedicated Server (DS) 模式下的服务端代码隐蔽性与安全性。
- **网络库能力**：提供基于 `NetworkBehaviour` 的网络对象与 `[Rpc(SendTo.xxx)]` 的高层级通信封装。
- **相关文档**：[C# 脚本开发](CSharp脚本/CSharp脚本开发.md)

## 脚本在虚拟世界中的定位

无论是使用 Lua 还是 C#，脚本的核心作用是：
1. **控制对象生命周期**：监听玩家进入 (`OnPlayerJoined`)、化身生成 (`OnActorSpawned`) 等虚拟世界事件。
2. **处理网络同步**：操作同步变量（如 `NetworkVariable`）和发起 RPC（如 `DouyinRemoteEvent`），维护多端状态一致性。
3. **调用核心系统 API**：操作商业化接口 (`DouyinMarketingService`)、数据存储 API (`DataStoreService`) 以及处理主权和控制权转移 (`RequestOwnership`)。

在后续开发中，建议逻辑较轻的业务玩法可以使用 Lua 实现，而针对 Dedicated Server 复杂的服务端校验逻辑及数据落库，推荐使用 C# 脚本结合 `ServerScripts` 目录进行构建。

## C# 与 Lua 的核心生命周期映射

无论是哪种语言，只要脚本作为组件挂载在网络对象上，都会遵循平台提供的网络生命周期。两者的核心映射关系如下：

| 阶段 / 行为 | Lua (`DouyinScript`) | C# (`NetworkBehaviour`) | 说明 |
| --- | --- | --- | --- |
| **脚本挂载方式** | 通过 `Douyin Script` 代理组件挂载 | 直接将 C# 类拖拽至 GameObject 上 | Lua 脚本实际上是作为一个资源被代理执行的 |
| **网络对象初始化** | `function OnNetSpawned()` | `public override void OnNetworkSpawn()` | 同步变量和 RPC 通信仅在此事件触发**之后**才有效 |
| **网络对象销毁** | `function OnNetDestroy()` | `public override void OnNetworkDespawn()` | 对象被网络销毁或玩家退房时触发 |
| **帧更新** | `function Update()` | `private void Update()` | 每帧执行。Lua 如需帧间隔请在函数体内读取 `CS.UnityEngine.Time.deltaTime`；C# 端直接使用 Unity 的原生 `Update` |
| **主权变更** | 无内置专有回调 | `protected virtual void OnOwnershipChanged(ulong pre, ulong cur)` | 监控对象的主权（写权限）发生转移时的事件 |

## 编码约束与开发规范

无论是编写 Lua 还是 C# 脚本，在执行时都受底层沙箱引擎的严格管控（包括异步逻辑包裹、第三方库限制、API 黑名单等）。
- 详情请查阅全局统一的：**[编码约束与开发规范](../编码约束与开发规范.md)**
