# 编码约束与开发规范 (Coding Constraints)

在抖音虚拟世界开发中，为了确保世界逻辑的安全、稳定和数据的一致性，平台制定了一系列底层的开发约束。所有创作者必须严格遵守相关模块的开发约束，否则可能会导致逻辑异常、数据丢失或触发报错。

为了便于查阅和建立心智模型，详细的开发约束已按照引擎底层架构和业务模块进行了体系化分类。您可以根据当前正在开发的模块，快速定位到对应的规范指南与避坑法则。

## Ⅰ. 核心系统 (Core)

核心系统涵盖了玩家形象、物理引擎、相机服务以及复杂实体的底层交互边界。

- **[Actor 模式开发约束](./编码约束与开发规范/Actor模式开发约束.md)**：详述合养精灵 (Pet) 与虚拟形象 (Avatar) 模式的严格界限、操作态与网络主权的区分，及专属 API 避坑指南。
- **[触发器生命周期约束](./编码约束与开发规范/触发器生命周期约束.md)**：规范 `OnActorTriggerEnter/Exit` 的本地玩家校验与状态清理越权边界，确保交互不被其他实体污染。
- **[多输入源与 UI 协作约束](./编码约束与开发规范/多输入源与UI协作约束.md)**：统一汇集官方摇杆、WASD 与 Runtime UI 输入状态的闭环规范，确立业务模组的输入主权。
- **[相机服务开发约束](./编码约束与开发规范/相机服务开发约束.md)**：规范 `DouyinCameraService` 的合法入口、空值兜底要求以及 `LateUpdate` 的时序控制。
### 物理子系统 (Physics)
- **[物理对象层级约束](./编码约束与开发规范/物理对象层级约束.md)**：详述可踩层 `Default(0)` 与防带飞道具 `Props(6)` 的互斥原则及显性递归设置约束。
- **[物理结算与实体去重约束](./编码约束与开发规范/物理结算与实体去重约束.md)**：规定基于“玩法实体”级别的物理碰撞与触发去重，严禁同一物理帧内同步重开结算窗口，避免重复计分。
- **[刚体运动控制约束](./编码约束与开发规范/刚体运动控制约束.md)**：定义处理 `Rigidbody` 物理运动时的强制规则，包含 `FixedUpdate` 唯一时机、前置守卫、以及避免参数混用等要求。
- **[碰撞与触发器规范](./编码约束与开发规范/碰撞与触发器规范.md)**：规范 `Collider` 和 Trigger 交互边界，涵盖触发器回调单一入口原则、组件同层级挂载及运行期显式 Layer 过滤。

## Ⅲ. 逻辑与脚本 (Logic&Scripting)

规范了代码运行时的安全边界与沙箱限制。

- **[脚本开发约束](./编码约束与开发规范/脚本开发约束.md)**：涵盖 C# 生命周期内的异步包裹规则、Lua JSON 解析 `dkjson` 规范及沙箱 API 黑白名单的越权拦截机制。

## Ⅳ. 多人游戏与网络 (Multiplayer)

多人联机玩法中，确保各端状态一致性的核心契约。

- **[网络开发约束](./编码约束与开发规范/网络开发约束.md)**：包含同步变量仅限主权写入限制、主权申请的固定判定顺序 (`isNetworkSettled` → `HasOwnership` → `RequestOwnership`)、RPC 非可靠性本质以及网络对象的正确生命周期用法。
