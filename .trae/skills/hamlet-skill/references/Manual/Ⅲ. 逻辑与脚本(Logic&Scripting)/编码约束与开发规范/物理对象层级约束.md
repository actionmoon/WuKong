# 物理对象层级约束

## 1. 概念 (Concept)
在处理带 `Rigidbody` 的自由刚体（如移动平台、可推道具）时，玩家与物体的物理接触（踩踏、推挤）高度依赖引擎的层级 (Layer) 设置。

## 2. 机制与配置 (Mechanism & Configuration)
- **显性且递归设置**：必须在初始化的 `Start` 阶段显性、从根节点开始递归地把所有子节点的 layer 设到目标值。不要依赖引擎的自动层级，也不要只设根节点（自由刚体常由多个子碰撞体组成，只设根节点，必定导致子碰撞体判定失效）。

### 层级配置对比表 (Layer Configuration Comparison)

| 对象类型 | 适用场景 | 目标 Layer | 交互表现 |
| :--- | :--- | :--- | :--- |
| **载人移动平台 / 升降台** | 需要带玩家移动的平台 | `Default(0)` (可踩层) | 玩家站上去后才会被正确带走 |
| **防带飞道具** | 球、冰球、可推道具 | `Props(6)` (物理道具层) | 禁止玩家站上去被顶飞，但保留实体碰撞（可踢可推） |

## 3. 黄金法则与避坑指南 (Golden Rules & Pitfalls)
- **🚫 避坑：严禁使用屏蔽接口防顶飞**
  禁止使用 `Physics.IgnoreCollision`、关碰撞体或 `Ignore Raycast(2)` 来实现防顶飞。这会导致撞墙、进球判定、射线检测全部失效。**防顶飞的唯一正确做法是设为 `Props(6)`。**
