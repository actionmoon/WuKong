# 角色控制开发规范与避坑指南

本文规定 `DouyinActor` 移动、飞行和游泳脚本的通用开发方式，适用于 Lua 和 C#。角色 API 说明见[角色移动、飞行与游泳](../../Ⅰ.%20核心系统%28Core%29/玩家网络对象/角色控制/角色移动、飞行与游泳.md)，Lua 专项实现见移动目录下的三个 Best Practice 文档。

## 一、通用角色控制开发规范

- 角色自身的移动、速度、飞行和游泳业务只对本地玩家执行；入口先判断对象非空和 `actor.isLocal`。
- 远端角色的移动和飞行表现由网络同步驱动，不要修改远端 Actor 的本地控制属性。
- 载具、骑行生物和场景 `Rigidbody` 使用各自的运动实现，不使用玩家角色 API 接管物理。
- `MoveContinuously`、飞行权限、飞行状态和事件监听都要有对应的退出或清理路径，并在 `OnDestroy()` 中兜底。
- 角色事件使用 `AddListener` 注册、`RemoveListener` 精准解绑，保存同一回调引用；不要使用 `RemoveAllListeners()` 清理其它模块的订阅。
- 交互、拾取等全端表现不能因为 `isLocal` 被整体跳过；只有本地 UI、输入和角色自身状态使用本地判断。
- `actor.speed` 是本地角色控制属性，不要为修改它单独套用网络对象主权申请流程。

## 二、移动开发规范

- `MoveContinuously` 结束时调用 `StopMove()`；`Immobilize(true)` 只禁止摇杆，完全冻结还需处理跳跃、拾取和座位入口。
- 强制修改角色位置使用 `Teleport`，不要直接写入 `actor.gameObject.transform.position`。
- `OnPickup` / `OnDrop` 的挂手、父节点和物理表现对任意非空 Actor 执行；只有本地角色效果才额外判断 `isLocal`。
- 移动和变速的 Lua 代码、参数和排错方式见[基础移动-Lua](../../../Best%20Practice/移动/基础移动-Lua.md)。

## 三、飞行开发规范

- `EnableFly`、`DisableFly`、`StartFly`、`StopFly` 和 `SetFlyMode` 只对本地玩家执行。
- `DisableFly` 只管理权限和按钮，`StopFly` 只管理当前飞行状态；需要同时限制时分别处理。
- `StartFly` 前检查 `CanFly()`；座位或其它上下文退出时，恢复飞行权限前再次检查 `CanFly()`。
- 起飞后立即落地通常表示房间或角色配置不允许飞行，不要优先归因于起飞高度或 UI。
- 一个玩法上下文内统一使用 `DisableFly(true)` 或 `DisableFly(false)`。
- `DisableFly(true)` 只隐藏按钮并限制权限，不会让正在飞行的玩家落地；需要落地时同时调用 `StopFly()`。
- 进入座位时禁飞，离座时只有 `CanFly()` 为真才恢复 `EnableFly()`。
- `onFlyStart` / `onFlyStop` 必须用 `AddListener` / `RemoveListener` 配对，不能使用 `+=` 或 `RemoveAllListeners()`。
- 飞行载具和骑行飞行生物使用专用运动实现，不要用玩家 Actor 飞行 API 替代。
- 飞行的 Lua 代码骨架见[飞行-Lua](../../../Best%20Practice/移动/飞行-Lua.md)。

## 四、游泳开发规范

- 游泳由水体被动触发，不要查找或调用不存在的 `StartSwim`。
- `CanSwim()` 为 `false` 时不能通过业务脚本强制开启游泳；`IsSwimming()` 异常时先检查房间和角色配置。
- `onSwimStart` / `onSwimStop` 必须用 `AddListener` / `RemoveListener` 配对，不能使用 `+=` 或 `RemoveAllListeners()`。
- 游泳期间的拾取、技能和自定义交互限制必须在实际业务入口判断 `IsSwimming()`，不能只隐藏按钮。
- 游泳期间禁飞时，在结束事件中先检查 `CanFly()` 再恢复飞行权限。
- 游泳事件和业务互斥规范已在本节说明，Lua 代码骨架见[游泳-Lua](../../../Best%20Practice/移动/游泳-Lua.md)。
