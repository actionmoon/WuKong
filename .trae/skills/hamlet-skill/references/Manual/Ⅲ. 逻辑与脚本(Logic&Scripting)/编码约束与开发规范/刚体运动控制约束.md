# 刚体运动控制约束

本约束定义了在处理 `UnityEngine.Rigidbody` 及物理运动时的强制规则。任何物理运动开发均必须遵守本指南，以避免物理引擎状态错乱、表现异常或性能问题。

---

## 刚体通用硬约束（12条）

以下约束在所有 Rigidbody 相关代码里都成立。

1. **`FixedUpdate` 唯一时机**：主动驱动 velocity / MoveRotation 必须放在 `FixedUpdate`，不要放 `Update` / `LateUpdate`，否则物理时序与物理引擎错位。
2. **前置守卫**：写入前必须做 nil-guard 与 `isKinematic` 判断：
   - `if rb == nil then return end`
   - `if rb.isKinematic then return end` —— **Kinematic 刚体不允许直接写 velocity**，写了物理引擎会报错或行为异常。
   - 若消费玩家输入：`if moveVec == nil then return end`。
3. **`velocity` 写回保留 y 分量**：除非物体完全脱离重力并由脚本接管三轴，写入最终速度时**绝对不能覆盖 y 轴速度**：
   ```lua
   -- 正确示例：保留原本的 y 轴下落速度
   rb.velocity = CS.UnityEngine.Vector3(horizontalVel.x, rb.velocity.y, horizontalVel.z)
   ```
4. **旋转用 `MoveRotation`**：用 `rb:MoveRotation(Quaternion.Euler(x, y, z))` 旋转物体，**不要**直接写 `transform.rotation` —— 直写会与刚体物理状态不一致，产生抖动或穿墙。
5. **XLua 四元数用 `*` 运算符**：`rot1 * rot2` 才是合法写法；`Quaternion.op_Multiply(rot1, rot2)` 在 XLua 中会抛 `attempt to call a nil value`，直接崩当前帧 `FixedUpdate`。
6. **水平限速用剥离 y 的水平向量**：`Vector3.ClampMagnitude(rb.velocity, max)` 会把重力赋予的下落速度强制归零，导致物体在空中漂浮或下坡卡顿。正确做法是先剥离 y 分量算 `ClampMagnitude`，再拼回 y。
7. **禁止 velocity 与 AddForce 混写**：两种物理模型（`velocity` 直写 vs 力累加）的 `drag` / `mass` 语义完全不同，混用会导致物体运动失控或参数失效；一个脚本选一种模型贯彻到底。
8. **玩家输入驱动时 W/S 双轴消费**：必须**同时**消费 `moveVec.x`（转向）与 `moveVec.y`（前进 / 倒车）；只消费其中一轴会导致"UI 加速按钮生效但 WASD 变哑"。
9. **禁止同帧直写 transform + 写 rb.velocity**：两条通路会互相覆盖，且直写 transform 与刚体状态不一致，Unity 物理引擎行为未定义。"WASD 有采样但实体不动"时禁止用"顺便直接改 transform 试一下"当作 hotfix；正确做法是只走 `rb.velocity` + `rb:MoveRotation` 一条通路排查。
10. **一次性施力配冷却**：`AddForce` / `AddTorque` 一次性施加时必须配短冷却（如 `0.1s`）防连发；但冷却时长不能大到把玩家 "再碰一次" 的合法交互也吞掉。
11. **本地物理不套主权门禁**：`AddForce` / collision 施力**不卡** `HasOwnership` / `isNetworkSettled`，否则单机或网络未 settled 时物体会"踢不动"。
12. **禁止 `FixedUpdate` 每帧 clamp `rb.velocity` 当"防顶飞"**：直接表现为"踢不动"。防顶飞应通过 Layer 分类解决；如真要限制最大角速度，用 `rb.maxAngularVelocity` **一次性配置**。

---

## 静态参数的修改边界

普通物理对象的静态参数（`mass`、`drag`、`angularDrag`、`centerOfMass` 等）是单一事实源：

- **资源配置优先**：优先通过对象 属性面板 配置。
- **禁止无条件覆写**：不应在 `Start` / `Update` 中无条件覆写这些参数。如果 Lua 里写了覆写，编辑器改动将失效，导致无法调参。
- **允许的生命周期切换**：`useGravity` / `isKinematic` 可在进入特定玩法（如进入座位、被拾取）时切换，但必须由对应的退出回调（如离座、放下）**显式恢复**到初始值。
