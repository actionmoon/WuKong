# 数据持久化与数据库开发约束

## 1. 概念 (Concept)
平台提供了 DataStore 和 OrderedDataStore 用于处理玩家数据的云端持久化存储，操作均为异步网络请求。

## 2. 规范 (Specification)
- **增量操作参数类型**：调用 `IncrementAsync` (增量更新) 时，其 `delta` 参数必须是 `double` 类型，不要将其声明为 `int` 或 `long`。
- **异步包裹规范 (Lua)**：在 Lua 中执行任何 DataStore 增删改查时，必须包裹在 `DATASTORE(function() ... end)` 中处理异步返回。若未包裹，平台将直接抛出 `-10034` 错误码。

## 3. 黄金法则与避坑指南 (Golden Rules & Pitfalls)
- **💡 黄金法则：安全的读取方式 (C#)**
  当不确定 Key 是否存在时，必须优先使用 `TryGetAsync<T>`。直接使用 `GetAsync<T>` 在找不到 Key 时会抛出 `DataStoreRemoteException`。**新号注册等正常业务分支绝对不要依赖异常捕获来流转**。
- **🚫 避坑：JSON 长度限制**
  尽管泛型的 `SetAsync<T>` 会自动进行 JSON 编解码，但业务层必须在存入前预估序列化后的文本长度。一旦超过单 Value 约 6000 字符的上限，写入将被直接拒绝，导致数据丢失。
