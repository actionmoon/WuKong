# 脚本沙箱与运行时开发约束

## 1. 概念 (Concept)
无论是编写 Lua 还是 C# 脚本，在执行时都受底层沙箱引擎的严格管控，以确保平台安全和运行稳定。

## 2. 边界 (Boundary)
- **API 黑白名单**：所有的 UGC 业务脚本在运行时都会进行 SDK 沙箱检查，一旦调用了不在 SDK 白名单内的方法或反射接口，将直接被拦截并报沙箱越权错误。
- **C# 工程目录隔离**：
  - `GameScripts`（客户端/共享）：**严禁**访问 `ServerScripts` 程序集中的任何类型。打包客户端包体会时，`ServerScripts` 会被物理裁剪，强行访问将导致编译报错。
  - `ServerScripts`（DS服务端专属）：挂载在此节点（及其子节点）的组件在客户端 AssetBundle 中会被自动剔除。

## 3. 机制与规范 (Mechanism & Specification)
- **JSON 解析 (Lua)**：在 Lua 项目中处理 JSON 序列化与反序列化时，**需要使用内置的 `dkjson` 库**，禁止直接使用 `require("cjson")` 以免触发沙箱黑名单拦截。
- **C# 与 Lua 核心网络生命周期映射**：
  - 网络初始化：Lua `OnNetSpawned()` <=> C# `OnNetworkSpawn()`。**注意**：同步变量和 RPC 通信仅在此事件触发**之后**才有效。
  - 网络销毁：Lua `OnNetDestroy()` <=> C# `OnNetworkDespawn()`。

## 4. 黄金法则与避坑指南 (Golden Rules & Pitfalls)
- **🚫 避坑：异步包裹 (C#)**
  不要在 Unity 的原生生命周期函数（如 `Start`、`Update`）或回调事件中编写裸 `async void`。若必须在生命周期内触发异步逻辑（如请求 DataStore 数据库或拉取排行榜），请使用 `_ = XxxAsync();` 并在内部包裹完整的 `try / catch` 逻辑，以防止异常逃逸导致当前帧或后端进程卡死。
