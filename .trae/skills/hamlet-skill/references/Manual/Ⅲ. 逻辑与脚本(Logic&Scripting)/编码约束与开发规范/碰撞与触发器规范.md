# 碰撞与触发器规范

本约束定义了在处理 `UnityEngine.Collider`、Trigger 交互及 Layer 碰撞矩阵时的强制规则。任何涉及物理接触、触发器回调与物理过滤的开发均必须遵守本指南。

---

## 一、 触发器与回调的单一入口原则

当底层物理事件（Trigger / Collision 等）被用于**得分、命中、拾取、通关、伤害**等玩法结算时，必须遵守单一入口原则，避免产生重复结算。

1. **同源互斥**：一次玩法事件应该**由与 Collider 类型匹配的单一入口驱动**。不要把同一套业务同时接到实体碰撞（Collision）和触发器（Trigger）入口——同一次接触可能会同时触发两者，导致业务逻辑重复执行。
2. **入口选择**：
   - 实体碰撞反馈（如：篮球拍击、推箱施力）：仅使用 `OnActorCollisionEnter`。
   - 范围交互（如：拾取按钮、靠近提示）：仅使用 `OnActorTriggerEnter/Exit`。
3. **慎用 Stay**：`OnTriggerStay` / `OnActorCollisionStay` **不能**作为一次性结算的主路径，除非需求明确要求持续效果并已配套去重逻辑。

---

## 二、 Hamlet Actor 回调的组件层级约束

在 Hamlet 平台下，Actor 回调事件的冒泡机制与 Unity 原生物理有所不同。

1. **同节点挂载**：负责接收回调的 `DouyinScript` / `DouyinScriptBehaviour` 必须与产生该回调的目标 `Collider` 挂在**同一个 `GameObject`** 上。
2. **不会自动冒泡**：父节点上的脚本不会自动接收子节点 Collider 产生的 Hamlet Actor 回调（如 `OnActorTriggerEnter`）。“脚本在 Root、Trigger 在 Child” 是常见的失效拓扑。
3. **正确做法**：推荐让负责回调的脚本与对应的 Trigger 或实体 Collider 处于同节点，视觉 Mesh 可以继续放在子节点。

---

## 三、 Layer 运行时设层约束

带有 Rigidbody 的自由刚体，其碰撞层在运行时具有不确定性（引擎可能自动重置 Root 层）。因此，**不能仅靠静态配置生效**。

1. **必须显性设层**：如果目标层是 `Props(6)` 或其他非 `0` 和 `9` 的值，必须在 `Start` 里显性调用 `SetLayer`。不能依赖“编辑器里设过”。
2. **必须递归**：只设 Root 会漏掉子碰撞体，必须递归地把整棵子树都设到目标层。
   ```lua
   -- 递归设层示例
   local function setLayerRecursive(trans, layer)
     trans.gameObject:SetLayer(layer)
     for i = 0, trans.childCount - 1 do
       setLayerRecursive(trans:GetChild(i), layer)
     end
   end
   ```
3. **二选一互斥**：
   - 载人平台设 `Default(0)`，让踩地检测命中。
   - 防带飞物体设 `Props(6)`，让踩地检测穿过。
   - **禁止**用 `IgnoreRaycast(2)` 防顶飞，这会破坏射线检测（如进球判定、相机遮挡）。

---

## 四、 碰撞过滤优先级

当需要屏蔽两个物体之间的实体碰撞（例如：挡板不与球门门框相互挤压）时，按以下优先级选择方案：

### 1. 首选：Pair-wise 过滤 (`Physics.IgnoreCollision`)
```lua
CS.UnityEngine.Physics.IgnoreCollision(colliderA, colliderB, true)
```
- **优点**：只影响这对 Collider，不误伤其他物体；同时保留 Trigger 触发能力。
- **注意**：若一方是复合模型，需要**遍历所有子 Collider** 逐对调用。
- **有限重试**：跨资源的 pair-wise 过滤需要两方资源都准备好，因此在 `Start` 中应实现有限重试（如尝试6次，每次间隔 0.5s），达到上限后标记阻塞，不要无限轮询或降级为“仅屏蔽事件”。

### 2. 备选方案：Layer 全局过滤 (`Physics.IgnoreLayerCollision`)
- **缺点**：产生全局副作用，影响所有属于这两个 Layer 的物体对。
- **要求**：只在明确规划过、且确认没有跨资源误伤时才使用。

### 3. 常见过滤误区
- **不要用 `SetLayer(2)` 代替过滤**：`IgnoreRaycast` 影响射线，不影响实体推挤。
- **不要在回调里过滤**：“只过滤事件不上报”但实体碰撞仍在发生，会导致明显的视觉抖动。
- **不要关闭 Collider**：将 `Collider.enabled = false` 用来“防顶飞”是错误的，会丢失撞地、撞墙能力（防顶飞应使用 `Props(6)` Layer）。
