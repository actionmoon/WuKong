# 网络概述

抖音虚拟世界 (Douyin World) 是一个多人在线的互动平台，处理好多端之间的数据互通、状态同步和逻辑仲裁是多人游戏开发的核心。

本章节系统性地阐述了平台提供的强大网络能力。整个网络与多人游戏模块由浅入深分为三大核心板块：**网络模型**决定架构底座，**网络基础**定义对象与权限，**数据与通信**提供状态同步与消息传递的手段。您可以根据需求查阅对应的子文档：

## 一、 网络模型 (Network Models)

网络模型决定了您的游戏将以何种架构运行。Douyin World 提供了从单机到强竞技网游的多种底层架构支持，不同模式下在网络对象管理、防作弊和代码组织上有着本质的区别：

- **[网络模型概述](./网络模型/网络模型概述.md)**：包含各网络模型的横向对比以及架构选型的“黄金法则”。
- **[Single Player (单机模式)](./网络模型/网络模型-Single%20Player.md)**：纯本地或弱联网模式。
- **[Shared Mode (共享模式)](./网络模型/网络模型-Shared%20Mode.md)**：分布式计算，多端协同。房间无独立服务器，逻辑分散在各个客户端，依靠主权机制防并发，适合休闲社交。
- **[Dedicated Server (DS 模式)](./网络模型/网络模型-Dedicated%20Server.md)**：中心化权威节点。官方托管独立服务器，负责反作弊与核心逻辑仲裁，安全性极高，适合强竞技与商业化玩法。
- **[Shared Mode 升级到 DS 模式](./网络模型/SharedMode%20模式升级到Dedicated%20Server模式.md)**：指导开发者如何在验证玩法后，将分布式游戏平滑重构为强安全性的 DS 服务端架构。

## 二、 网络基础 (Network Basics)

网络对象是多人游戏的基础单位，凡是需要多人共享状态的物体都必须是网络对象（挂载 `DouyinNetworkGuid`）。理解对象的创建、权限流转与异常恢复是开发的基石：

- **[主权与控制权](./网络基础/主权与控制权.md)**：深入解析“谁有权修改对象（主权）”与“谁在操作对象（控制权）”的分离与流转机制。
- **[网络对象的动态创建](./网络基础/网络对象的动态创建.md)**：阐述使用 `NetSpawn` / `ServerSpawn` 等专属接口动态生成网络对象的使用规范。
- **[断线重连机制](./网络基础/断线重连机制.md)**：详细说明玩家断线、杀进程退房时的底层网络行为，以及主权自动转移与归还的流转逻辑。

## 三、 数据与通信 (Data & Communication)

为了在不同客户端、或是客户端与服务器之间传递数据，平台提供了“状态同步”与“事件通知”两大核心能力：

- **[同步变量](./数据与通信/同步变量.md)**：
  - **核心状态同步机制**。当值变化时自动在多端同步。
  - **特性**：写前必须校验主权；平台保证最终一致性；新加入玩家或断线重连能自动拉取最新数据快照。
- **[RPC 通信概述](./数据与通信/RPC/RPC%20概述.md)**：
  - **事件通知机制**。事件驱动，即时发送，适用于次要的通知类消息（如播放动作、特效），不保证绝对送达。
  - **[SendMessage](./数据与通信/RPC/SendMessage.md)**：客户端之间的通信通道，适用于 Shared Mode 和 DS 模式的端到端广播与委托。
  - **[RemoteEvent](./数据与通信/RPC/RemoteEvent.md)**：DS 模式专用的**异步单向**通信通道（Client ⇄ Server）。
  - **[RemoteFunction](./数据与通信/RPC/RemoteFunction.md)**：DS 模式专用的**异步双向**通信通道（Client ⇄ Server，带有结果回调）。

以下是不同数据通信方式的特点、使用场景及注意事项：
| 通信方式 | 特点 | 适用场景 | 注意事项 |
| --- | --- | --- | --- |
| **同步变量** | - 变量值变化时自动同步<br>- 定时同步，存在延迟 | 持续存在的状态值（生命值、得分、道具数量） | - 写前必须确认主权<br>- 平台确保最终一致性，断线重连拉取最新数据 |
| **RPC 调用 (SendMessage)** | - 事件驱动，主动调用<br>- 实时性高 | 次要通知类消息（游戏开始提示、播放动作等） | - 不保证接收方一定能收到<br>- 如需确保数据一致性，请务必使用同步变量 |
| **RemoteEvent / RemoteFunction** | - 事件驱动，C/S 双向<br>- 实时性高 | DS 模式下跨端的指令传递（客户端触发操作 → 服务端校验） | - 只用于 DS 模式<br>- 基于 TCP，可靠传输，但不补发断线消息 |
