# 网络对象的动态创建

在 Douyin World 中，网络对象分为**静态网络对象**和**动态网络对象**。动态网络对象必须通过专门的 API 进行孵化（Spawn），不能使用 Unity 原生的 `GameObject.Instantiate`。

## 一、 静态网络对象与动态网络对象

- **非网络对象**：用 `GameObject.Instantiate` 创建的对象，不支持同步变量和 RPC 消息。
- **静态网络对象**：默认放置在 Unity 场景里的网络对象，它们属于“房间网络对象”，与房间同生共死。
- **动态网络对象**：在运行时动态创建的网络对象，分为两类：
  1. **通过 `DouyinObjectService.NetSpawn` 创建**：属于“房间级网络对象”，与房间存在时间相同。即使创建者下线，它也不会自动销毁，必须显式调用 `DouyinObjectService.NetDestroy` 进行销毁。
  2. **通过 `DouyinActor.NetSpawn` 创建**：属于“玩家绑定网络对象”。当创建它的玩家 Actor 销毁时，该对象也会自动销毁（例如玩家的血条）。

---

## 二、 房间级对象的动态创建 (DouyinObjectService.NetSpawn)

使用 `DouyinObjectService.NetSpawn` 创建出来的是**动态房间网络对象**。任何一端执行创建后，房间内所有客户端都会同步生成该对象。

### 1. 创建前提

> **适用范围**：当 [hamlet-preferences.md](../../../../hamlet-preferences.md) 中 `DevTool=UnityEditor` 时阅读。
> `DevTool` 的详细说明请参考[开发工具概述](../../VI.%20开发工具/开发工具概述.md)。

- **Prefab 必须是网络对象**：挂载了 `DouyinScript` (Lua) 或 `DouyinMonoBehaviour` (C#)。
- **必须配置资源映射**：在 `DouyinWorldRoot.NetSpawnObjectAsset` (Douyin Net Spawn Object Asset) 中配置 `key -> Prefab` 的映射关系。API 调用时传入该 `key`。

### 2. 双端语言接口差异
- **Lua 接口**：`DouyinObjectService.NetSpawn(key, function(go, id) end)`。
  回调在创建端本地执行，时机介于 `Awake` 和 `OnNetSpawned` 之间，适合注入创建者 ID 等初始参数。
- **C# 接口**：`GameObject NetSpawn(string key, out int id, Action<GameObject, int> onSpawn = null)`。
  **注意：C# 的 `NetSpawn` 是同步返回 GameObject 的。** 但返回的 GameObject 上 `NetworkVariable` 尚未从服务端同步，**不能立即读取**，初始化逻辑应写在回调 `onSpawn` 或自身的 `OnNetworkSpawn` 中。

### 3. SharedMode 与 DedicatedServer 模式下的创建差异

| 维度 | SharedMode | DedicatedServer (DS) |
| --- | --- | --- |
| **创建发起方** | 任何客户端均可调用创建 | **建议由 DS 服务端调用**创建 |
| **初始主权** | 归属于调用创建的客户端 | 初始主权归服务端 |
| **主权请求与保护** | 主权可自然流转，通常不需要严格拦截 | **必须在脚本中显式拒绝主权请求**，否则默认放行，导致客户端篡改公共数据 |
| **销毁管理** | 创建者下线后主权转移，需其他玩家在 Update 兜底销毁残留 | 由 DS 服务端统一管理生命周期与销毁 |

**DS 模式主权守门 (致命坑点)**：
DS 模式下房间公共对象的主权默认归服务端，但**如果未显式拒绝主权请求，任何客户端都可以抢走主权并篡改同步变量**。
- **Lua 拦截写法**：在对象脚本中实现 `function OnOwnershipRequest(senderID) return false end`。
- **C# 拦截写法**：在 `OnNetworkSpawn` 中订阅 `NetworkObject.OnOwnershipRequested += _ => false;`。

### 4. DouyinObjectService.ServerSpawn (DS内部专属)
- `NetSpawn` 创建的是**客户端可见**对象。
- `ServerSpawn` 创建的是**仅服务端可见**对象（客户端不生成），用于服务器内部逻辑。销毁时必须对应调用 `ServerDestroy`。

### 5. 销毁方式与父子关系陷阱
- 必须通过 `DouyinObjectService.NetDestroy` 销毁。
- **C# NetDestroy 参数差异**：`NetDestroy(go, autoRequest)` 中，`autoRequest=true` 表示“非主权方发起销毁时，自动请求主权后再销毁”，而不是销毁子节点。
- **父子关系陷阱**：如果将网络对象 A 设为 Actor 或其他网络对象的子节点（`SetParent`），在销毁父节点前，**必须先解除父子关系 (`transform.SetParent(null)`)**，否则父节点销毁会触发原生的 `GameObject.Destroy` 销毁子节点，导致子节点的网络状态残留，新进房的玩家依然会看到幽灵对象。

## 三、 玩家绑定对象的动态创建 (DouyinActor.NetSpawn)

使用 `DouyinActor.NetSpawn` 创建的是**与玩家关联的动态网络对象**（如血条、头顶称号）。

### 1. 核心机制
- 在 `OnActorSpawned` 事件中调用。
- **必须判断本地权限**：`if not actor.isLocal then return end` (Lua) 或 `if (!actor.isLocal) return;` (C#)，确保每位玩家只为自己发起创建请求，其他玩家的对应对象会自动同步生成。
- **断线重连防重**：玩家断线重连时 `OnActorSpawned` 会再次触发，必须使用本地表（如 `bloodTable[actor.actorID]`）记录是否已创建，避免重复生成。

### 2. 销毁方式
- 当创建该对象的 Actor 被销毁时，系统会**自动销毁**该网络对象，无需开发者手动干预清理（不会残留），极大降低了维护成本。
- 若需手动销毁，可调用 `actor:NetDestroy(go)`。

## 四、 动态网络对象管理器模式

在动态创建与管理网络对象时，根据网络同步模式的不同，通常会采用不同的管理器架构。

### 1. 网络同步模式与管理器选型
- **Shared Mode（分布式同步）**：多端协同，无中心节点。每个客户端独立处理自身权限内的网络对象逻辑更新。由于无中心节点，各客户端需独立管理数据，**分布式管理器**更适配。在分布式管理中，所有节点地位平等，通过对等通信协商决策。
- **传统 Client-Server（中心化同步）**：客户端发起请求，服务器作为中心节点集中处理关键数据与计算。由主节点/中心服务器统一接收请求、调度资源、下发指令。此模式下适用**中心化管理器**。

**注意**：在 Shared Mode 模式中若强行使用中心化管理器，需主权方作为中心节点统一处理消息，但这会面临主权转移（如切后台/断线）、弱网导致的数据异常等高危风险，故不推荐。

### 2. 分布式与中心化管理器横向对比

| **维度** | **分布式管理器** | **中心化管理器** |
| --- | --- | --- |
| **数据存储** | 各客户端本地维护 `networkObjects` 表 | `networkObjects` 作为同步变量字典，由主权方/服务端统一管理 |
| **决策机制** | 节点平等协商，无中心依赖 | 主节点统一调度，其他节点仅执行 |
| **容错性** | 无单点故障风险（主权转移不影响整体） | 依赖主节点稳定性（主权转移/弱网易引发异常） |
| **适用场景** | Shared Mode 模式（多端协同） | Dedicated Server (DS) 或传统 Client-Server 模式 |

> **提示**：关于分布式管理器的具体代码实现框架（如血条绑定、生命周期管理等），请参考最佳实践文档《分布式与中心化管理器》。

## 五、 黄金法则与避坑指南 (FAQ)

1. **选型法则：什么时候用哪个 API？**
   - **对象归属某个玩家**（血条、名牌、专属挂件）：优先使用 `DouyinActor.NetSpawn`，自动跟随销毁。
   - **对象归属整个房间**（门、机关、掉落物）：优先使用 `DouyinObjectService.NetSpawn`，自行管理生命周期。

2. **坑 1：断线重连后出现多个相同的绑定对象**
   - **原因**：重连会重新触发 `OnActorSpawned`。
   - **修复**：在创建前检查是否已为该 `actorID` 创建过对象。

3. **坑 2：C# 侧 NetSpawn 同步返回值获取同步变量报错或拿不到值**
   - **原因**：同步返回的是本地立即实例化的 GameObject，但网络数据还未同步。
   - **修复**：仅在回调中注入初始参数，真实初始化逻辑放在对象的 `OnNetworkSpawn` 中。

4. **坑 3：玩家退房后，SharedMode 房间内残留玩家召唤物**
   - **原因**：玩家下线无法自己调用 `NetDestroy`，且对象未与 Actor 绑定。
   - **修复**：利用主权转移机制，其他获得主权的在线玩家在 `Update` 里检测召唤物的 `targetActorId` 是否已离线，若离线则代为调用 `NetDestroy` 兜底销毁。

5. **坑 4：DS 独占节点组件规范（C# 特有高危坑点）**
   - **现象**：服务端报错 `LocalSpawnByObjectInfo GameObjectInfo miss` 或客户端丢失对象。
   - **原因**：在 `DouyinServerRoot` 子树下挂载了带 `NetworkObject` 的组件，导致 SDK 错误地将其广播给客户端。
   - **修复**：`DouyinServerRoot` 及其子节点上的脚本**严禁**继承 `DouyinMonoBehaviour`，必须改为 `MonoBehaviour` 并移除 `NetworkObject`。如需 GUID，请挂载 `DouyinNetworkGuid`。

6. **坑 5：C# 侧引用 ServerScripts 导致编译报错**
   - **原因**：C# 采用双程序集隔离，客户端脚本（`GameScripts/`）**严禁**引用 `ServerScripts/` 中的类型。
   - **修复**：所有跨端通信一律走 `DouyinRemoteEvent` 字符串通道解耦。确保 `simulator.json` 中已开启 `enableCSharp = true`。
