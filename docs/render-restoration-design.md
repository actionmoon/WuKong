# 悟空 · 渲染还原方案

日期：2026-11-23。状态：用户已确认按此方案实施。

依据：[任务计划](plan.md)、[交付报告](step8-delivery.md)、原站 `docs/reference/wukong/src/render.js` 与原始 GLB。目标是在现有 Unity 2021.3 / URP 12 / Hamlet 工程中尽可能接近原站的光照、表面细节、角色轮廓和整体色调。

## 1. 已确认的差距

| 项目 | 本地证据 | 处理方向 |
| --- | --- | --- |
| 色调映射 | `Materials/ArenaPost.asset` 的 `components` 仅有空引用；场景相机开启后处理 | 修复 Profile 子资源持久化，核验实际运行 ACES；不靠增加橙色滤镜接近原站 |
| 阴影 | 桌面 High Fidelity 与移动 Balanced 的 URP 资源均为 8 米、1024、单级联 | 桌面从 2048、约 50 米、两级联起调；移动从 1024、约 35 米起调；以画面和耗时确定最终值 |
| 环境照明 | Builder 混用天空线性色与雾色转换，生成 32 像素无 mip 的天空 Cubemap | 按源文件明确线性 / sRGB 语义，分别核验背景、漫反射环境光和预滤波反射 |
| 天命人 | SampleBuilder 使用中性法线和固定 0.35 光滑度，金属度为 0 | 从原始模型恢复法线、粗糙度、遮蔽、金属度和透明轮廓 |
| 场景 PBR | SDK `World_Lit` 从基础图 Alpha 读取金属度；打包器只写入法线、光滑度与 AO，材质仅设置金属度因子 | 核对源 MR 的 B 通道、因子和各贴图 UV，避免把不透明 Alpha 当作金属度图 |
| 透明、双面表面 | 保留 glTF ShaderGraph；交付仍有 BuiltIn Deferred / Metal 编译问题 | 使用兼容当前 URP 的材质路径，保留 Alpha、裁切阈值、双面、法线及阴影语义 |
| 视觉 | 原站 / Unity 出生与血池截图可见整体偏暖、角色受光和阴影差异 | 统一机位、分辨率、姿态和状态后复核，现有截图仅作定性依据 |

以上为静态配置与既有截图观察。实际运行中的 SDK 管线覆盖、后处理和反射是否生效，需要在 Editor 与调试器分别核验。

## 2. 方案选择

- **推荐：修复渲染链路，再校准源材质。** 先恢复色彩空间、ACES、环境反射和阴影，再补齐 PBR、毛发裁切及血池表面。收益覆盖全场景，便于保留现有资源和性能基线。
- **只调灯光与后处理。** 工作量较小，但无法补回角色法线、金属度、透明轮廓，作为完整还原方案不足。
- **整体重写渲染与特效。** 可扩展毛发、折射及复杂屏幕效果，但平台适配和性能成本较大，本轮优先采用现有 URP 能力。

## 3. 实施顺序

1. **建立当前基线。** 经 unity-mcp 核验活动场景、相机、运行管线、材质依赖和 Console；重新构建并记录当前出生点、血池、天命人和虎先锋近景。沿用现有诊断入口取得固定机位。
2. **修复整体渲染。** 正确保存 ACES 子资源；依据源 `arena.json` / `render.js` 校准太阳方向、强度、天空背景、雾及环境反射。保留原站曝光 1 的参考语义；Unity 与 Three.js 的曝光参数不直接按数值等同。调整阴影距离、分辨率、偏移与级联，补足角色和台阶接触阴影；核验抗锯齿。
3. **恢复材质数据。** 使用原始 GLB 建立按资源和材质标识映射的转换，恢复角色与场景的法线、MR、AO、发光和 UV 变换。SDK 打包材质只有在通道与 UV 可以正确表达时使用；其他表面使用经平台构建验证的 URP 材质。只转换模型表面，不覆盖 UI、粒子和运行时技能专用材质。
4. **校准特殊表面。** 毛发和植被按原 Alpha 模式恢复裁切 / 混合及双面表现；血池保留源表面层次、颜色、粗糙度和透明关系；检查石化、隐身、淡出和重试恢复与新材质的兼容性。优先还原原站已有表现，复杂动态毛发和额外折射按实际差距决定是否必要。
5. **实际回归与交付。** 用相同机位记录前后截图，执行移动、战斗、技能材质切换、死亡和重试；构建并启动 DS 两端验证。采样 FPS、帧时间和内存，对照相同窗口、路线、时长的本轮基线。更新计划与独立实施报告。

## 4. 实现约束

- 通过现有 Editor Builder 或独立渲染装配入口更新场景与资源，操作使用 unity-mcp；避免重跑整场景装配导致已完成的移动端 HUD 被重建。
- 原始资源契约继续保留。材质转换应可重复执行，映射包含来源资源标识，避免同名材质混淆。
- 配置与资产变更先明确 SDK 调试器实际使用的管线；场景外的全局设置只在确认必要时修改。
- 桌面与移动分别保留合适的渲染预算。所有性能结论基于实测；没有真机数据时不声明手机性能已通过。
- 项目通用开发、构建和回归规则继续引用 `plan.md` 中的技能与偏好单一来源。本文件仅记录本轮设计。

## 5. 验收与产物

- 保存后重新加载 Profile，ACES 组件引用有效；实际调试器可观察后处理、阴影和材质效果。
- 目标材质保留源纹理语义；毛发 / 植被无明显实心卡片，角色、石阶、金属和血池分别核对。
- 出生点与血池统一机位截图用于核对色调、明暗关系、阴影覆盖和表面细节；角色近景核对法线及轮廓。截图保留平台水印，不做后期美化。
- 新材质相关 Shader 编译结果、场景加载结果及技能状态恢复分别记录；剩余问题保留原始证据。
- 输出更新后的场景、渲染资源、可重复转换 / 装配入口，以及含对照图和性能数据的 `docs/render-restoration-implementation.md`。
- 本轮目标是有证据的视觉接近，不预设还原百分比或逐像素一致结论。
