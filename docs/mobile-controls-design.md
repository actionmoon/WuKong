# 右下角操作按钮与移动端技能交互方案

日期：2026-11-23。状态：已确认并实现；代码、场景装配和桌面回归见[实施记录](mobile-controls-implementation.md)。

依据：[任务计划](plan.md)、[步骤 8 交付](step8-delivery.md)、现有 `PresentationHUD.lua`、`CombatInput.lua` 和 `WuKongPresentationBuilder.cs`。

## 目标与现状

使用自定义右下角操作按钮，让玩家在移动中直接攻击、闪避和施法。保留官方左侧摇杆、键鼠兼容输入及 DS 战斗判定。

目前右侧有 12 个战斗按钮，另有独立挑战按钮。战斗按钮均为 84×56 的矩形，排成三列四行；轻棍、闪避与法术缺少操作层级。HUD 已显示冷却并禁用部分资源不足的按钮，但没有就近解释原因，也没有蓄力状态反馈。

输入同时接收按钮点击、平台触摸通知和矩形轮询。轮询依据手指当前位置判断按钮，滑入另一个按钮可能产生新的动作；去重依赖 0.12 秒间隔，不能保证同一次触摸只发一次命令。

## 方案选择

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| **主动作大按钮＋四技能常驻（推荐）** | 闪避容易触达；四技能一键直达；无需学习菜单手势 | 占据较多右下区域，需按动作频率分组 |
| 主动作＋点击展开技能面板 | 常态画面更简洁 | 施法多一次点击，移动战斗中切换更慢 |
| 主动作＋长按滑选技能 | 入口最紧凑 | 手指遮挡选项，需学习滑选，误选处理更复杂 |

采用第一种，并按用户最新要求调整为右下角四层同心扇形：第一层仅闪避，第二层轻棍与重棍，第三层四技能，第四层辅助操作。每层按钮大小一致，由内到外逐级缩小；所有操作保持直接点击。整个右下操作区不超过屏幕宽度的 40%、高度的 60%。

## 布局

[查看横屏布局示意](mobile-controls-layout.svg)。此图为设计示意，不是 Unity 截图。

参考尺寸为 1280×720。操作容器为 **408×408**，锚定安全区右下角；按钮、冷却遮罩、蓄力反馈、状态提示与触摸区域全部包含在容器内。示例安全区右侧、底部各留白 24 像素，连同留白计算的右下区域为 **432×432**，占全屏宽度 **33.75%**、高度 **60%**，满足宽度 40% 上限。

扇形圆心相对容器右下角向左、向上各内缩 20；从向左的水平线向上计角。四层半径依次为 **44、156、260、356**，按钮直径依次为 **92、84、76、68**，每向外一层直径减少 8。所有层以 **45° 为对称轴**，同层多按钮沿圆弧等角度分布，闪避位于最内层 45° 方向。

相邻层的径向净间隙统一为 **24**，按 `外层半径−内层半径−两层按钮半径之和` 计算。层间保留一致的空白带；同层按按钮数量等分角度，圆形按钮边缘留有空隙，外接交互矩形也不重叠。冷却描边向按钮内部绘制，状态变化不改变尺寸或间距。

运行时以真实屏幕尺寸 W、H 计算区域上限，而不是以参考画布比例替代：区域位于屏幕最右侧 40%、最下侧 60%，再与安全区相交。设安全区右侧留白为 R、底部留白为 B、安全区宽高为 Sw、Sh，统一缩放系数为 `min(H/720, min(0.40W−R,Sw)/408, min(0.60H−B,Sh)/408)`。容器、按钮、间距、文字和提示一起缩放，保证四层形状与同层大小一致；该容器在原 HUD 缩放基础上做对应的局部缩放。独立中央挑战按钮及左上帮助／声音入口不归入右下操作区。

帮助、声音保留独立入口。开始／重新挑战保留中央按钮，仅在对应状态显示。布局适配安全区；竖屏显示横屏提示并停止战斗输入。右下控件触摸不参与转动镜头，空白区域仍可拖动视角。

## 技能反馈与流程

1. 玩家按下可用按钮，按钮立即显示按下反馈，向现有输入队列提交一次请求。实际施法、消耗、冷却和命中以 DS 快照为准。
2. 冷却显示剩余秒数与遮罩；资源不足显示“法力不足”或能量百分比。弱化按钮仍接受提示点击，但不提交战斗请求；提示在操作容器内部顶部显示 1.5 秒，不扩大右下区域。
3. 赤潮形态下更新轻重攻击名称、返回入口及其他技能可用状态。变身或精魄过渡期间依据已有快照字段提示状态，避免承诺当前不能执行的技能。
4. 帮助面板优先展示触屏操作；键鼠作为兼容操作说明。常态提示使用“按住重棍蓄力”等触屏文案。

资源阈值读取现有配置，HUD 不另建一份数值规则。动作取消窗与排队规则仍由 DS 执行；不能因客户端暂时处于攻击动作就一律禁用技能。

## 触摸输入

- 每个手指在按下时确定所属按钮；移动后不转交给相邻按钮。从空白区域滑入按钮不触发操作。
- 轻棍、闪避、法术、葫芦与切换类操作每次按下只提交一次。平台通知、UGUI 点击和屏幕轮询统一进入输入处理，采用手指及触摸生命周期去重，鼠标兼容点击也走同一入口。
- 重棍与棍花采用按住状态。手指松开、触摸取消或滑出原按钮时结束按住；重棍按现有规则释放，棍花停止。这里的“滑出”结束的是输入，不增加取消重棍攻击的玩法。
- 多指独立持有按钮；释放一个手指不清除其他仍有效的按住状态。支持左摇杆移动同时右手蓄力，以及独立手指触发闪避，动作结果遵循现有取消窗。
- 帮助打开、切为竖屏、失焦、角色销毁、挑战 epoch 变化及世界退出时清空触摸归属、待提交点击与按住状态。打开面板的同一触摸不穿透到战斗。

## 实施范围

1. `WuKongPresentationBuilder.cs`：按四层半径与角度生成扇形按钮，同层直径一致；生成圆形视觉、状态遮罩、进度与容器内提示区域，通过 Unity MCP 装配并保存场景。
2. `PresentationHUD.lua`：缓存新增引用，管理可用状态、冷却、能量、蓄力及触屏帮助，提供按钮命中与状态查询。
3. `CombatInput.lua`：统一触摸归属、按下去重和多指按住；保留现有命令名称、摇杆、键鼠与诊断入口。必要时拆出独立输入状态模块，保持职责清晰。
4. `docs/run-and-controls.md` 与 `docs/plan.md`：实现、回归后更新实际操作和证据；新增独立移动端优化验收记录。步骤 8 的历史交付结果不改写为本次已验结果。

通用开发和调试规则继续引用任务计划第 1 节的单一来源；本文件仅描述本次功能选择与验收。
