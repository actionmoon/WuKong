# 棍势、法术、变身与精魄

步骤 6 按 [任务计划](plan.md) 已批准范围执行，配置与开发规则沿用计划第 1 节引用的单一事实来源。参考行为来自 `docs/reference/wukong/src/stances.js / spells.js / transform.js / spirit.js`；数值与事件来自 `assets/data/stances.json / spells.json / bianhua.json` 及相应动画合同。

1. 生成共用技能配置，合并天命人的棍势、法术和变身过渡动画；装配广智、广谋与毒蛇真实模型、动作及武器挂点。
2. 将扩展技能接入现有战斗动作、输入缓存、伤害和挑战循环，DS 维护技能合法性、资源、冷却、形态及召唤物。客户端提交统一输入，读取快照驱动模型、动画、按钮和资源显示。
3. 验证固定输入用例，再打包场景并使用一个 DS、两个实际客户端关联输入、结算与同步证据。重跑受影响的基础战斗与 Boss 用例。
4. 更新实际结果、构建时间和证据链接，移除临时自动回放标记并保存最终场景，然后按计划等待用户确认步骤 7。

棍势沿用 Z / X / C 切换劈棍、立棍、戳棍，V 长按棍花；移动端提供切换与长按入口。覆盖立棍 / 戳棍蓄力、等级增长、释放、体力耗尽，劈棍识破 / 贯索 / 斩棍式、立棍风云转、戳棍退寸进尺。立棍使用真实骨骼区分棍身与抬高的身体，棍身受击扣体力；棍花抵消源配置范围内的投射物。

定身法用 1 或按钮施放，按施法事件扣 50 MP，普通冷却 50 秒，攻击预警内使用精准版本并按源事件缩短冷却。根据虎先锋状态与防御计算持续时间，累计命中耗尽定身耐久时破除；定身免疫状态仍按源 Buff 判断。聚形散气用 2 或按钮施放，扣 30 MP、冷却 35 秒，化气持续 10 秒并每秒扣 3 MP；分身承接虎先锋目标，轻棍触发破隐一击，攻击、缺蓝、超时、死亡和形态变化按源规则退出。

赤潮用 4 或按钮施放及主动退出，需满变身能量；广智拥有独立血量、体力和气势，保存天命人的原资源，退出后恢复。技能包含出生攻击、轻击链、气势满后的火焰变招、重击命中派生及闪避后的方向重击。能量耗尽或广智血量归零会退回天命人，技能施放与精魄之间保持源互斥。

广谋精魄用 F 或按钮施放，需满精魄能量，成功施放耗尽能量；命中按原效果表回复能量。广谋只切换模型与受击胶囊，保持天命人的属性；技能召唤两条毒蛇，存在 10 秒，按出生、攻击、消失时间轴执行，发射加速毒弹并使用召唤者攻击比例结算。受击打破霸体或死亡时恢复天命人，挑战重试清理形态、分身、定身、毒蛇、毒弹与技能状态。

模块划分：共用配置提供动画与动作数据；服务端棍势、法术和形态模块通过现有战斗状态机的扩展接口工作；客户端角色代理按形态选择对应模型，技能表现脚本维护分身、毒蛇与毒弹。沿用现有 20 Hz 共享快照，每位玩家仍拥有独立挑战。

验收覆盖资源不足、连续施放、输入窗口、施法中受击、定身破除、分身目标恢复、变身手动 / 能量 / 血量退出、精魄中断、毒弹命中、技能中死亡与重试清理。粒子、材质曲线、溶解、声音和完整界面美化属于步骤 7；本步交付可操作的真实模型、动画与战斗结算。

实际实现与操作：

- `Shared/Modules/SkillsConfig.lua` 由 [配置生成器](../tools/prepare_skills.py) 生成，保留 116 个剪辑合同及全部事件类型；棍势消耗按 20 个效果 ID 映射，动画循环重新开放命中与消耗窗口。
- `Server/Modules/StanceSession.lua / SpellSession.lua / FormSession.lua` 分别维护棍势、法术与形态；`SkillsSession.lua` 接入战斗状态机。Boss 与挑战模块使用当前形态属性、受击胶囊和分身目标。共享脚本通过 `ServerBoot.lua` 取得服务端模块及测试入口。
- 天命人模板共有 163 个剪辑，其中本步新增 56 个；广智 55 个、广谋 1 个、毒蛇 4 个。服务端使用隐藏的真实模型采样骨骼与挂点；客户端代理选择当前形态模型，按快照采样动画。广智的 8 个武器挂点已装配。
- Z / X / C 切换棍势，V 长按棍花，1 定身、2 散气、4 赤潮及主动退出、F 广谋。新增 6 个触摸按钮，并接入长按输入。HUD 显示当前形态、血量上限、棍势、法术冷却和两种能量。
- F5 在调试器中启动约 77 秒技能回放；F6 / F7 / F8 / F9 / F10 沿用先前 Boss、基础战斗及诊断入口。模拟器测试命令经服务端校验，正式运行不接受这些命令。

回归与证据：

1. `python3 -B tools/verify_skills.py` 使用 Lua 5.3 执行生产模块，共 59 项：技能 31 项、原有玩家战斗 10 项、Boss 与挑战 18 项，全部通过。覆盖实际命中回复精魄、变身中胜利、变身血量归零自动退出、冷却和资源、法术打断、棍身受击、棍花拦截、毒弹及死亡重试。见 [固定用例证据](reference/step6-fixed-evidence.json)。
2. 模型 / 动画数量通过 Unity Editor 实际对象核对；场景使用 `SkillsTemplates` 活动父对象取得非活动模板，避免运行时查找遗漏。资源映射及源导出推断见 [映射记录](reference/step6-skill-mapping.json)。
3. 三端回归使用一个 DS、两个实际 Avatar 客户端；按统一输入进入技能，核对服务端结算与两端快照。完整结果由 [取证脚本](../tools/record_skills_evidence.py) 写入 [运行证据](reference/step6-runtime-evidence.json)。该文件的 `pass`、进程异常计数、各技能里程碑及构建时间为实际验收结果。
4. 会话 `hamlet-simulator-pulonqfs` 实际通过：服务端 59/59，三端 Lua 异常 0；两端技能里程碑全部通过，6 次毒弹真实命中，普通轻棍命中回复精魄 1.5，死亡重试后恢复初始资源。最终移除自动回放标记，三个进程均退出，场景保存且无脏标记；交付缓存时间为 `2026-11-22T13:36:48.638484+08:00`，启动 dry-run 通过。
5. 四段棍势保留和识破奖励去重的最后修正经过固定用例验证，未另外重跑完整三端回放；真实回放的棍势释放覆盖立棍三段和戳棍一段。
