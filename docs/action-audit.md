## 原地打转：已复现的原因

触发条件是玩家锁定虎先锋后持续向前，接近并穿过虎先锋的中心。

1. `CombatInput.lua:172–183` 每帧以镜头 yaw 将前推输入转成世界方向。
2. `CombatInput.lua:471–480` 将角色朝向不断转向 Boss 中心。
3. `ArenaPresentation.lua:171–185` 又将镜头转向同一个中心；下一帧输入方向随镜头改变。
4. 客户端位移路径 `CombatInput.lua:438–484` 缺少原站 `combat.js:41–65` 的玩家防穿透处理。Unity 场景中 `TigerBaseline` 的 Collider 数量为 **0**。服务端虽然限制 Boss 向玩家移动，但没有对称限制客户端玩家向 Boss 移动。
5. 玩家跨过中心后，目标方向翻转约 180°，角色、镜头和前推方向继续互相影响，形成反复转向、绕圈。

使用**生产 `CombatInput.Update` 与 `ArenaPresentation.alignCamera`** 做 Lua 5.3 固定轨迹测试，60 Hz、Boss 静止、世界 X/Z 移动；Boss 中心设为原点：

| 6 秒输入 | 累计转向 | 结果 |
| --- | ---: | --- |
| 不锁定，持续前推 | 0° | 直线前进 |
| 锁定，从 Boss 前方 3 米持续前推 | 582.81° | 穿过中心后反复绕转 |
| 锁定，从 10 米持续前推 | 491.30° | 接近后出现同类绕转 |
| 锁定，静止不输入 | 0° | 保持静止 |
| 同样近身前推，加入原站防穿透算法作为对照 | 0° | 停在 1.36 米接触边界 |

对照算法仅加入临时测试环境，没有写入项目玩法。测试未模拟 SDK 自动转向、网络延迟和真实触摸；因此这里确认的是**足以独立造成绕转的代码机制**，不是把用户遇到的全部打转情形都归为同一原因。手机按钮误带镜头、SDK 原生控制与自定义控制冲突仍未得到本轮运行证据支持。

## 同时发现的动作问题

| 问题 | 证据与影响 | 代码位置 |
| --- | --- | --- |
| 锁定左右闪避反向 | 角色朝 +Z 时，右输入选 `Dodge_L`，其横向根位移为 **−3.6388 米**；左输入选 `Dodge_R`，横向为 **+4.4174 米**。前后方向对照通过 | `CombatInput.lua:399–405`；原站为右手坐标，方向标签不能直接照搬到 Unity |
| 锁定横移动画左右映射反向 | Unity 世界中正右分量选 `LF/LB`，负右分量选 `RF/RB`；与闪避使用同类符号规则 | `CombatSession.lua:191–198`，静态确认；尚未做逐帧视觉对照 |
| 自由状态闪避不先朝输入方向转身 | 角色朝 +Z、输入向右时，生产逻辑仍沿原朝向使用前闪避；测试结果主要向 +Z 位移，而不是向右 | `CombatInput.lua:399–405、465–480`；原站 `player.js:391` 在此处先设置 yaw |
| 玩家动作根旋转被丢弃 | `rootDelta` 返回第三项 yaw 增量，客户端仅接收 forward、side，无法完整应用带旋转的动作曲线 | `CombatClock.lua:78–96`、`CombatInput.lua:465`；未把它单独认定为本次绕转主因 |
| F7 回放未开始挑战 | `reset()` 仅发送 `test-reset`。当前 DS 将挑战置为 `ready`，后续攻击命令被拒绝；本轮没有产生该段预定的连招、蓄力、葫芦和完美闪避动作 | `CombatInput.lua:246–250`、`CombatState.lua:198–199`、`CombatSession.lua:92–94` |

F5/F6 的重置后另有 `boss-idle` 或 `boss-ai`，会开始挑战，所以它们的实际动作证据仍有效。F7 的历史基础战斗数据发生在先前实现阶段，不能直接作为当前版本回放通过的证明。

## 建议修复顺序

1. 在玩家移动路径补齐原站防穿透与贴边滑动规则，覆盖自由移动、锁定移动和动作根位移，并遵循技能的穿透例外。优先回归近身前推、Boss 移动、侧移、疾跑和聚形散气。
2. 统一 Unity 世界方向、角色局部左右与动画方向映射，修正左右闪避和横移动画；自由闪避在动作开始时确定输入朝向。
3. 补齐玩家根旋转、移动起停/转身和动画融合，再进行全部动作的逐项视觉检查。
4. 修复 F7 的挑战初始化，补录五段连招、疾跑轻棍、葫芦、方向闪避与完美闪避的当前实际证据。
5. 在真实键鼠和目标手机重现同样条件，核验是否仍有 SDK 转向或触摸镜头影响。
